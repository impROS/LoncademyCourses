## Neden bu konu

Hazır connector'lar işlerin %90'ını görür. Kalan %10 için iki yol vardır: **kendi SMT ([Single Message Transform — kayıt başına dönüşüm ↗](../00-baslangic/02-kavram-sozlugu.md#smt))'ni yazmak**
(kolay, çoğu zaman yeterli) ya da **kendi connector'ını yazmak** (zor, nadiren gerekli).
Bu konuda ilkini gerçekten yazıp çalıştıracağız.

İkinci yarıda **MirrorMaker 2**: cluster'lar arası replikasyon. Felaket kurtarma, veri merkezi
göçü ve bulut geçişlerinin standart aracı — ve yanlış anlaşıldığında en pahalı olanı.

> **Büyük fikir:** SMT **kayıt başına, durumsuz, hafif** bir dönüşümdür. İş mantığı, join,
> agregasyon gerekiyorsa yanlış araçtasın — orası **Kafka Streams**'in işidir (06).

## 1. ⭐ SMT ne zaman doğru araç

| İşlem | SMT uygun mu |
|---|---|
| Alan maskeleme / silme / yeniden adlandırma | ✅ |
| Header ekleme, topic yönlendirme (`RegexRouter`) | ✅ |
| Tip dönüşümü (`Cast`), zaman formatı (`TimestampConverter`) | ✅ |
| Key çıkarma (`ExtractField`), flatten | ✅ |
| Filtreleme (`Filter` + predicate) | ✅ |
| **Başka bir kayıtla birleştirme (join)** | ❌ Streams |
| **Toplama / sayma / pencereleme** | ❌ Streams |
| **Dış servis çağrısı** | ❌ (her kayıtta senkron çağrı hattı öldürür) |

**Yerleşik SMT'lerden sık kullanılanlar:** `InsertHeader` · `RegexRouter` · `ExtractField` ·
`MaskField` · `ReplaceField` · `Cast` · `TimestampConverter` · `Flatten` · `Filter` ·
`ValueToKey` · `SetSchemaMetadata`.

> ⭐ **Predicate'ler:** SMT'ler `predicates` ile koşullu çalıştırılabilir
> (`TopicNameMatches`, `HasHeaderKey`, `RecordIsTombstone`) — `negate` ile tersi alınır.
> "Sadece şu topic'te maskele" gibi kurallar böyle yazılır.

## 2. ⭐ Kendi SMT'ni yazmak — çalışan örnek

`Transformation<R extends ConnectRecord<R>>` arayüzü dört metot ister:
`configure` · `apply` · `config` · `close`.

Konvansiyon: soyut bir taban sınıf + `Key` ve `Value` iç sınıfları (yerleşik SMT'lerin hepsi böyle).

```java
public abstract class MaskeleSmt<R extends ConnectRecord<R>> implements Transformation<R> {

    private static final ConfigDef CONFIG_DEF = new ConfigDef()
            .define("min.digits", ConfigDef.Type.INT, 10, ConfigDef.Importance.MEDIUM, "...")
            .define("mask.char", ConfigDef.Type.STRING, "*", ConfigDef.Importance.LOW, "...");

    private Pattern pattern; private String maskChar;

    @Override public void configure(Map<String, ?> configs) {
        Object raw = configs.get("min.digits");
        int minDigits = raw == null ? 10 : Integer.parseInt(String.valueOf(raw));
        maskChar = configs.get("mask.char") == null ? "*" : String.valueOf(configs.get("mask.char"));
        pattern = Pattern.compile("\\d{" + minDigits + ",}");
    }

    @Override public R apply(R record) {
        Object value = operatingValue(record);
        if (!(value instanceof String s)) return record;      // dokunamıyorsan DOKUNMA
        String masked = maskDigits(s);
        return masked.equals(s) ? record : newRecord(record, masked);
    }

    public static class Value<R extends ConnectRecord<R>> extends MaskeleSmt<R> { ... }
    public static class Key<R extends ConnectRecord<R>>   extends MaskeleSmt<R> { ... }
}
```

Tam kod: [`lab/src/main/java/tr/improsy/kafkalab/k72/MaskeleSmt.java`](../lab/src/main/java/tr/improsy/kafkalab/k72/MaskeleSmt.java)

**Kullanımı:**

```properties
transforms=maskele
transforms.maskele.type=tr.improsy.kafkalab.k72.MaskeleSmt$Value
transforms.maskele.min.digits=10
transforms.maskele.mask.char=#
```

**Gerçek lab çıktısı** — girdi dosyası ve topic'e düşen hâli:

```
girdi:  musteri Ahmet tc 12345678901 tutar 250
        musteri Ayse kart 4111111111111111 tutar 90
        kisa sayi 12345 kalsin

çıktı:  musteri Ahmet tc ########### tutar 250
        musteri Ayse kart ################ tutar 90
        kisa sayi 12345 kalsin          ⬅ 5 haneli sayıya DOKUNULMADI
```

> ⚠️ **SMT yazarken üç kural:**
> 1. **Durumsuz ol.** SMT örnekleri task başına oluşturulur; kayıtlar arası durum tutma.
> 2. **Hızlı ol.** Her kayıt için çalışır; ağ/disk çağrısı yapma.
> 3. **Dokunamıyorsan kaydı olduğu gibi döndür.** Beklenmedik tipte istisna fırlatmak
>    tüm hattı durdurur (`errors.tolerance` — [hatalı kayıt atlansın mı ↗](../00-baslangic/02-kavram-sozlugu.md#errorstolerance) devrede değilse).

**Paketleme ve dağıtım:**

```

├── benim-smt/
│   └── kafka-lab-1.0.0.jar        ← plugin.path bu ÜST dizini gösterir
└── file/
    └── connect-file-4.3.1.jar
```

```properties

```

## 3. ⭐ Kendi connector'ını yazmak — gerekli mi?

| Önce şunu dene | Ancak sonra |
|---|---|
| Hazır connector + SMT | — |
| Hazır connector + predicate'li SMT zinciri | — |
| Kafka Streams ile dönüştürüp yeni topic'e yaz | — |
| **Kendi connector'ın** | Gerçekten desteklenmeyen bir sistem varsa |

Yazacaksan iskelet: `SourceConnector`/`SinkConnector` (yapılandırma, `taskConfigs(int)`) +
`SourceTask`/`SinkTask` (`poll()` / `put(Collection<SinkRecord>)`).

**Source connector'da kritik nokta:** `poll()` içinde `SourceRecord` üretirken
**sourcePartition** ve **sourceOffset** vermelisin — Connect'in yeniden başlatmada nereden
devam edeceğini bilmesi bu ikiliye bağlıdır (7.1).

```java
new SourceRecord(
    Map.of("dosya", filename),        // sourcePartition: "iş biriminin kimliği"
    Map.of("konum", byteOffset),      // sourceOffset: "nerede kaldım"
    topic, null, Schema.STRING_SCHEMA, line);
```

## 4. ⭐ MirrorMaker 2: cluster'lar arası replikasyon

MM2 ayrı bir uygulama değil, **Connect üzerine kurulmuş üç connector'dır**:

| Connector | Görevi |
|---|---|
| `MirrorSourceConnector` | Topic verisini ve yapılandırmasını kopyalar |
| `MirrorCheckpointConnector` | **Consumer group offsetlerini** çevirip kopyalar |
| `MirrorHeartbeatConnector` | Bağlantı canlılığını ölçen heartbeat topic'i |

**Topic adlandırma:** Varsayılan `DefaultReplicationPolicy` hedefte **kaynak takma adıyla ön ek**
kullanır: `kaynak.siparisler`. Bu, döngüsel replikasyonu (A→B→A) engeller.

> ⚠️ **`IdentityReplicationPolicy`** (ön ek yok) kolaycı görünür ama **döngü koruması kaybolur**;
> yalnızca tek yönlü, tek atlamalı senaryolarda ve bilinçli kullanılmalıdır.

**Örnek yapılandırma:**

```properties
clusters = kaynak, hedef
kaynak.bootstrap.servers = kaynak-b1:9092,kaynak-b2:9092
hedef.bootstrap.servers  = hedef-b1:9092,hedef-b2:9092

kaynak->hedef.enabled = true
kaynak->hedef.topics = siparisler|odemeler          # regex
kaynak->hedef.groups = .*                            # offset çevrimi yapılacak gruplar
kaynak->hedef.emit.checkpoints.enabled = true
kaynak->hedef.sync.group.offsets.enabled = true      # offsetleri hedefte YAZ

replication.factor = 3
checkpoints.topic.replication.factor = 3
heartbeats.topic.replication.factor = 3
offset-syncs.topic.replication.factor = 3

refresh.topics.interval.seconds = 60
sync.topic.configs.enabled = true
```

Çalıştırma: `connect-mirror-maker.sh mm2.properties` (kendi Connect worker'larını ayağa kaldırır)
ya da mevcut bir Connect cluster'ına üç connector olarak yüklenir.

**Offset çevrimi neden gerekir?** Aynı kaydın offset'i iki cluster'da **farklıdır** (7.1).
`MirrorCheckpointConnector`, `offset-syncs` topic'ini kullanarak kaynak offsetini hedef offsetine
çevirir ve `sync.group.offsets.enabled=true` ise hedefte grup offsetlerini yazar — böylece
felaket anında tüketiciler **yaklaşık doğru** noktadan devam eder.

> ⭐ **MM2 at-least-once'tır ve asenkrondur.** Failover sonrası **duplicate işleme normaldir**;
> tüketicilerin idempotent olması gerekir (4.2). MM2 "sıfır veri kaybı" **vaat etmez**.

| MM2 ne çözer | Ne çözmez |
|---|---|
| Felaket kurtarma (aktif-pasif) | Senkron replikasyon / sıfır RPO ([kabul edilen veri kaybı penceresi ↗](../00-baslangic/02-kavram-sozlugu.md#rpo-rto)) |
| Veri merkezi / bulut göçü | Exactly-once cross-cluster |
| Coğrafi yakınlık için veri kopyası | Otomatik failover kararı (onu sen verirsin) |
| Cluster birleştirme/ayırma | Aynı offsetleri korumak (offsetler **çevrilir**) |

## Sık karıştırılanlar — tek tabloda

| Karışan | Doğrusu | Neden diğeri değil |
|---|---|---|
| SMT ↔ Streams | SMT **kayıt başına, durumsuz**; Streams stateful | Join/agregasyon SMT ile yapılmaz |
| SMT'de dış çağrı ↔ uygun | **Uygun değil** — her kayıtta senkron çağrı hattı öldürür | Zenginleştirme için Streams + GlobalKTable |
| MM2 ayrı uygulama ↔ Connect connector'ları | **Üç connector**: source, checkpoint, heartbeat | Connect'in tüm işletim modeli geçerli |
| MM2 topic adları ↔ aynı kalır | Varsayılan **`kaynak.` ön eki** | Ön ek döngü korumasıdır |
| MM2 offsetleri ↔ aynı | Offsetler **çevrilir**, aynı değildir | Cluster'lar bağımsız log'lardır |
| MM2 ↔ sıfır veri kaybı | **At-least-once, asenkron** | Failover'da duplicate normaldir |
| `plugin.path` ([Connect eklenti dizini ↗](../00-baslangic/02-kavram-sozlugu.md#pluginpath)) jar ↔ dizin | **Üst dizini** göster; alt dizinlerde jar'lar dursun | Yanlış yol = sessiz yükleme hataları (7.1) |

## 🖥 Pratik — kendi SMT'ni yaz ve çalıştır

> **Amaç:** Gerçek bir SMT yazıp Connect'e yüklemek ve MM2 ile **gerçek bir replikasyon** kurmak
> · **Süre:** 25 dk (A) + 25 dk (B)
> **💸 Maliyet:** Yok — B bölümü ikinci bir tek node'lu cluster açar (~1 GB disk, ~1 GB RAM).
> **⚠️ MM2'yi broker'ın içinde çalıştırma:** kendi Connect worker'larını başlatır; broker'la aynı
> konteynerde çalıştırmak belleği ve diski tüketip broker'ı çökertebilir. Lab **ayrı bir konteyner** kullanır.

### Bölüm A — SMT'yi derle ve dağıt

1. Lab projesini paketle:
   ```bash
   cd lab && mvn -q package -DskipTests && ls -la target/kafka-lab-1.0.0.jar
   ```
2. Plugin dizinini kur ve jar'ları yerleştir:
   ```bash
   docker exec kafka-1 bash -c 'mkdir -p /tmp/plugins/lab /tmp/plugins/file && \
     cp /opt/kafka/libs/connect-file-4.3.1.jar /tmp/plugins/file/'
   docker cp lab/target/kafka-lab-1.0.0.jar kafka-1:/tmp/plugins/lab/
   ```
3. Worker ve connector yapılandırmasını yaz:
   ```bash
   docker exec kafka-1 bash -c 'cat > /tmp/worker2.properties <<EOF
   bootstrap.servers=kafka-1:19092
   key.converter=org.apache.kafka.connect.storage.StringConverter
   value.converter=org.apache.kafka.connect.storage.StringConverter
   offset.storage.file.filename=/tmp/connect2.offsets
   offset.flush.interval.ms=3000
   listeners=HTTP://:8085
   plugin.path=/tmp/plugins
   EOF
   cat > /tmp/source2.properties <<EOF
   name=maskeli-kaynak
   connector.class=org.apache.kafka.connect.file.FileStreamSourceConnector
   tasks.max=1
   file=/tmp/pii.txt
   topic=lab-smt-out
   transforms=maskele
   transforms.maskele.type=tr.improsy.kafkalab.k72.MaskeleSmt\$Value
   transforms.maskele.min.digits=10
   transforms.maskele.mask.char=#
   EOF
   printf "musteri Ahmet tc 12345678901 tutar 250\nmusteri Ayse kart 4111111111111111 tutar 90\nkisa sayi 12345 kalsin\n" > /tmp/pii.txt
   rm -f /tmp/connect2.offsets'
   ```
4. Topic'i oluştur ve çalıştır:
   ```bash
   docker exec kafka-1 /opt/kafka/bin/kafka-topics.sh --bootstrap-server kafka-1:19092 \
     --create --topic lab-smt-out --partitions 1 --replication-factor 3
   docker exec kafka-1 bash -c 'timeout 35 /opt/kafka/bin/connect-standalone.sh \
     /tmp/worker2.properties /tmp/source2.properties > /tmp/smt.log 2>&1; echo bitti'
   ```
5. Sonucu gör:
   ```bash
   docker exec kafka-1 /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server kafka-1:19092 \
     --topic lab-smt-out --from-beginning --max-messages 3
   ```
   Beklenen: 11 ve 16 haneli sayılar `#` ile maskelenmiş, **5 haneli sayıya dokunulmamış**.
6. **Deney A — eşik:** `min.digits=5` yap ve tekrar çalıştır (offset dosyasını silmeyi unutma).
   Kısa sayı da maskelendi mi?
7. **Deney B — Key sürümü:** `type` değerini `...MaskeleSmt$Key` yap. Value'lar artık maskesiz mi?
8. **Deney C — predicate:** SMT'yi yalnızca belirli bir topic'te çalıştır:
   ```properties
   predicates=sadeceBu
   predicates.sadeceBu.type=org.apache.kafka.connect.predicates.TopicNameMatches
   predicates.sadeceBu.pattern=lab-smt-.*
   transforms.maskele.predicate=sadeceBu
   ```

### Bölüm C — MM2 tasarım egzersizi (çözümlü)

> **Senaryo:** İstanbul'da aktif bir Kafka cluster'ı var (3 broker, 40 topic, 2 TB, günde 500 GB).
> Ankara'ya aktif-pasif felaket kurtarma kurulacak. RPO hedefi 5 dakika, RTO 30 dakika.
> Tüketici uygulamaları failover sonrası kaldığı yerden devam edebilmeli.

<details>
<summary>Çözüm</summary>

**Mimari:** İstanbul (kaynak) → Ankara (hedef), tek yönlü MM2. MM2 worker'ları **hedef tarafta**
çalıştırılır (uzak okuma, yerel yazma — ağ kopmalarında daha dayanıklı).

```properties
clusters = ist, ank
ist.bootstrap.servers = ist-b1:9092,ist-b2:9092,ist-b3:9092
ank.bootstrap.servers = ank-b1:9092,ank-b2:9092,ank-b3:9092

ist->ank.enabled = true
ist->ank.topics = .*
ist->ank.topics.exclude = .*\.internal,__.*        # iç topic'leri kopyalama
ist->ank.groups = .*
ist->ank.emit.checkpoints.enabled = true
ist->ank.sync.group.offsets.enabled = true
ist->ank.emit.checkpoints.interval.seconds = 30    # RPO hedefinden çok küçük

replication.factor = 3
checkpoints.topic.replication.factor = 3
heartbeats.topic.replication.factor = 3
offset-syncs.topic.replication.factor = 3
sync.topic.configs.enabled = true
refresh.topics.interval.seconds = 60
```

**Kapasite:** Günde 500 GB → sürekli ~6 MB/s replikasyon trafiği + yeniden yakalama (catch-up)
payı. WAN ([veri merkezleri arası ağ ↗](../00-baslangic/02-kavram-sozlugu.md#wan)) bant genişliği en az **3-4 katı** planlanmalı; MM2 worker'ları için ayrı makineler.

**Failover prosedürü (RTO 30 dk):**
1. İstanbul'a yazmayı durdur (mümkünse).
2. `ank` üzerinde replikasyon lag'inin sıfırlandığını doğrula (heartbeat + checkpoint topic'leri).
3. Tüketicileri Ankara'ya yönlendir; topic adları `ist.siparisler` olduğu için ya
   **abonelik regex'i** (`(ist\.)?siparisler`) kullanılır ya da `IdentityReplicationPolicy`
   bilinçli tercih edilir.
4. Üreticileri Ankara'ya yönlendir.

**Kritik uyarılar:**
- MM2 **asenkrondur**: RPO 0 değildir; kabul edilen kayıp penceresi replikasyon lag'i kadardır.
- Offsetler **çevrilir**, birebir aynı değildir → failover sonrası **duplicate işleme normaldir**;
  tüketiciler idempotent olmalı (4.2).
- Geri dönüş (failback) planı baştan yazılmalı; `ank->ist` yönü de tanımlanmadıysa
  geri dönüş elle veri taşımaya döner.
- `sync.topic.configs.enabled=true` olmadan hedefte partition sayısı/retention **farklı** kalabilir.
</details>

## Nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — Yanlış araç**
> *"SMT içinde başka bir topic'ten veri okuyup zenginleştirmek istiyoruz."*
> → SMT durumsuzdur. **Kafka Streams + GlobalKTable** (6.3).

**Kalıp 2 — Hattı durduran SMT**
> *"Özel SMT'miz beklenmedik bir tipte NPE atıyor ve connector duruyor."*
> → `apply()` tanımadığı tipte kaydı **olduğu gibi döndürmeli**.

**Kalıp 3 — Plugin bulunamıyor**
> *"`Failed to find any class that implements Transformation`."*
> → Jar yanlış yerde ya da `plugin.path` üst dizini göstermiyor (7.1).

**Kalıp 4 — Beklenmedik topic adları**
> *"MM2 sonrası hedefte `siparisler` yok, `ist.siparisler` var."* → `DefaultReplicationPolicy`
> ön eki. Beklenen davranış; tüketici aboneliğini buna göre yaz.

**Kalıp 5 — Failover'da duplicate**
> *"MM2 failover'ından sonra mesajlar tekrar işlendi."* → MM2 at-least-once'tır ve offsetler
> çevrilir. Tüketiciler idempotent olmalı.

**Kalıp 6 — Farklı yapılandırma**
> *"Hedef cluster'da partition sayısı ve retention farklı."*
> → `sync.topic.configs.enabled` kapalı.

## 60 saniyelik özet

- **SMT** = kayıt başına, **durumsuz**, hafif dönüşüm. Join/agregasyon/dış çağrı **Streams'in işi**.
- Yerleşikler: `InsertHeader`, `RegexRouter`, `MaskField`, `ExtractField`, `Cast`,
  `TimestampConverter`, `Filter`, `ValueToKey`… **Predicate**'lerle koşullu çalıştırılır.
- Kendi SMT'n: `Transformation` arayüzü + `Key`/`Value` iç sınıfları; `configure`, `apply`,
  `config`, `close`.
- SMT kuralları: **durumsuz ol**, **hızlı ol**, **dokunamıyorsan kaydı olduğu gibi döndür**.
- Dağıtım: jar'ı bir alt dizine koy, `plugin.path` **üst dizini** göstersin.
- Kendi connector'ını yazmadan önce SMT/Streams alternatiflerini tüket.
  Source connector'da **sourcePartition + sourceOffset** vermek zorunludur.
- **MM2 = üç Connect connector'ı**: `MirrorSource` (veri) · `MirrorCheckpoint` (offset çevrimi) ·
  `MirrorHeartbeat` (canlılık).
- Hedefte topic adı varsayılan olarak **`kaynak.` ön eki** alır — bu **döngü korumasıdır**.
- MM2 **asenkron ve at-least-once**'tır: RPO sıfır değildir, failover'da **duplicate normaldir**.
- **Offset çevrimi muhafazakârdır**: lab'da kaynak p0=180 iken hedef p0=**102** çevrildi
  (p1 birebir 50). MM2 emin olmadığında **geri** yuvarlar — kayıp yerine tekrar işlemeyi seçer.
- Grup listesi varsayılan **10 dakikada bir** taranır (`refresh.groups.interval.seconds=600`) —
  "offset çevrimi çalışmıyor" derken önce buna bak.
- `sync.topic.configs.enabled` olmadan hedefte partition/retention **ıraksar**.
