## Neden bu konu

4.2a'da **tek girdinin** aralıklarına baktık. Burada iki yeni durum var: **birden fazla koşulun
kombinasyonu** (karar tablosu) ve **sistemin geçmişine bağlı davranış** (durum geçiş). Sınavın
hesap sorusu genelde "kaç kural var" veya "kaç geçiş var" biçiminde gelir.

**Büyük fikir:** **Karar tablosu = koşulların kombinasyonu.** **Durum geçiş = sistemin hafızası.**
Birincisi "hangi girdi bileşimi hangi sonucu verir", ikincisi "sistem şu anda hangi durumdaysa ne olur".

---

## 1. Karar tablosu testi (Decision Table Testing) ⭐⭐

**Ne zaman kullanılır:** İş kuralı **birden fazla koşulun kombinasyonuna** bağlıysa.
"Eğer A ve B ise X, eğer A ve B değilse Y" gibi.

### Tablonun yapısı

| Bölüm | Ne içerir |
|---|---|
| **Conditions** (koşullar) | Girdi koşulları — üst satırlar |
| **Actions** (eylemler) | Sonuçlar/çıktılar — alt satırlar |
| **Rules** (kurallar) | **Her sütun bir kuraldır** — bir koşul bileşimi + sonucu |

### Gösterim biçimleri

| Biçim | Nasıl yazılır |
|---|---|
| **Full decision table** | Koşulların **tüm** kombinasyonları. n adet Boolean koşul → **2ⁿ kural** |
| **Collapsed (minimized)** | Sonucu etkilemeyen koşullar **"–" (don't care)** ile birleştirilir → kural sayısı azalır |

**Gösterim sembolleri:**

| Sembol | Anlamı |
|---|---|
| `T` / `Y` / `1` | Koşul doğru |
| `F` / `N` / `0` | Koşul yanlış |
| `–` | **Don't care** — sonucu etkilemez |
| `X` | Eylem gerçekleşir |
| (boş) | Eylem gerçekleşmez |

### Coverage item ve kapsam

- **Coverage item = kural (tablonun bir sütunu)**
- **Kapsam % = (test edilen kural sayısı / toplam kural sayısı) × 100**
- **%100 karar tablosu kapsamı = her kuraldan en az bir test case.**

**Sayı kuralı ⭐:** **n adet Boolean (T/F) koşul → tam tabloda 2ⁿ kural.**

| Koşul sayısı | Tam tablo kural sayısı |
|---|---|
| 2 | 4 |
| 3 | **8** |
| 4 | **16** |
| 5 | 32 |

> ⚠️ **Tuzak:** Bir koşulun **ikiden fazla** değeri varsa 2ⁿ geçmez. Örneğin koşullar
> {üyelik: yok/gümüş/altın} (3 değer) ve {sepet: <100 / ≥100} (2 değer) ise → **3 × 2 = 6 kural**.

### Çözümlü örnek A — 3 Boolean koşul

> **Kural:** Bir bankada kredi onayı için üç koşul var:
> **C1:** Kredi notu ≥ 700? · **C2:** Aylık gelir ≥ 20.000 TL? · **C3:** Mevcut kredisi var mı?
>
> **İş kuralı:** Kredi notu ve gelir yeterliyse onaylanır. Ama mevcut kredisi varsa,
> onay için **her ikisinin de** yeterli olması **ve** ek olarak manuel inceleme gerekir.
> Diğer tüm durumlarda reddedilir.

**Tam tablo — 3 Boolean koşul → 2³ = 8 kural:**

| | R1 | R2 | R3 | R4 | R5 | R6 | R7 | R8 |
|---|---|---|---|---|---|---|---|---|
| **C1** Not ≥700 | T | T | T | T | F | F | F | F |
| **C2** Gelir ≥20k | T | T | F | F | T | T | F | F |
| **C3** Mevcut kredi | T | F | T | F | T | F | T | F |
| **A1** Onayla | | X | | | | | | |
| **A2** Manuel incelemeye gönder | X | | | | | | | |
| **A3** Reddet | | | X | X | X | X | X | X |

**%100 kapsam için 8 test case.**

**Collapsed hali:** R3–R8'de C1 ve C2'nin ikisi birden T değilse sonuç hep "reddet" —
C3 sonucu etkilemez. Birleştirilirse:

| | R1 | R2 | R3' | R4' |
|---|---|---|---|---|
| **C1** | T | T | F | – |
| **C2** | T | T | – | F |
| **C3** | T | F | – | – |
| **A1** Onayla | | X | | |
| **A2** Manuel inceleme | X | | | |
| **A3** Reddet | | | X | X |

→ **4 kural.** Aynı iş kuralı, daha az test case.

> ⚠️ **Tuzak:** Sınav "how many rules does the FULL decision table have" mı diyor,
> yoksa "the collapsed table" mı? İkisi farklı sayı verir. **Soruyu kelime kelime oku.**

### Karar tablosunun faydaları ve maliyeti

| ✅ Fayda | ❌ Maliyet |
|---|---|
| Koşul kombinasyonlarını **sistematik** kapsar | Koşul sayısı arttıkça kural sayısı **üstel** büyür |
| **Eksik veya çelişkili** iş kurallarını ortaya çıkarır | Büyük tablolar okunması zor |
| Spesifikasyondaki boşlukları görünür kılar | Collapse etmek dikkat ister |

**En büyük yan faydası:** Tabloyu doldururken **spesifikasyonda tanımlanmamış** bir kombinasyon
bulursun. Bu **statik test** değeridir (Bölüm 3) — kod yazılmadan kusur bulmuş olursun.

## 2. Durum geçiş testi (State Transition Testing) ⭐⭐

**Ne zaman kullanılır:** Sistemin cevabı **sadece o anki girdiye değil, geçmişine de** bağlıysa.
"Aynı butona basmak, sistem hangi durumdaysa farklı sonuç veriyorsa" → durum geçiş.

### Dört bileşen

| Bileşen | Ne demek | Örnek |
|---|---|---|
| **State** (durum) | Sistemin bulunabileceği bir konum | `Boşta`, `Kilitli`, `Oynatılıyor` |
| **Event** (olay/girdi) | Duruma etki eden tetikleyici | `PIN gir`, `Oynat`, `Durdur` |
| **Transition** (geçiş) | Bir durumdan diğerine (veya kendine) gidiş | `Boşta --Oynat--> Oynatılıyor` |
| **Action** (eylem/çıktı) | Geçişle birlikte üretilen çıktı | `Ekranda "Oynatılıyor" göster` |

**İki gösterim:**

| Gösterim | Ne gösterir |
|---|---|
| **State transition diagram** | Daireler (durum) + oklar (geçiş). **Yalnızca geçerli geçişleri** gösterir |
| **State table** | Satır = durum, sütun = olay. **Tüm durum-olay kombinasyonlarını** gösterir — **geçersiz olanlar dahil** |

> ⚠️ **Kritik ayrım:** Diyagram sadece **geçerli** geçişleri gösterir; **state table geçersiz
> (imkânsız) geçişleri de** gösterir. Geçersiz geçişleri bulmak istiyorsan **tabloya** bak.
> Sınav bunu sorar.

### Üç kapsam seviyesi ⭐⭐

| Seviye | Coverage item | Ne gerektirir | Gücü |
|---|---|---|---|
| **All states coverage** | Her **durum** | Her durum en az bir kez ziyaret edilir | **En zayıf** |
| **Valid transitions coverage (0-switch)** | Her **geçerli geçiş** | Her geçerli geçiş en az bir kez uygulanır | **Standart** |
| **All transitions coverage** | **Tüm** geçişler — geçerli + **geçersiz** | Tablodaki her hücre uygulanır | **En güçlü** |

**Kritik ilişkiler:**

- **%100 valid transitions coverage ⟹ %100 all states coverage** (her geçişi koşarsan her duruma uğrarsın)
- **Tersi doğru değil:** %100 all states coverage, %100 transition coverage'ı **garanti etmez**.

> ⚠️ **En sık sorulan:** Bu iki cümle. Sınav sana "%100 all states coverage sağlandı, tüm geçerli
> geçişler kapsandı mı?" diye sorar → **hayır**.

### Çözümlü örnek B — medya oynatıcı

> **Durumlar:** `Durdurulmuş`, `Oynatılıyor`, `Duraklatılmış`
> **Geçerli geçişler:**
> - Durdurulmuş --Oynat--> Oynatılıyor
> - Oynatılıyor --Duraklat--> Duraklatılmış
> - Duraklatılmış --Oynat--> Oynatılıyor
> - Oynatılıyor --Durdur--> Durdurulmuş
> - Duraklatılmış --Durdur--> Durdurulmuş

**State table (3 durum × 3 olay = 9 hücre):**

| Durum \ Olay | **Oynat** | **Duraklat** | **Durdur** |
|---|---|---|---|
| **Durdurulmuş** | Oynatılıyor | *geçersiz* | *geçersiz* |
| **Oynatılıyor** | *geçersiz* | Duraklatılmış | Durdurulmuş |
| **Duraklatılmış** | Oynatılıyor | *geçersiz* | Durdurulmuş |

**Sayılar:**

| Ölçüm | Sayı |
|---|---|
| Durum sayısı | **3** |
| **Geçerli** geçiş sayısı | **5** |
| Geçersiz geçiş sayısı | **4** (9 − 5) |
| **All states coverage** için gereken minimum | 3 durumu ziyaret eden **1 test dizisi** yeterli olabilir |
| **Valid transitions (0-switch) coverage** | **5 geçişin hepsi** kapsanmalı |
| **All transitions coverage** | **9 hücrenin hepsi** — geçersizler dahil |

**Örnek test dizisi (valid transitions için):**
`Durdurulmuş → Oynat → Oynatılıyor → Duraklat → Duraklatılmış → Oynat → Oynatılıyor → Durdur →
Durdurulmuş → Oynat → Oynatılıyor → Duraklat → Duraklatılmış → Durdur → Durdurulmuş`
→ 5 geçerli geçişin hepsi kapsandı.

> ⚠️ **Dikkat:** Sadece `Durdurulmuş → Oynat → Duraklat → Durdur` dizisi **3 durumun hepsini** ziyaret eder
> (%100 all states coverage) ama **5 geçişin sadece 3'ünü** kapsar (%60 transition coverage).
> **Bu, iki seviyenin farkının kanıtıdır.**

## Sık karıştırılanlar — tek tabloda

| Soruda/pratikte geçen | Doğru cevap | Neden diğeri değil |
|---|---|---|
| Birden fazla koşulun kombinasyonu | **Karar tablosu** | Durum geçiş geçmişe bakar |
| Sistemin geçmişine bağlı davranış | **Durum geçiş** | Karar tablosu anlık koşullara bakar |
| Karar tablosunda **bir sütun** | **Bir kural (rule)** | Satır koşul veya eylemdir |
| Coverage item = kural | **Karar tablosu** | Durum geçişte durum veya geçiş |
| 3 Boolean koşul, tam tablo | **8 kural** | Collapsed daha az olabilir |
| 4 Boolean koşul, tam tablo | **16 kural** | 2⁴ |
| Koşul 3 değer alıyorsa | **2ⁿ geçmez** — değerleri çarp | 3 × 2 = 6 gibi |
| `–` sembolü | **Don't care** — sonucu etkilemez | T/F belirli değerlerdir |
| Sadece **geçerli** geçişleri gösterir | **State transition diagram** | Tablo geçersizleri de gösterir |
| **Geçersiz** geçişleri de gösterir | **State table** | Diyagram göstermez |
| Her durumu ziyaret et | **All states coverage** — **en zayıf** | Transition coverage daha güçlü |
| Her geçerli geçişi uygula | **Valid transitions / 0-switch** | All transitions geçersizleri de kapsar |
| Geçersiz geçişleri de test et | **All transitions coverage** — **en güçlü** | 0-switch sadece geçerlileri kapsar |
| "%100 all states ⟹ %100 transitions" | **Yanlış** | Ters yön doğrudur, bu yön değil |
| "%100 valid transitions ⟹ %100 all states" | **Doğru** | Her geçişi koşarsan her duruma uğrarsın |

### Bölüm A — karar tablosu (10 dk)

> **İş kuralı:** Bir online kurs platformunda indirim şöyle hesaplanıyor:
> - **C1:** Öğrenci mi?
> - **C2:** Yıllık abonelik mi (aylık değil)?
> - **C3:** Kupon kodu girdi mi?
>
> **Kurallar:** Öğrenci ise %20 indirim. Yıllık abonelikse ayrıca %10. Kupon varsa ayrıca %5.
> İndirimler toplanır. Hiçbiri yoksa indirim yok.

1. **Tam karar tablosunu** çiz. Kaç kural var? ______
2. Her kural için **toplam indirim** yüzdesini hesapla.
3. **%100 karar tablosu kapsamı** için kaç test case gerekir? ______
4. Bu tablo **collapse edilebilir mi**? Neden?

**Çözüm anahtarı:**

| | R1 | R2 | R3 | R4 | R5 | R6 | R7 | R8 |
|---|---|---|---|---|---|---|---|---|
| C1 Öğrenci | T | T | T | T | F | F | F | F |
| C2 Yıllık | T | T | F | F | T | T | F | F |
| C3 Kupon | T | F | T | F | T | F | T | F |
| **İndirim** | **35%** | **30%** | **25%** | **20%** | **15%** | **10%** | **5%** | **0%** |

- **Kural sayısı: 2³ = 8**
- **%100 kapsam: 8 test case**
- **Collapse edilemez** — çünkü **her koşul sonucu etkiliyor**, hiçbir yerde "don't care" yok.
  ⭐ Bu önemli bir ders: collapse her zaman mümkün değildir.

- [ ] **Kontrol:** 8 kuralın 8'inde farklı indirim çıktı. Aynı çıkan iki kural varsa yanlış hesapladın.
- [ ] **Kaydet:** Eğer "kupon sadece yıllık abonelikte geçerli" kuralı eklenseydi, hangi kurallar
      **çelişkili** hale gelirdi? ______ (Cevap: R3 ve R7 — kupon var ama yıllık değil)

### Bölüm B — state table (10 dk)

> **Sistem:** Bir ATM kartı. Durumlar: `Aktif`, `Bloke`, `İptal`
> **Olaylar:** `Yanlış PIN (3. kez)`, `Şubede çöz`, `Kartı iptal et`
> **Geçerli geçişler:**
> - Aktif --Yanlış PIN (3. kez)--> Bloke
> - Bloke --Şubede çöz--> Aktif
> - Aktif --Kartı iptal et--> İptal
> - Bloke --Kartı iptal et--> İptal

1. **State table**'ı çiz (3 durum × 3 olay = 9 hücre). Geçersiz hücreleri işaretle.
2. Durum sayısı: ______ · Geçerli geçiş sayısı: ______ · Geçersiz geçiş sayısı: ______
3. **%100 all states coverage** için bir test dizisi yaz.
4. Bu dizi **%100 valid transitions coverage** sağlıyor mu? ______

**Çözüm anahtarı:**

| Durum \ Olay | Yanlış PIN (3.) | Şubede çöz | Kartı iptal et |
|---|---|---|---|
| **Aktif** | Bloke | *geçersiz* | İptal |
| **Bloke** | *geçersiz* | Aktif | İptal |
| **İptal** | *geçersiz* | *geçersiz* | *geçersiz* |

- Durum: **3** · Geçerli geçiş: **4** · Geçersiz geçiş: **9 − 4 = 5**
- **All states dizisi:** `Aktif --Yanlış PIN--> Bloke --Kartı iptal et--> İptal`
  → 3 durumun hepsi ziyaret edildi = **%100 all states coverage**
- **Ama valid transitions:** 4 geçişin sadece **2'si** kapsandı = **%50**.
  Eksikler: `Bloke --Şubede çöz--> Aktif` ve `Aktif --Kartı iptal et--> İptal`

- [ ] **Kontrol:** 4. soruya "hayır" dedin ve eksik geçişleri yazdın.
      **Bu, %100 all states'in %100 transitions'ı garanti etmediğinin kanıtıdır.**
- [ ] **Kaydet:** `İptal` durumundan çıkış yok. Buna ne denir? ______ (Cevap: **terminal/final state**)

## Sınavda nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — Kural sayısı**
> *"A decision table has four independent Boolean conditions. How many rules does the FULL decision
> table contain?"* → **16 (2⁴)**

**Kalıp 2 — Boolean olmayan koşul**
> *"One condition has three possible values and another has two. How many rules does the full
> decision table contain?"* → **6 (3 × 2)**

**Kalıp 3 — Kapsam tanımı**
> *"What does 100% decision table coverage require?"*
> → **At least one test case for every rule (column) in the table.**

**Kalıp 4 — Don't care**
> *"In a collapsed decision table, what does the '–' symbol mean?"*
> → **The condition does not affect the outcome for that rule (don't care).**

**Kalıp 5 — Diyagram vs tablo**
> *"Which representation shows invalid transitions?"* → **The state table** (diyagram göstermez)

**Kalıp 6 — Kapsam ilişkisi**
> *"100% all states coverage has been achieved. Does this guarantee 100% valid transitions coverage?"*
> → **No. But 100% valid transitions coverage does guarantee 100% all states coverage.**

**Kalıp 7 — Geçiş sayma**
> *"A system has 4 states and 5 events. How many cells does the state table contain, and how many
> of them may represent invalid transitions?"* → **20 cells; those not shown in the diagram are invalid.**

**Kalıp 8 — Teknik seçimi**
> *"An application's response to a button depends on which screen the user came from. Which technique
> is MOST appropriate?"* → **State transition testing** (geçmişe bağlı davranış)

## 60 saniyelik özet

### Karar tablosu
- **Koşulların kombinasyonu** için. Sütun = **kural**, satırlar = **conditions** ve **actions**.
- **n Boolean koşul → tam tabloda 2ⁿ kural.** Koşul 2'den fazla değer alıyorsa **değerleri çarp**.
- **Coverage item = kural.** %100 kapsam = **her kuraldan en az bir test case**.
- **Collapsed** tablo `–` (don't care) ile kural sayısını azaltır — ama **her tablo collapse edilemez**.
- Yan faydası: **spesifikasyondaki boşluk ve çelişkileri** ortaya çıkarır (statik test değeri).

### Durum geçiş
- **Geçmişe bağlı davranış** için. Dört bileşen: **state · event · transition · action**.
- **Diyagram → sadece geçerli geçişler.** **State table → geçersizler de dahil**, tüm kombinasyonlar.
- Üç kapsam: **all states (en zayıf)** < **valid transitions / 0-switch** < **all transitions (en güçlü)**.
- **%100 valid transitions ⟹ %100 all states.** **Tersi geçerli değildir.**
- Geçersiz geçişleri test etmek istiyorsan **state table** kullan.
