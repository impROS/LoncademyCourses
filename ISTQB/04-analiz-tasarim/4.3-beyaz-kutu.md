## Neden bu konu

Sınavın en net **hesap sorusu** buradan gelir: "bu kod parçası için %100 statement/branch coverage
kaç test case gerektirir?" Cevabı ezberle değil, **saymayla** bulursun. En sık kaybedilen puan:
statement ile branch coverage'ı karıştırmak ve **%100 branch ⟹ %100 statement** ilişkisini ters kurmak.

**Büyük fikir:** **Statement coverage = her satır çalıştı mı. Branch coverage = her karar hem TRUE
hem FALSE sonuçlandı mı.** Branch daha güçlüdür ve statement'ı **içerir**.

---

## 1. Statement testing ve statement coverage ⭐

**Coverage item = çalıştırılabilir ifade (executable statement).**

```
Statement coverage % = (çalıştırılan ifade sayısı / toplam ifade sayısı) × 100
```

**%100 statement coverage** = kodun **her çalıştırılabilir satırı** en az bir kez çalıştırıldı.

### Çözümlü örnek A

```java
1  public int f(int x) {
2      int r = 0;
3      if (x > 10) {
4          r = 1;
5      }
6      return r;
7  }
```

Çalıştırılabilir ifadeler: satır 2, 3, 4, 6 → **4 ifade**

| Test | x | Çalışan satırlar | Statement coverage |
|---|---|---|---|
| T1 | 20 | 2, 3, 4, 6 | **4/4 = %100** |
| T2 | 5 | 2, 3, 6 | 3/4 = %75 |

→ **%100 statement coverage için 1 test case yeterli** (x = 20).

> ⚠️ **Kritik:** Bu tek test, `if` koşulunun **FALSE** olduğu durumu **hiç denemedi**.
> Yani `x ≤ 10` yolunda bir kusur varsa (örneğin `r`'nin 0 dönmemesi gerekiyorsa) **bulamazsın**.
> **Statement coverage'ın zayıflığı tam olarak budur.**

---

## 2. Branch testing ve branch coverage ⭐⭐

**Branch (dal):** Bir kararın (decision) sonuçlarından biri — koşullu dallarda **TRUE dalı** ve
**FALSE dalı**; ayrıca koşulsuz atlamalar da birer daldır.

**Coverage item = dal (branch).**

```
Branch coverage % = (çalıştırılan dal sayısı / toplam dal sayısı) × 100
```

**%100 branch coverage** = her karar hem **TRUE** hem **FALSE** sonucunu verecek şekilde çalıştırıldı
(ve tüm koşulsuz dallar geçildi).

### Aynı örnek, branch coverage

```java
3      if (x > 10) {     // 2 dal: TRUE ve FALSE
```

| Test | x | `x > 10` | Kapsanan dal |
|---|---|---|---|
| T1 | 20 | TRUE | TRUE dalı |
| T2 | 5 | FALSE | FALSE dalı |

→ **%100 branch coverage için 2 test case gerekir.**

> ⚠️ **Bu, iki kapsamın farkının en net örneğidir:** aynı kod için
> **statement %100 → 1 test**, **branch %100 → 2 test**.

### Çözümlü örnek B — iki bağımsız `if`

```java
1  public int discount(int age, boolean member) {
2      int rate = 0;
3      if (age < 18) {
4          rate = 20;
5      }
6      if (member) {
7          rate = rate + 10;
8      }
9      return rate;
10 }
```

**Kararlar:** 2 (satır 3 ve satır 6) → **4 dal** (her karar için TRUE + FALSE)

| Test | age | member | `age<18` | `member` | rate |
|---|---|---|---|---|---|
| T1 | 10 | true | **T** | **T** | 30 |
| T2 | 30 | false | **F** | **F** | 0 |

**Kapsanan dallar:** T1 → iki TRUE dalı. T2 → iki FALSE dalı. **Toplam 4/4 = %100 branch coverage.**

→ **%100 branch coverage için 2 test case yeterli.**

**%100 statement coverage için?** Satır 4 ve 7'nin çalışması gerekir → T1 tek başına yeterli.
→ **1 test case.**

> ⚠️ **Sık yapılan hata:** "2 karar var, her biri 2 dal, o halde 4 test case lazım" demek. **Yanlış.**
> Bir test case **birden fazla dalı** aynı anda kapsayabilir. **Dal sayısı ≠ test case sayısı.**
> Sınav bunu doğrudan sorar.

### Çözümlü örnek C — iç içe `if`

```java
1  public String grade(int score, boolean bonus) {
2      if (score >= 50) {
3          if (bonus) {
4              return "A";
5          }
6          return "B";
7      }
8      return "F";
9  }
```

**Kararlar:** satır 2 ve satır 3 → **4 dal**

| Test | score | bonus | Satır 2 | Satır 3 | Sonuç |
|---|---|---|---|---|---|
| T1 | 80 | true | **T** | **T** | "A" |
| T2 | 80 | false | T | **F** | "B" |
| T3 | 30 | – | **F** | *çalışmaz* | "F" |

**%100 branch coverage için 3 test case.**
⚠️ İç içe yapıda, dış kararın FALSE dalını denemek için ayrı bir test gerekir — çünkü o durumda
iç karar hiç çalışmaz.

**%100 statement coverage için?** Satır 4, 6, 8'in her biri çalışmalı → yine **3 test case**.
Bu örnekte ikisi eşit çıkıyor; ama örnek A ve B'de eşit değildi. **Her koda göre değişir, sayarak bul.**

## 3. İki kapsamın ilişkisi ⭐⭐ — sınavın favorisi

| İfade | Doğru mu |
|---|---|
| **%100 branch coverage ⟹ %100 statement coverage** | ✅ **Doğru** |
| **%100 statement coverage ⟹ %100 branch coverage** | ❌ **Yanlış** |

**Neden:** Her dalı çalıştırırsan, o dalların içindeki tüm satırları da çalıştırmış olursun.
Ama her satırı çalıştırmak, her kararın **iki sonucunu** da denediğin anlamına gelmez —
örnek A'da gördüğün gibi.

**Hafıza kancası:** **Branch, statement'ı yutar.** Branch daha güçlü, daha pahalı, daha çok test ister.

> ⚠️ **Özel durum:** `if` bloğunun `else`'i yoksa bile FALSE dalı vardır (`if` atlanır).
> Bu dal **kod satırı içermez** ama yine de bir daldır ve branch coverage için test edilmelidir.
> Statement coverage bu dalı hiç görmez — çünkü orada sayılacak bir satır yok.

## 4. Beyaz kutu testinin değeri ⭐

| ✅ Değeri | ❌ Sınırı |
|---|---|
| Kodun **tamamı** dikkate alınır — spesifikasyonda olmayan yollar dahil | **Spesifikasyonda olup kodda hiç yazılmamış** özelliği bulamaz |
| Kapsam **sayısal olarak ölçülebilir** | Yüksek kapsam kodun **doğru** olduğunu göstermez |
| **Kusur maskeleme**ye karşı korur | Kod bilgisi ve araç gerektirir |
| Spesifikasyon eksik/güncel değilse bile uygulanabilir | Eksik gereksinimleri göremez |
| Otomatik araçlarla ölçülebilir (JaCoCo gibi) | Yalnızca yazılanı ölçer |

> ⚠️ **En kritik sınır:** **%100 branch coverage, kodun doğru olduğunu göstermez.**
> Yanlış formül yazılmışsa, %100 kapsamla da yanlış sonuç dönerken tüm testler geçebilir —
> tabii testlerin beklenen sonuçları da yanlışsa. Kapsam bir **ölçüdür**, bir **kalite garantisi değil**.

> ⚠️ **İkinci kritik sınır:** Beyaz kutu **eksik kodu** göremez. Bu yüzden 4.1'de söylediğimiz gibi
> **kara kutu ile birlikte** kullanılır.

## Sınavda nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — Test case sayma**
> ```
> if (a > 0) { x = 1; }
> if (b > 0) { y = 2; }
> ```
> *"What is the minimum number of test cases required for 100% branch coverage?"* → **2**
> (`a>0 && b>0` bir test, `a≤0 && b≤0` ikinci test)

**Kalıp 2 — Statement vs branch**
> ```
> if (x > 10) { y = 1; }
> return y;
> ```
> *"How many test cases are needed for 100% statement coverage, and how many for 100% branch coverage?"*
> → **1 for statement, 2 for branch**

**Kalıp 3 — İlişki**
> *"Which statement is correct?"*
> → **100% branch coverage implies 100% statement coverage, but not vice versa.**

**Kalıp 4 — Kapsamın sınırı**
> *"A module has 100% branch coverage and all tests pass. What can you conclude?"*
> → **Only that every branch was exercised — not that the code is correct or complete.**

**Kalıp 5 — Beyaz kutunun kör noktası**
> *"Which defect can 100% branch coverage NOT detect?"*
> → **A required feature that was never implemented.**

**Kalıp 6 — else'siz if**
> *"An `if` statement has no `else` block. How many branches does the decision have?"* → **Two**
> (TRUE dalı ve `if`'in atlandığı FALSE dalı)

## 60 saniyelik özet

- **Statement coverage:** coverage item = **çalıştırılabilir ifade**. %100 = her satır en az bir kez çalıştı.
- **Branch coverage:** coverage item = **dal**. %100 = her karar hem **TRUE** hem **FALSE** sonuçlandı.
- Kapsam formülü ikisinde de: **(kapsanan / toplam) × 100.**
- **%100 branch ⟹ %100 statement. Tersi geçerli değildir.** Branch daha güçlü, daha pahalı.
- **Dal sayısı ≠ test case sayısı.** Bir test birden fazla dalı kapsayabilir. **Say, çarpma.**
- `else`'siz `if`'in de **iki dalı** vardır; FALSE dalı kod satırı içermez ama branch coverage için gerekir.
- Beyaz kutunun değeri: kodun **tamamını** dikkate alır, kapsam **sayısal ölçülür**, spesifikasyon
  eksikse bile uygulanabilir.
- Beyaz kutunun sınırı: **hiç yazılmamış özelliği bulamaz** ve **%100 kapsam doğruluk kanıtı değildir**.
- Bu yüzden **kara kutu ile birlikte** kullanılır.
