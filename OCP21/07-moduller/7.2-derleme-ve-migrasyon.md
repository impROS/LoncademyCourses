# 7.2 — Derleme, jar, jlink ve Modüle Geçiş

## Neden bu konu

Sınav burada **komut satırı bayraklarını** sorar: `-p` neyin kısaltması, `-m` nasıl yazılır,
`jar --describe-module` ne gösterir, `jdeps` ne işe yarar.

Bunlar ezberlenir. IDE arkanda çalıştırdığı için hiç görmemiş olabilirsin — bu yüzden bu konuyu
**terminalde yaparak** öğrenmelisin.

**Büyük fikir:** Modül dünyasında **classpath yerine module path** geçer. Aynı komutların
`-cp` yerine `-p`, sınıf adı yerine `modül/sınıf` alan sürümleri vardır.

---

## 1. ⭐⭐ Komutlar ve bayraklar

### `javac` — derleme

```bash
# tek modul
javac -d out/com.ocp.api $(find src/com.ocp.api -name '*.java')

# COK modul (tercih edilen)
javac -d out --module-source-path src $(find src -name '*.java')

# baska modullere bagimliysa
javac -d out --module-path libs --module-source-path src $(find src -name '*.java')
```

| Bayrak | Uzun hâli | Anlamı |
|---|---|---|
| `-d` | — | Çıktı dizini |
| `-p` | `--module-path` | Bağımlı modüllerin bulunduğu yer |
| — | `--module-source-path` | Çok modüllü kaynak kökü |
| `-cp` / `-classpath` | — | Eski classpath |

### `java` — çalıştırma

```bash
java --module-path out --module com.ocp.uygulama/com.ocp.uygulama.Main
java -p out -m com.ocp.uygulama/com.ocp.uygulama.Main        # kisa hali
java -p jars -m com.ocp.uygulama                              # jar'da Main-Class varsa
```

| Bayrak | Kısa | Anlamı |
|---|---|---|
| `--module-path` | `-p` | Modül yolu |
| `--module` | `-m` | **`modulAdi/AnaSinifTamAdi`** |
| `--list-modules` | — | Görünen tüm modülleri listeler |
| `--describe-module` | `-d` | Bir modülün yönergelerini gösterir |
| `--show-module-resolution` | — | Çözümleme adımlarını yazdırır |

> ⚠️⚠️ **Tuzak:** `-m` değeri **`modul/sinif`** biçimindedir — arada **eğik çizgi**, nokta değil.
> `java -m com.ocp.uygulama.Main` **çalışmaz**.

### `jar` — paketleme

```bash
jar --create --file jars/api.jar -C out/com.ocp.api .
jar --create --file jars/app.jar --main-class com.ocp.uygulama.Main -C out/com.ocp.uygulama .
jar --describe-module --file jars/saglayici.jar
jar --list --file jars/api.jar
```

| Bayrak | Kısa | Anlamı |
|---|---|---|
| `--create` | `-c` | Yeni jar |
| `--file` | `-f` | Jar dosyası adı |
| `--main-class` | `-e` | Manifest'e giriş noktası yazar |
| `-C dizin .` | — | O dizine geçip içeriği al |
| `--describe-module` | `-d` | **Modül yönergelerini** gösterir |
| `--list` | `-t` | İçeriği listeler |
| `--update` | `-u` | Var olan jar'ı günceller |

### `jdeps` — bağımlılık analizi

```bash
jdeps --module-path jars -s jars/app.jar          # ozet bagimliliklar
jdeps --jdk-internals uygulama.jar                # kullanilan JDK ic API'leri
jdeps --generate-module-info out uygulama.jar     # taslak module-info uretir
```

### `jlink` — özel çalışma zamanı

```bash
jlink --module-path jars \
      --add-modules com.ocp.uygulama,com.ocp.saglayici \
      --launcher selam=com.ocp.uygulama \
      --output runtime

./runtime/bin/selam
```

| Not | Detay |
|---|---|
| Ne üretir | **JRE gerektirmeyen**, yalnızca gereken modülleri içeren çalışma zamanı |
| Boyut kazancı | Tam JDK ~300 MB yerine ~50 MB civarı (⚠️ sürüme göre değişir) |
| Şart | **Tüm** modüller adlandırılmış olmalı — **automatic modül kabul etmez** |
| `--launcher ad=modul` | Çalıştırılabilir betik üretir |
| `--compress` / `--strip-debug` | Boyutu daha da küçültür |

> ⚠️ **`jlink` automatic modüllerle çalışmaz.** Classpath'ten gelen jar'lar önce gerçek modül
> hâline getirilmelidir.

## 2. ⭐ Modüle geçiş stratejileri

| Strateji | Nasıl | Ne zaman |
|---|---|---|
| **Bottom-up (aşağıdan yukarı)** | Önce **bağımlılıkların en altındakini** modülleştir, yukarı doğru çık | Tüm bağımlılıklar modüle çevrilebiliyorsa — **tercih edilen** |
| **Top-down (yukarıdan aşağı)** | Önce **uygulamayı** modülleştir, bağımlılıkları **automatic modül** olarak bırak | Kütüphaneler henüz modül değilse |

Sebep: **adlandırılmış bir modül, classpath'teki (unnamed) kodu okuyamaz** (7.1).
Bu yüzden aşağıdan yukarı gitmek doğal sıradır.

### ⭐ Split package sorunu

**Aynı paket adı birden çok modülde bulunamaz.** Modül sistemi bunu başlatma anında
`java.lang.LayerInstantiationException` veya derleme hatasıyla reddeder.

Eski kütüphanelerde sık görülür ve migrasyonun en zorlu adımıdır; çözümü paketleri
yeniden adlandırmak veya jar'ları birleştirmektir.

---

## 3. Erişim kontrolünün yeni katmanı

Java 9 öncesi: `private` → paket-özel → `protected` → `public`.
Java 9 sonrası **`public` artık üç ayrı anlama gelir**:

| Durum | Kim erişir |
|---|---|
| `public` + paket **`exports` edilmemiş** | **Yalnızca kendi modülü** |
| `public` + `exports p to m` | Yalnızca `m` |
| `public` + `exports p` | Herkes |

Buna **"public ama exported değil"** durumu denir ve modül sisteminin özüdür.

## Sık karıştırılanlar — tek tabloda

| Soruda geçen | Doğru cevap | Neden diğeri değil |
|---|---|---|
| `-p` | `--module-path` | `-cp` classpath |
| `-m` değeri | **`modul/SinifTamAdi`** | Nokta değil, eğik çizgi |
| `--module-source-path` | Çok modüllü **derleme** | `--module-path` bağımlılıklar için |
| `jar -d` / `--describe-module` | Modül yönergelerini gösterir | `--list` içeriği listeler |
| `jar --main-class` | Manifest'e giriş noktası | Modül adı değil |
| `jdeps` | Bağımlılık **analizi** | Modül üretmez (`--generate-module-info` hariç, o **taslak** üretir) |
| `jlink` | Özel **çalışma zamanı** | Jar üretmez |
| `jlink` + automatic modül | **Çalışmaz** | Tümü named olmalı |
| Aynı paket iki modülde | **Split package** — yasak | Çalışma/derleme hatası |
| Named modül → classpath | **Erişemez** | Migrasyon yönünü belirler |
| `public` + exports yok | Modül **dışından erişilemez** | — |

## 🖥 Pratik — Paketle, analiz et, kendi runtime'ını üret

> **Amaç:** jar / jdeps / jlink zincirini uçtan uca çalıştırmak · **Süre:** 25 dk
> **💸 Maliyet:** Yok · **Disk:** `jlink` çıktısı ~50 MB yer kaplar, sonunda silinecek

### Adımlar

1. 7.1'deki modülleri derle (zaten yaptıysan atla):
   ```bash
   cd 07-moduller/ornekler
   javac -d out --module-source-path src $(find src -name '*.java')
   ```
2. Üç modülü de jar'la:
   ```bash
   mkdir -p jars
   jar --create --file jars/com.ocp.api.jar -C out/com.ocp.api .
   jar --create --file jars/com.ocp.saglayici.jar -C out/com.ocp.saglayici .
   jar --create --file jars/com.ocp.uygulama.jar --main-class com.ocp.uygulama.Main -C out/com.ocp.uygulama .
   ```
3. Modül tanımını oku:
   ```bash
   jar --describe-module --file jars/com.ocp.saglayici.jar
   ```
   **Beklenen:** `requires com.ocp.api`, `requires java.base mandated`,
   `provides com.ocp.api.Selamlayici with com.ocp.saglayici.TurkceSelamlayici`.
4. Jar'lardan çalıştır — `--main-class` sayesinde sınıf adı yazmana gerek yok:
   ```bash
   java -p jars -m com.ocp.uygulama
   ```
5. Bağımlılıkları analiz et:
   ```bash
   jdeps --module-path jars -s jars/com.ocp.uygulama.jar
   ```
6. 💸 **Kendi çalışma zamanını üret** (~50 MB disk):
   ```bash
   jlink --module-path jars --add-modules com.ocp.uygulama,com.ocp.saglayici \
         --launcher selam=com.ocp.uygulama --output runtime
   ./runtime/bin/selam
   du -sh runtime
   ```
7. Modülleri listele:
   ```bash
   java --module-path jars --describe-module com.ocp.uygulama
   java --list-modules | head -5
   ```

- [ ] **Kontrol:** `jar --describe-module` çıktısında `provides ... with ...` satırını gördün.
- [ ] **Kontrol:** `./runtime/bin/selam` uygulamayı **JDK olmadan** çalıştırdı.
- [ ] **Kaydet:** `du -sh runtime` kaç MB gösterdi? ______

### 💸 Temizlik (ZORUNLU — ~50 MB)

```bash
rm -rf runtime out jars
```

- [ ] **Kontrol:** `ls` çıktısında yalnızca `src` kaldı.

## Sınavda nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — `-m` biçimi**
> Modülü çalıştırmak için doğru komut hangisi?
> → **`java -p out -m com.ocp.uygulama/com.ocp.uygulama.Main`**

**Kalıp 2 — Bayrak eşleme**
> `-p` neyin kısaltmasıdır?
> → **`--module-path`**

**Kalıp 3 — jlink kısıtı**
> Bağımlılıklardan biri automatic modül. `jlink` çalışır mı?
> → **Hayır.**

**Kalıp 4 — Split package**
> İki farklı modül `com.util` paketini içeriyor.
> → **Hata.** Aynı paket iki modülde bulunamaz.

**Kalıp 5 — public erişimi**
> Bir sınıf `public` ama paketi `exports` edilmemiş. Başka modül erişebilir mi?
> → **Hayır.**

## 60 saniyelik özet

- `-p` = **`--module-path`**; `-m` = **`--module`** ve değeri **`modul/SinifTamAdi`**'dır.
- Çok modüllü derleme: **`javac -d out --module-source-path src ...`**.
- `jar --create --file ... --main-class ... -C dizin .`
- **`jar --describe-module`** bir jar'ın modül yönergelerini gösterir.
- Jar'da `Main-Class` varsa `java -p jars -m modulAdi` yeter.
- **`jdeps`** bağımlılıkları analiz eder; `--generate-module-info` **taslak** üretir.
- **`jlink`** yalnızca gereken modülleri içeren **özel çalışma zamanı** üretir;
  **automatic modüllerle çalışmaz**.
- `--launcher ad=modul` çalıştırılabilir betik üretir.
- Migrasyon: **bottom-up tercih edilir**; named modüller **classpath'i okuyamaz**.
- **Split package yasaktır**: aynı paket birden çok modülde bulunamaz.
- Java 9'dan beri `public` "erişilebilir" demek değildir — paket **`exports`** edilmiş olmalıdır.
