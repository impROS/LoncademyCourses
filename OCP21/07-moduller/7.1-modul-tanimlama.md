# 7.1 — Modül Tanımlama: exports, requires ve Servisler

> **Süre:** ~35 dakika okuma + 25 dakika pratik
> **Test:** [`7.1-test.html`](7.1-test.html) · 14 soru

## Neden bu konu

Modüller günlük işte nadiren yazdığın ama sınavda **kesin sorulan** bir konu. Spring Boot ile
çalışıyorsan `module-info.java` görmemiş olabilirsin — bu yüzden bu iki konu (7.1, 7.2)
**pratik yapmadan geçilmemesi gereken** yerlerdir.

Sınav en çok şunu sorar: **`requires` mi `exports` mi?** Hangisi "ben kullanacağım", hangisi
"başkaları kullanabilsin" demek.

**Büyük fikir:** Modül sistemi **paket düzeyinde erişim kontrolüdür**. `public` artık "herkes
erişebilir" demek değil — "modülüm bu paketi **`exports` ederse** herkes erişebilir" demek.

---

## 1. ⭐ `module-info.java`

Modülün **kök dizininde**, paket dışında durur:

```
src/com.ocp.api/
├── module-info.java
└── com/ocp/api/Selamlayici.java
```

```java
module com.ocp.api {
    exports com.ocp.api;
}
```

| Kural | Detay |
|---|---|
| Dosya adı | **`module-info.java`** — tam olarak böyle |
| Konum | Modülün kök dizini (paket klasörlerinin **üstünde**) |
| Modül adı | Nokta ayrılmış tanımlayıcılar; **tire (`-`) yasak** |
| Ad ile klasör | Aynı olması **zorunlu değil** ama gelenektir |
| `java.base` | **Otomatik** gelir, yazmaya gerek yok |
| Boş gövde | `module m { }` geçerlidir |
| `module` / `requires` / `exports` | **Bağlamsal anahtar kelimeler** — değişken adı olarak kullanılabilirler |

---

## 2. ⭐⭐ Yönergeler

| Yönerge | Anlamı | Yön |
|---|---|---|
| `requires m;` | **Ben** `m`'ye bağımlıyım | İçeri |
| `requires transitive m;` | Ben `m`'ye bağımlıyım **ve beni kullananlar da onu görsün** | İçeri + yayılır |
| `requires static m;` | Derlemede gerekli, **çalışmada isteğe bağlı** | İçeri |
| `exports p;` | `p` paketimi **herkese** açarım | Dışarı |
| `exports p to a, b;` | `p` paketimi **yalnızca** `a` ve `b`'ye açarım (qualified export) | Dışarı |
| `opens p;` | `p` paketimi **çalışma zamanı yansımasına (reflection)** açarım | Dışarı |
| `opens p to a;` | Yalnızca belirli modüllere | Dışarı |
| `uses S;` | `S` servisini **tüketirim** | Servis |
| `provides S with Impl;` | `S` servisini `Impl` ile **sağlarım** | Servis |
| `open module m { }` | **Tüm** paketler yansımaya açık | Modül düzeyi |

> ⚠️⚠️ **Tuzak:** `exports` **derleme + çalışma zamanı** erişimi verir ama **yansımaya (reflection)**
> özel üyelere erişim vermez. Frameworkler (Spring, Jackson, JPA) için **`opens`** gerekir.

> ⚠️ `open module m { }` içinde ayrıca `opens` yazamazsın — **derleme hatası**.

### `requires transitive` neden var

```java
module a { exports com.a; }
module b { requires transitive a; exports com.b; }
module c { requires b; }        // c, com.a paketini de GORUR
```

`b` API'sinde `a`'nın tiplerini döndürüyorsa `transitive` **şarttır**; yoksa `c` derlenmez.

## 3. ⭐⭐ Servisler (`uses` / `provides`)

Modül sistemi, arayüz ile uygulamayı **birbirinden habersiz** tutmanın yolunu sunar.

```java
// api modulu
module com.ocp.api { exports com.ocp.api; }

// saglayici modulu
module com.ocp.saglayici {
    requires com.ocp.api;
    provides com.ocp.api.Selamlayici with com.ocp.saglayici.TurkceSelamlayici;
}

// tuketici modulu
module com.ocp.uygulama {
    requires com.ocp.api;
    uses com.ocp.api.Selamlayici;
}
```

```java
ServiceLoader<Selamlayici> yukleyici = ServiceLoader.load(Selamlayici.class);
for (Selamlayici s : yukleyici) { System.out.println(s.selamla("Ridvan")); }
```

| Kural | Detay |
|---|---|
| Uygulama sınıfı | **Parametresiz `public` constructor** gerekir (veya `public static provider()` metodu) |
| Uygulama paketi | **`exports` edilmek zorunda değil** — servis mekanizması erişimi kendisi sağlar |
| Tüketici | `uses` yazmadan `ServiceLoader` **hiçbir sağlayıcı bulamaz** |
| Sağlayıcı yoksa | `ServiceLoader` boş döner — **exception atmaz** |
| Birden çok sağlayıcı | Hepsi döner, **sıra garantisi yok** |

---

## 4. Modül türleri

| Tür | Ne demek |
|---|---|
| **Named (adlandırılmış)** | `module-info.java` içerir, modül yolunda (`--module-path`) |
| **Automatic (otomatik)** | `module-info.java` **yok** ama modül yolunda; adı jar adından veya `Automatic-Module-Name` manifest girdisinden gelir. **Her şeyi exports eder** ve **tüm modülleri requires eder** |
| **Unnamed (adsız)** | Classpath'teki her şey. Named modüller **onu göremez** |

> ⚠️ **Tuzak:** Adlandırılmış bir modül, **classpath'teki (unnamed) koda erişemez**.
> Bu yüzden modülerleşme "aşağıdan yukarı" (bottom-up) yapılır (7.2).

## Sık karıştırılanlar — tek tabloda

| Soruda geçen | Doğru cevap | Neden diğeri değil |
|---|---|---|
| "Bu modülü kullanacağım" | **`requires`** | `exports` tam tersi |
| "Paketimi açayım" | **`exports`** | `requires` içeri bakar |
| Yansıma (reflection) erişimi | **`opens`** | `exports` yansımaya özel üye vermez |
| Bağımlılığın API'de görünmesi | **`requires transitive`** | Düz `requires` yayılmaz |
| Derlemede var, çalışmada yok | **`requires static`** | — |
| Yalnızca belirli modüle açmak | `exports p to m;` | — |
| `open module` + `opens` birlikte | **Derleme hatası** | Zaten hepsi açık |
| Modül adında tire | **Yasak** | Nokta ve alt çizgi serbest |
| `java.base` | **Otomatik** | Yazılmasına gerek yok |
| Servis uygulama sınıfı `exports` | **Gerekmez** | `provides` yeter |
| `uses` yazılmadı | `ServiceLoader` **boş döner** | Exception atmaz |
| Servis uygulamasında ctor | **Parametresiz public** şart | — |
| Named modül → classpath kodu | **Erişemez** | Unnamed modül görünmez |
| Automatic modül | Her şeyi **exports** eder | — |

## 🖥 Pratik — Üç modüllü bir servis kur

> **Amaç:** `requires`/`exports`/`uses`/`provides` zincirini gerçekten çalıştırmak · **Süre:** 25 dk
> **💸 Maliyet:** Yok

### Adımlar

1. Kurs kökünden örnek klasörüne git:
   ```bash
   cd 07-moduller/ornekler
   ```
2. Yapıyı incele — üç modül var:
   ```bash
   find src -type f | sort
   ```
   `com.ocp.api` (arayüz) · `com.ocp.saglayici` (uygulama) · `com.ocp.uygulama` (tüketici).
3. Üçünü birden derle:
   ```bash
   javac -d out --module-source-path src $(find src -name '*.java')
   ```
4. Çalıştır:
   ```bash
   java --module-path out --module com.ocp.uygulama/com.ocp.uygulama.Main
   ```
   **Beklenen çıktı:**
   ```
   modul adi   : com.ocp.uygulama
   named mi?   : true
   bulunan servis: com.ocp.saglayici.TurkceSelamlayici -> Merhaba, Ridvan!
   toplam servis : 1
   ```
5. **Deney 1:** `src/com.ocp.uygulama/module-info.java` içindeki `uses` satırını sil, yeniden derle
   ve çalıştır. Servis sayısı **0**'a düşecek — `uses` olmadan `ServiceLoader` hiçbir şey bulamaz.
   Satırı geri koy.
6. **Deney 2:** `src/com.ocp.api/module-info.java` içindeki `exports` satırını sil ve derlemeyi dene.
   `package com.ocp.api is not visible` hatasını göreceksin. Geri koy.

## Sınavda nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — Yön sorusu**
> `moduleB`, `moduleA`'nın bir sınıfını kullanacak. `moduleA`'da ve `moduleB`'de hangi yönergeler olmalı?
> → `moduleA`: **`exports`**, `moduleB`: **`requires`**.

**Kalıp 2 — Reflection**
> Bir framework `moduleA`'daki private alanlara yansımayla erişmek istiyor.
> → **`opens`** gerekir; `exports` yetmez.

**Kalıp 3 — transitive**
> `b`'nin public API'si `a`'nın tipini döndürüyor, `c` `b`'yi kullanıyor ve derlenmiyor.
> → `b` içinde **`requires transitive a;`**.

**Kalıp 4 — Servis**
> ```java
> module m { provides Api with Impl; }
> ```
> `Impl`'in paketi `exports` edilmeli mi?
> → **Hayır.**

**Kalıp 5 — Geçersiz ad**
> ```java
> module com.ocp-api { }
> ```
> → **Compilation fails.** Tire yasak.

## 60 saniyelik özet

- `module-info.java` modülün **kökünde**, paket klasörlerinin üstünde durur.
- **`requires` = içeri**, **`exports` = dışarı**. En çok karıştırılan çift budur.
- `requires transitive` bağımlılığı **kullananlara da** geçirir.
- `requires static` derleme zamanında zorunlu, çalışma zamanında **isteğe bağlı**.
- `exports` yansımaya (reflection) **özel erişim vermez** → framework'ler için **`opens`** gerekir.
- `open module` içinde ayrıca `opens` yazmak **derleme hatasıdır**.
- Servis: sağlayıcıda **`provides ... with ...`**, tüketicide **`uses`**; ikisi de olmalı.
- Servis uygulamasının paketi **`exports` edilmek zorunda değildir**; **parametresiz public ctor** gerekir.
- `uses` yoksa `ServiceLoader` **boş döner**, hata vermez.
- Modül adında **tire yasak**; `java.base` **otomatik** gelir.
- Named modüller **classpath'teki (unnamed) kodu göremez**.
- Automatic modül her şeyi **exports** eder ve tüm modülleri **requires** eder.
