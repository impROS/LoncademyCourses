# 8.3 — Thread-Safe Kod: Kilitler, Atomic ve Concurrent Koleksiyonlar

> **Alan:** Managing Concurrent Code Execution — tahmini ~2 soru
> **Süre:** ~35 dakika okuma + 20 dakika pratik
> **Test:** [`8.3-test.html`](8.3-test.html) · 15 soru

## Neden bu konu

Sınav burada iki şeyi ölçer: **hangi araç neyi çözer** (`volatile` görünürlük, `synchronized`
bütünlük, `Atomic` atomiklik) ve **hangi koleksiyon thread-safe**.

En sık tuzak: **`volatile` bir sayacı thread-safe yapmaz.** `sayac++` üç işlemdir
(oku-artır-yaz) ve `volatile` bunları atomik hâle getirmez.

**Büyük fikir:** Eşzamanlılıkta iki ayrı sorun vardır — **görünürlük** (bir thread'in yazdığını
diğeri görüyor mu) ve **atomiklik** (işlem bölünmeden bitiyor mu). `volatile` yalnızca birinciyi,
`synchronized`/`Lock`/`Atomic` ikisini birden çözer.

---

## 1. ⭐⭐ Yarış durumu (race condition)

```java
static int sayac = 0;
// 8 thread, toplam 10.000 artirma
sayac++;                       // OKU + ARTIR + YAZ  -> 3 islem, atomik DEGIL
// sonuc: 9791 gibi bir sayi — 10.000 DEGIL
```

| Araç | Görünürlük | Atomiklik | Not |
|---|---|---|---|
| `volatile` | ✅ | ❌ | Sayaç için **yetmez** |
| `synchronized` | ✅ | ✅ | Kilit maliyeti var |
| `AtomicInteger` | ✅ | ✅ | Kilitsiz (CAS), sayaçlar için ideal |
| `ReentrantLock` | ✅ | ✅ | Esnek: `tryLock`, adalet, kesilebilirlik |

---

## 2. ⭐ `synchronized`

```java
synchronized void m() { }                 // kilit: this
static synchronized void s() { }          // kilit: SinifAdi.class
void b() { synchronized (kilitNesnesi) { } }   // kilit: belirtilen nesne
```

| Kural | Detay |
|---|---|
| Kilit nesnesi | Örnek metotta `this`, statik metotta **`Sinif.class`** |
| Yeniden girişli (reentrant) | ✅ Aynı thread kilidi tekrar alabilir |
| `synchronized` bloklama durumu | Thread durumu **`BLOCKED`** (8.1) |
| Virtual thread ile | **Pinning** riski → `ReentrantLock` tercih edilir (8.1) |

### `wait` / `notify` / `notifyAll`

```java
synchronized (kilit) {
    while (!kosul) kilit.wait();      // kilidi BIRAKIR ve bekler
    // ...
}
synchronized (kilit) { kilit.notifyAll(); }
```

| Kural | Detay |
|---|---|
| Kilit tutulmadan çağrılırsa | **`IllegalMonitorStateException`** |
| `wait()` | Kilidi **bırakır** |
| `sleep()` | Kilidi **bırakmaz** (8.1) |
| `if` yerine `while` | Sahte uyanmalara (spurious wakeup) karşı **`while` şart** |
| `notify` vs `notifyAll` | Biri vs hepsi — genelde `notifyAll` güvenlidir |

## 3. ⭐ `volatile` ve `Atomic`

```java
volatile boolean calisiyor = true;    // gorunurluk: dogru kullanim (bayrak)
volatile int sayac = 0;
sayac++;                              // YANLIS: hala atomik degil
```

```java
AtomicInteger a = new AtomicInteger();
a.incrementAndGet();     // ++a  -> yeni deger
a.getAndIncrement();     // a++  -> ESKI deger
a.addAndGet(5);
a.compareAndSet(5, 10);  // beklenen deger 5 ise 10 yap, boolean doner
a.updateAndGet(x -> x * 2);
a.get();
```

| Sınıf | Ne için |
|---|---|
| `AtomicInteger` / `AtomicLong` | Sayaçlar |
| `AtomicBoolean` | Bayraklar |
| `AtomicReference<T>` | Nesne referansı |
| `LongAdder` | Çok yüksek çekişmede `AtomicLong`'dan hızlı |

> ⚠️ `getAndIncrement` **eski** değeri, `incrementAndGet` **yeni** değeri döner —
> `i++` ile `++i` farkının atomic karşılığı (1.1).

## 4. `Lock` API

```java
Lock kilit = new ReentrantLock();
kilit.lock();
try {
    // kritik bolge
} finally {
    kilit.unlock();          // finally'de olmasi ZORUNLU
}

if (kilit.tryLock()) { try { } finally { kilit.unlock(); } }   // beklemeden dene
kilit.tryLock(1, TimeUnit.SECONDS);                            // sureli dene
kilit.lockInterruptibly();                                     // beklerken kesilebilir
```

| `synchronized` | `ReentrantLock` |
|---|---|
| Otomatik serbest bırakılır | **Elle `unlock()`** gerekir |
| Beklemeden denemek yok | **`tryLock()`** var |
| Süreli bekleme yok | **`tryLock(timeout)`** var |
| Kesilemez | **`lockInterruptibly()`** var |
| Adalet (fairness) yok | `new ReentrantLock(true)` |
| Virtual thread'de **pinning** | Pinning **yok** |

> ⚠️⚠️ **Tuzak:** Kilidi almamış bir thread `unlock()` çağırırsa
> **`IllegalMonitorStateException`** atılır. `unlock` her zaman **`finally`** içinde olmalıdır.

`ReadWriteLock`: çok okuyucu **aynı anda**, tek yazıcı **tek başına**.

## 5. ⭐⭐ Concurrent koleksiyonlar

| Tip | Ne için | Not |
|---|---|---|
| `ConcurrentHashMap` | Thread-safe map | **`null` anahtar/değer yasak** → NPE |
| `ConcurrentSkipListMap` | Sıralı thread-safe map | `TreeMap` karşılığı |
| **`CopyOnWriteArrayList`** | Okuma çok, yazma az | Her yazmada **kopya**; iterasyonda **CME atmaz** |
| `CopyOnWriteArraySet` | Aynı mantık, set | |
| `ConcurrentLinkedQueue` | Kilitsiz kuyruk | |
| `BlockingQueue` (`ArrayBlockingQueue`, `LinkedBlockingQueue`) | Üretici-tüketici | `put`/`take` **bloklar** |

```java
var l = new CopyOnWriteArrayList<>(List.of("a", "b"));
for (String s : l) l.add("x");        // ConcurrentModificationException ATMAZ
                                       // iterator eski KOPYA uzerinde gezer
```

| `BlockingQueue` metodu | Dolu/boşsa |
|---|---|
| `put(e)` / `take()` | **Bloklar** |
| `offer(e)` / `poll()` | `false` / `null` |
| `offer(e, t, unit)` / `poll(t, unit)` | Süreli bekler |
| `add(e)` / `remove()` | **Exception** atar |

> ⚠️ `Collections.synchronizedList(list)` her metodu senkronize eder ama **iterasyon** yine
> elle senkronize edilmelidir; `CopyOnWriteArrayList`'te bu gerekmez.

### Eşzamanlılık sorunları

| Sorun | Ne demek |
|---|---|
| **Deadlock** | İki thread karşılıklı olarak diğerinin kilidini bekler — **hiçbiri ilerlemez** |
| **Livelock** | Thread'ler sürekli tepki verir ama **iş ilerlemez** |
| **Starvation** | Bir thread kaynağa **hiç erişemez** |
| **Race condition** | Sonuç **zamanlamaya** bağlı olarak değişir |

## Sık karıştırılanlar — tek tabloda

| Soruda geçen | Doğru cevap | Neden diğeri değil |
|---|---|---|
| `volatile int` + `++` | **Thread-safe değil** | `volatile` atomiklik vermez |
| `volatile` ne verir | **Görünürlük** | Bütünlük için `synchronized`/`Atomic` |
| `static synchronized` kilidi | **`Sinif.class`** | Örnek metotta `this` |
| Kilitsiz `wait()` | **`IllegalMonitorStateException`** | — |
| `wait` vs `sleep` | `wait` kilidi **bırakır** | `sleep` bırakmaz |
| `wait` çevresinde `if` | **Yanlış** — `while` olmalı | Sahte uyanmalar |
| `getAndIncrement` | **Eski** değer | `incrementAndGet` yeni değer |
| Kilit almadan `unlock()` | **`IllegalMonitorStateException`** | — |
| `unlock` nerede | **`finally`** içinde | — |
| `ConcurrentHashMap` + `null` | **NPE** | `HashMap` kabul eder |
| `CopyOnWriteArrayList` iterasyonda değişim | **CME atmaz** | `ArrayList` atar (2.2) |
| `BlockingQueue.put` | **Bloklar** | `offer` `false` döner |
| Virtual thread + `synchronized` | **Pinning** | `ReentrantLock` kullan |

## Sınavda nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — volatile yetmez**
> `volatile int sayac;` alanına 100 thread `sayac++` yapıyor. Sonuç doğru mu?
> → **Hayır.** `volatile` atomiklik vermez.

**Kalıp 2 — Kilitsiz wait**
> ```java
> Object o = new Object();
> o.wait();
> ```
> → **`IllegalMonitorStateException`**.

**Kalıp 3 — Atomic dönüşü**
> ```java
> AtomicInteger a = new AtomicInteger(5);
> System.out.println(a.getAndIncrement() + " " + a.get());
> ```
> → **`5 6`**.

**Kalıp 4 — ConcurrentHashMap null**
> ```java
> new ConcurrentHashMap<String,String>().put(null, "x");
> ```
> → **`NullPointerException`**.

**Kalıp 5 — CopyOnWriteArrayList**
> Iterasyon sırasında `add` yapılıyor. → **Exception atılmaz**; yeni eleman o iterasyonda **görünmez**.

## 60 saniyelik özet

- `sayac++` **atomik değildir** (oku-artır-yaz). `volatile` bunu **düzeltmez**.
- `volatile` = **görünürlük**; `synchronized` / `Lock` / `Atomic` = **görünürlük + atomiklik**.
- Örnek `synchronized` metot **`this`**'i, statik olan **`Sinif.class`**'ı kilitler.
- `wait`/`notify` **kilit tutarken** çağrılmalı; değilse **`IllegalMonitorStateException`**.
- `wait()` kilidi **bırakır**, `sleep()` **bırakmaz**. `wait` her zaman **`while` döngüsünde**.
- `getAndIncrement` **eski**, `incrementAndGet` **yeni** değeri döner.
- `ReentrantLock`: `unlock()` **`finally`'de**; `tryLock`, `tryLock(timeout)`, `lockInterruptibly` sunar.
- Kilit almadan `unlock()` → **`IllegalMonitorStateException`**.
- `ConcurrentHashMap` **null anahtar/değer kabul etmez**.
- `CopyOnWriteArrayList` iterasyonda **CME atmaz**; iterator **eski kopyayı** gezer.
- `BlockingQueue`: `put`/`take` **bloklar**, `offer`/`poll` özel değer döner, `add`/`remove` **atar**.
- Virtual thread'lerde `synchronized` **pinning** yapar → `ReentrantLock` tercih edilir.
