## Neden bu konu

**Virtual threads Java 21'in bayrak özelliğidir** (JEP 444) ve 1Z0-830'da neredeyse kesin sorulur.
Java 17 kaynaklarında bu konu **yoktur**.

Klasik taraftan ise sınav hep aynı iki şeyi sorar: **`start()` ile `run()` farkı** ve
**thread durumları**.

**Büyük fikir:** Platform thread'i işletim sisteminin thread'idir — **pahalıdır**, bu yüzden
havuzlanır. Virtual thread JVM'in yönettiği hafif bir thread'tir — **ucuzdur**, bu yüzden
**havuzlanmaz**, her görev için yenisi açılır.

## 1. ⭐ Thread oluşturma

```java
// 1) Runnable (tercih edilen klasik yol)
Thread t1 = new Thread(() -> System.out.println("calisti"));
t1.start();

// 2) Thread'i genisletme (tercih edilmez)
class Isci extends Thread { public void run() { } }
new Isci().start();

// 3) Java 21 Builder API
Thread t2 = Thread.ofPlatform().name("islem-1").daemon().start(() -> { });
Thread t3 = Thread.ofVirtual().name("v-1").start(() -> { });
Thread t4 = Thread.ofVirtual().unstarted(() -> { });   // olusturur, BASLATMAZ
Thread t5 = Thread.startVirtualThread(() -> { });      // kisayol
```

### ⭐⭐ `start()` vs `run()`

```java
Thread t = new Thread(() -> System.out.println(Thread.currentThread().getName()));
t.start();     // YENI thread -> "Thread-0"
t.run();       // MEVCUT thread -> "main"   (siradan metot cagrisi!)
```

| Kural | Detay |
|---|---|
| `run()` doğrudan çağrılırsa | **Yeni thread açılmaz**, sıradan metot çağrısıdır |
| İkinci kez `start()` | **`IllegalThreadStateException`** |
| Bir thread yeniden başlatılabilir mi | ❌ Hayır |
| Çalışma sırası | **Garantisiz** — çıktı sırası soruları genelde "tahmin edilemez" ile cevaplanır |

## 2. Thread durumları

| Durum | Ne zaman |
|---|---|
| `NEW` | Oluşturuldu, `start()` çağrılmadı |
| `RUNNABLE` | Çalışıyor veya CPU bekliyor |
| `BLOCKED` | `synchronized` kilidi bekliyor |
| `WAITING` | `join()`, `wait()`, `park()` — süresiz |
| `TIMED_WAITING` | `sleep(n)`, `join(n)`, `wait(n)` |
| `TERMINATED` | Bitti |

```java
Thread.sleep(100);              // TIMED_WAITING; InterruptedException (CHECKED) atar
t.join();                       // t bitene kadar bekler
t.interrupt();                  // kesme bayragini set eder
Thread.currentThread().isInterrupted();
```

> ⚠️ `Thread.sleep` **checked** `InterruptedException` atar → yakala ya da bildir (4.1).
> `sleep` **kilitleri bırakmaz**; `wait()` bırakır (8.3).

### Daemon thread'ler

| | Platform thread | Daemon thread |
|---|---|---|
| Varsayılan | `daemon = false` | — |
| JVM kapanışı | **Bekler** | **Beklemez**, öldürülür |
| Ayarlama | `setDaemon(true)` — **`start()`'tan önce** | |

## 3. ⭐⭐⭐ Virtual thread'ler (Java 21)

```java
Thread v = Thread.ofVirtual().start(() -> System.out.println("hafif"));
v.join();
System.out.println(v.isVirtual());     // true
```

| Özellik | **Platform thread** | **Virtual thread** |
|---|---|---|
| Kim yönetir | İşletim sistemi | **JVM** |
| Maliyet | ~1 MB yığın, pahalı | Çok ucuz — **milyonlarca** açılabilir |
| Havuzlanmalı mı | ✅ Evet (`ExecutorService`) | ❌ **Hayır** — havuzlamak anlamsızdır |
| `isDaemon()` | Varsayılan `false` | **Her zaman `true`** |
| `setDaemon(false)` | ✅ | ❌ **`IllegalArgumentException`** |
| Öncelik (priority) | Etkili | **Yok sayılır** (hep `5` döner) |
| Thread grubu | Ayarlanabilir | Sabit |
| İyi olduğu iş | CPU-yoğun | **I/O bekleyen** (ağ, dosya, DB) |
| `ThreadLocal` | Çalışır | Çalışır ama **önerilmez** (çok sayıda thread) |

### Nasıl çalışır

Virtual thread bir **carrier** (taşıyıcı) platform thread'i üzerinde çalışır. Kod **bloklayıcı**
bir işleme girdiğinde (I/O, `sleep`) JVM virtual thread'i taşıyıcıdan **söker (unmount)** ve
taşıyıcıyı başka bir virtual thread'e verir. Bloklama biterse yeniden **takılır (mount)**.

> ⚠️⚠️ **Pinning:** `synchronized` blok içindeyken bloklanırsa virtual thread taşıyıcıya
> **çivilenir** (pinned) ve taşıyıcı serbest kalmaz — ölçek kaybolur.
> Bu yüzden virtual thread kullanan kodda `synchronized` yerine **`ReentrantLock`** tercih edilir (8.3).

```java
// Java 21'de bir gorev icin bir virtual thread: normaldir
try (var exec = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 10_000; i++) {
        exec.submit(() -> { Thread.sleep(100); return null; });
    }
}   // close() TUM gorevleri bekler (8.2)
```

## Sık karıştırılanlar — tek tabloda

| Soruda geçen | Doğru cevap | Neden diğeri değil |
|---|---|---|
| `t.run()` | **Aynı** thread'de çalışır | `start()` yeni thread açar |
| İkinci `t.start()` | `IllegalThreadStateException` | Thread yeniden kullanılamaz |
| İki thread'in çıktı sırası | **Tahmin edilemez** | — |
| `Thread.sleep` | **Checked** `InterruptedException` | Yakalanmalı |
| `sleep` ve kilitler | Kilitleri **bırakmaz** | `wait()` bırakır |
| Virtual thread `isDaemon()` | **Her zaman `true`** | Değiştirilemez |
| Virtual thread `setDaemon(false)` | **`IllegalArgumentException`** | — |
| Virtual thread önceliği | **Yok sayılır** | Hep 5 |
| Virtual thread'i havuzlamak | **Anlamsız** | Ucuz oldukları için gereksiz |
| Virtual thread + CPU-yoğun iş | **Fayda yok** | I/O için tasarlandı |
| Virtual thread + `synchronized` bloklama | **Pinning** | `ReentrantLock` kullan |
| `Thread.startVirtualThread(r)` | Oluşturur **ve başlatır** | `ofVirtual().unstarted()` başlatmaz |

## Sınavda nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — run() tuzağı**
> ```java
> Thread t = new Thread(() -> System.out.print(Thread.currentThread().getName()));
> t.run();
> ```
> → **`main`**.

**Kalıp 2 — İkinci start**
> ```java
> t.start();
> t.start();
> ```
> → **`IllegalThreadStateException`**.

**Kalıp 3 — Virtual daemon**
> ```java
> Thread v = Thread.ofVirtual().unstarted(() -> {});
> v.setDaemon(false);
> ```
> → **`IllegalArgumentException`**.

**Kalıp 4 — Çıktı sırası**
> İki thread aynı anda yazdırıyor, çıktı sorulur.
> → **Sıra garanti edilemez.**

**Kalıp 5 — Pinning**
> Virtual thread `synchronized` blok içinde bloklanırsa ne olur?
> → Taşıyıcı thread'e **çivilenir**, ölçek kaybolur.

## 60 saniyelik özet

- `start()` **yeni thread** açar; `run()` doğrudan çağrılırsa **mevcut thread'de** çalışır.
- İkinci `start()` → **`IllegalThreadStateException`**; thread yeniden kullanılamaz.
- Çıktı sırası **hiçbir zaman garanti değildir**.
- Durumlar: `NEW`, `RUNNABLE`, `BLOCKED`, `WAITING`, `TIMED_WAITING`, `TERMINATED`.
- `Thread.sleep` **checked** `InterruptedException` atar ve **kilitleri bırakmaz**.
- Daemon thread'ler JVM kapanışını **engellemez**; `setDaemon` **`start()` öncesi** çağrılmalı.
- **Virtual thread'ler her zaman daemon'dır**; `setDaemon(false)` **`IllegalArgumentException`** atar.
- Virtual thread **önceliği yok sayar** ve **havuzlanmaz** — görev başına bir tane açılır.
- `Thread.ofVirtual().start(r)` · `Thread.startVirtualThread(r)` · `ofVirtual().unstarted(r)`.
- Virtual thread'ler **I/O bekleyen** işler içindir; CPU-yoğun işte fayda getirmez.
- `synchronized` içinde bloklanma **pinning** yaratır → **`ReentrantLock`** tercih edilir.
- `Executors.newVirtualThreadPerTaskExecutor()` görev başına bir virtual thread açar.
