# 9.1 — I/O Stream'leri, Konsol ve Serialization

> **Alan:** Using Java I/O API — tahmini ~2 soru
> **Süre:** ~35 dakika okuma + 20 dakika pratik
> **Test:** [`9.1-test.html`](9.1-test.html) · 15 soru

## Neden bu konu

I/O sınıfları kalabalıktır ve sınav **hangi sınıf hangi aileye ait** diye sorar:
`FileReader` mi `FileInputStream` mi, `BufferedReader` tek başına açılabilir mi.

Serialization tarafında ise iki kural her seferinde sorulur: **`transient` alanlar ne olur** ve
**deserialization sırasında constructor çalışır mı**.

**Büyük fikir:** I/O'da iki eksen vardır — **byte mı karakter mi** ve **düşük seviye mi sarmalayıcı mı**.
Dört kutuluk bu tablo, sınıf adlarının hepsini açıklar.

---

## 1. ⭐⭐ Dört kutu: byte/karakter × düşük/yüksek

| | **Byte akışı** | **Karakter akışı** |
|---|---|---|
| **Kök sınıflar** | `InputStream` / `OutputStream` | `Reader` / `Writer` |
| **Düşük seviye (kaynağa bağlanır)** | `FileInputStream`, `FileOutputStream`, `ByteArrayInputStream` | `FileReader`, `FileWriter`, `StringReader` |
| **Yüksek seviye (sarmalar)** | `BufferedInputStream`, `ObjectInputStream`, `PrintStream` | `BufferedReader`, `BufferedWriter`, `PrintWriter` |
| **Köprü** | — | `InputStreamReader`, `OutputStreamWriter` |

```java
// dusuk seviyeyi YUKSEK seviye sarmalar
try (var r = new BufferedReader(new FileReader("a.txt"))) {
    String satir;
    while ((satir = r.readLine()) != null) System.out.println(satir);
}
```

| Kural | Detay |
|---|---|
| Yüksek seviye tek başına | ❌ `new BufferedReader("a.txt")` **derlenmez** — bir `Reader` ister |
| Sıra | Kaynak **içte**, sarmalayıcı **dışta** |
| `read()` dönüşü | **`int`** (byte/char değil); dosya sonunda **`-1`** |
| Kapatma | En **dıştakini** kapatmak yeter; zincir kapanır |
| `Reader`/`Writer` ne zaman | **Metin** için; byte akışı ikili (binary) veri için |

> ⚠️ **Tuzak:** `read()` neden `int` döner? Çünkü `-1` (dosya sonu) ile geçerli `0xFF` baytını
> ayırt edebilmek gerekir. `while ((c = r.read()) != -1)` kalıbı bu yüzdendir.

## 2. Sık kullanılan metotlar

| Sınıf | Metot | Not |
|---|---|---|
| `InputStream` | `read()`, `read(byte[])`, `readAllBytes()`, `transferTo(out)` | |
| `OutputStream` | `write(int)`, `write(byte[])`, `flush()`, `close()` | |
| `Reader` | `read()`, `read(char[])` | |
| `BufferedReader` | **`readLine()`** (sonda `null`), `lines()` → `Stream<String>` | |
| `Writer` | `write(String)`, `append(...)` | |
| `BufferedWriter` | `newLine()` | |
| `PrintWriter` / `PrintStream` | `print`, `println`, `printf`, `format` | **Exception fırlatmaz**, `checkError()` ile bakılır |

```java
try (var w = new PrintWriter(new FileWriter("a.txt"))) {
    w.println("satir");
    w.printf("%s=%d%n", "x", 5);
}
```

> ⚠️ `flush()` çağrılmadan program biterse tamponlanmış veri **kaybolabilir**.
> try-with-resources `close()` çağırdığı için otomatik `flush` olur (4.2).

### Konsol

```java
System.out    // PrintStream
System.err    // PrintStream
System.in     // InputStream

var c = System.console();      // IDE'de genelde NULL doner!
if (c != null) {
    String ad = c.readLine("Ad: ");
    char[] sifre = c.readPassword("Sifre: ");   // ekranda GORUNMEZ
}
```

> ⚠️ **Tuzak:** `System.console()` IDE'den veya yönlendirilmiş girdiyle çalıştırıldığında
> **`null`** döner — sınav "her zaman bir `Console` döner" şıkkını koyar, yanlıştır.

## 3. ⭐⭐⭐ Serialization

```java
class Kisi implements Serializable {          // MARKER arayuz: metot yok
    private static final long serialVersionUID = 1L;
    private String ad;
    private transient String sifre;           // SERILESTIRILMEZ
    private static int sayac;                 // static da serilestirilmez
}
```

```java
try (var out = new ObjectOutputStream(new FileOutputStream("k.ser"))) {
    out.writeObject(kisi);
}
try (var in = new ObjectInputStream(new FileInputStream("k.ser"))) {
    Kisi k = (Kisi) in.readObject();          // ClassNotFoundException (checked) atabilir
}
```

| Kural | Detay |
|---|---|
| `Serializable` | **Marker** arayüz, metodu yok |
| Uygulamayan tip yazılırsa | **`NotSerializableException`** (runtime) |
| `transient` alanlar | **Yazılmaz** — geri okunduğunda **varsayılan değer** (`0`, `null`, `false`) |
| `static` alanlar | **Yazılmaz** — sınıfa aittir, nesneye değil |
| `serialVersionUID` | Yazılmazsa derleyici üretir; sınıf değişirse **`InvalidClassException`** riski |
| Alan tipleri | Tüm **non-transient** alanlar da `Serializable` olmalı |
| `readObject` | **Checked** `ClassNotFoundException` ve `IOException` atar |

### ⭐⭐ Deserialization'da constructor **çalışmaz**

```java
class Ust { int u = 1; Ust() { u = 99; } }               // Serializable DEGIL
class Alt extends Ust implements Serializable { int a = 5; }
```

Geri okunduğunda:

| Ne çalışır | Sonuç |
|---|---|
| `Alt` constructor'ı | ❌ **Çalışmaz** |
| `Alt` alan initializer'ları | ❌ **Çalışmaz** — değerler dosyadan gelir |
| **İlk `Serializable` olmayan üst sınıfın** parametresiz ctor'ı | ✅ **Çalışır** (`Ust()` → `u = 99`) |
| `transient` alanlar | Varsayılan değere döner |

> ⚠️⚠️ Bu yüzden `Serializable` olmayan üst sınıfın **parametresiz constructor'ı olmak zorundadır**;
> yoksa `InvalidClassException` alırsın.

`writeObject` / `readObject` `private` metotlarını tanımlayarak süreci özelleştirebilirsin.

## Sık karıştırılanlar — tek tabloda

| Soruda geçen | Doğru cevap | Neden diğeri değil |
|---|---|---|
| `new BufferedReader("a.txt")` | **Derlenmez** | Bir `Reader` ister |
| `read()` dönüş tipi | **`int`**, sonda `-1` | `byte`/`char` değil |
| `readLine()` sonda | **`null`** | `-1` değil |
| `FileReader` vs `FileInputStream` | Karakter vs **byte** | |
| `PrintWriter` hata durumu | **Exception atmaz** | `checkError()` |
| `System.console()` | **`null` olabilir** | IDE'de genelde null |
| `Serializable` metotları | **Yok** (marker) | |
| `transient` alan geri okunduğunda | **Varsayılan değer** | Kaydedilmemiştir |
| `static` alan | **Serileştirilmez** | Sınıfa ait |
| Deserialization + constructor | **Çalışmaz** | İlk non-serializable üst ctor çalışır |
| `readObject` exception'ı | **Checked** `ClassNotFoundException` | Yakalanmalı |
| `Serializable` olmayan nesne yazmak | **`NotSerializableException`** | Runtime |
| Kapatma | **En dıştaki** yeter | Zincir kapanır |

## Sınavda nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — Sarmalama**
> ```java
> BufferedReader r = new BufferedReader("a.txt");
> ```
> → **Compilation fails.**

**Kalıp 2 — read() dönüşü**
> ```java
> char c;
> while ((c = reader.read()) != -1) { }
> ```
> → **Compilation fails.** `read()` `int` döner.

**Kalıp 3 — transient**
> `transient int x = 5;` serileştirilip geri okunuyor. `x` nedir?
> → **`0`**.

**Kalıp 4 — Constructor**
> Deserialization sırasında sınıfın constructor'ı çalışır mı?
> → **Hayır.** İlk `Serializable` olmayan üst sınıfınki çalışır.

**Kalıp 5 — Serializable olmayan alan**
> `Serializable` bir sınıfın alanı `Serializable` değilse ve `transient` de değilse?
> → Yazarken **`NotSerializableException`**.

## 60 saniyelik özet

- İki aile: **byte** (`InputStream`/`OutputStream`) ve **karakter** (`Reader`/`Writer`).
- Düşük seviye kaynağa bağlanır, yüksek seviye onu **sarmalar**; sarmalayıcı tek başına açılamaz.
- Köprü sınıfları: `InputStreamReader`, `OutputStreamWriter`.
- `read()` **`int`** döner ve sonda **`-1`**; `readLine()` sonda **`null`**.
- En **dıştaki** akışı kapatmak yeter; try-with-resources otomatik `flush` + `close` yapar.
- `PrintWriter`/`PrintStream` **exception atmaz** — `checkError()` ile kontrol edilir.
- `System.console()` **`null` dönebilir** (IDE, yönlendirilmiş girdi).
- `Serializable` bir **marker** arayüzdür; uygulamayan nesne → **`NotSerializableException`**.
- **`transient` ve `static` alanlar serileştirilmez**; `transient` geri okunduğunda **varsayılan** olur.
- Deserialization **constructor çalıştırmaz**; **ilk `Serializable` olmayan üst sınıfın**
  parametresiz ctor'ı çalışır — bu yüzden o ctor **var olmak zorundadır**.
- `readObject` **checked** `ClassNotFoundException` ve `IOException` atar.
- `serialVersionUID` uyuşmazsa **`InvalidClassException`**.
