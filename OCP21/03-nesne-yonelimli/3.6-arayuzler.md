# 3.6 — Arayüzler ve Fonksiyonel Arayüzler

> **Alan:** Using Object-Oriented Concepts in Java — tahmini ~2 soru
> **Süre:** ~35 dakika okuma + 20 dakika pratik
> **Test:** [`3.6-test.html`](3.6-test.html) · 15 soru

---

## Neden bu konu

Arayüzler Java 8 ve 9'da değişti: artık `default`, `static`, `private` ve `private static` metotlar
barındırabiliyorlar. Sınav bu dört tipin **hangisinin kalıtıldığını**, **hangisinin gövde
zorunlu olduğunu** ve **çakışma (diamond) durumunda ne olduğunu** sorar.

İkinci kaynak: **fonksiyonel arayüz** tanımı. "Tam olarak bir abstract metot" kuralının
istisnaları vardır ve bunlar sorulur.

**Büyük fikir:** Arayüzdeki her üyenin **örtük belirteçleri** vardır. Yazmadığın `public`,
`abstract`, `static`, `final` kelimeleri derleyici tarafından eklenir — ve **çelişen** bir belirteç
yazarsan derleme hatası alırsın.

---

## 1. ⭐⭐ Örtük belirteçler

| Üye | Örtük belirteçler | Not |
|---|---|---|
| Metot (gövdesiz) | `public abstract` | `private`/`protected` yazamazsın |
| Alan | `public static final` | **Değer atamak zorunludur** |
| İç sınıf/arayüz/enum/record | `public static` | |

```java
interface I {
    int SABIT = 5;              // public static final int SABIT = 5;
    int SABIT2;                 // DERLENMEZ: deger atanmali
    void m();                   // public abstract void m();
    private void p() { }        // OK (Java 9+) ama GOVDE ZORUNLU
    protected void q();         // DERLENMEZ: protected yasak
    final void r();             // DERLENMEZ: abstract + final celiski
}
```

> ⚠️ **Tuzak:** Uygulayan sınıf metodu **`public`** yazmak zorundadır. Yazmazsan
> "erişim daraltılamaz" kuralı (3.4) devreye girer ve **derlenmez**.

---

## 2. ⭐⭐ Dört metot tipi

| Tip | Gövde | Kalıtılır mı | Nasıl çağrılır | Override edilebilir mi |
|---|---|---|---|---|
| `abstract` (gövdesiz) | ❌ | ✅ | Nesne üzerinden | **Zorunlu** |
| `default` | ✅ **zorunlu** | ✅ | Nesne üzerinden | ✅ İsteğe bağlı |
| `static` | ✅ **zorunlu** | ❌ **Kalıtılmaz** | **`Arayuz.metot()`** | ❌ |
| `private` | ✅ **zorunlu** | ❌ | Yalnızca arayüz içinden | ❌ |
| `private static` | ✅ **zorunlu** | ❌ | Yalnızca arayüz içinden | ❌ |

```java
interface Arac {
    String ad();                                    // abstract
    default String tanit() { return "Arac: " + ad() + kod(); }   // default
    static Arac bos() { return () -> "yok"; }       // static
    private String kod() { return "#" + hash(); }   // private
    private static int hash() { return 42; }        // private static
}

class Araba implements Arac {
    public String ad() { return "araba"; }
}

new Araba().tanit();     // "Arac: araba#42"
Arac.bos();              // static: ARAYUZ uzerinden
// new Araba().bos();    // DERLENMEZ: static metot kalitilmaz
```

> ⚠️⚠️ **Tuzak:** Arayüzün `static` metodu **uygulayan sınıfa geçmez**.
> `Araba.bos()` de **derlenmez** — yalnızca `Arac.bos()` çalışır. (Sınıf kalıtımında statik metotlar
> kalıtılır; arayüzlerde **kalıtılmaz** — bu ayrım sorulur.)

## 3. ⭐ Çakışma kuralları

### Sınıf, arayüzü yener

```java
interface I { default String m() { return "I"; } }
class Ust { public String m() { return "Ust"; } }
class Alt extends Ust implements I { }

new Alt().m();      // "Ust"   <- SINIF kazanir
```

### İki arayüz aynı `default`'u verirse — çözmek **zorundasın**

```java
interface A { default String m() { return "A"; } }
interface B { default String m() { return "B"; } }

class C implements A, B { }                    // DERLENMEZ: inherits unrelated defaults

class D implements A, B {
    public String m() { return A.super.m(); }  // OK: hangisini istedigini SOYLE
}
```

`A.super.m()` sözdizimi **yalnızca doğrudan uygulanan** arayüzler için geçerlidir.

### Daha spesifik arayüz kazanır

```java
interface A { default String m() { return "A"; } }
interface B extends A { default String m() { return "B"; } }
class C implements A, B { }      // OK -> "B"  (B daha spesifik)
```

## 4. ⭐ Fonksiyonel arayüz (SAM)

**Tanım:** Tam olarak **bir** abstract metodu olan arayüz. Lambda ve method reference'ın hedefi olur (6.1).

| Sayılır mı | Üye |
|---|---|
| ✅ **Sayılır** | Tek abstract metot |
| ❌ Sayılmaz | `default`, `static`, `private` metotlar |
| ❌ **Sayılmaz** | `Object`'in public metotlarının yeniden bildirimi (`equals`, `hashCode`, `toString`) |

```java
@FunctionalInterface
interface Karsilastir<T> {
    int karsilastir(T a, T b);                  // tek abstract -> SAM
    boolean equals(Object o);                   // Object'ten -> SAYILMAZ
    default Karsilastir<T> ters() { return (a,b) -> karsilastir(b,a); }
    static <U> Karsilastir<U> dogal() { return null; }
}
```

| `@FunctionalInterface` | Detay |
|---|---|
| Zorunlu mu | ❌ **Hayır** — lambda için annotation gerekmez |
| Ne işe yarar | Kuralı **derleme zamanında** denetletir |
| İki abstract metot varsa | Annotation varsa **derleme hatası**; yoksa sadece lambda hedefi olamaz |

> ⚠️ **Tuzak:** `Comparator` iki abstract metot bildirir gibi görünür (`compare` ve `equals`)
> ama `equals` `Object`'ten geldiği için **sayılmaz** — `Comparator` fonksiyonel bir arayüzdür.

## 5. Arayüz kalıtımı

| Durum | Geçerli mi |
|---|---|
| `interface A extends B, C` | ✅ Çoklu arayüz kalıtımı serbest |
| `interface A extends SomutSinif` | ❌ Arayüz sınıf genişletemez |
| `class A implements B, C` | ✅ |
| Arayüzde constructor | ❌ |
| Arayüzde örnek alanı | ❌ (alanlar `static final`) |
| Arayüz `sealed` olabilir mi | ✅ (3.5) |
| Arayüz `private`/`protected` üst düzey olabilir mi | ❌ |

## Sık karıştırılanlar — tek tabloda

| Soruda geçen | Doğru cevap | Neden diğeri değil |
|---|---|---|
| Arayüzde `int X;` | Derlenmez | Alanlar `final`, değer şart |
| Arayüzde `protected void m();` | Derlenmez | Metotlar örtük `public` |
| Uygulayan sınıfta `void m()` (public'siz) | Derlenmez | Erişim daraltılamaz |
| `private` arayüz metodu gövdesiz | Derlenmez | Gövde zorunlu |
| `sinif.staticArayuzMetodu()` | **Derlenmez** | Arayüz statikleri kalıtılmaz |
| Sınıf metodu vs arayüz `default` | **Sınıf** kazanır | Sınıf her zaman önceliklidir |
| İki arayüzden aynı `default` | **Derlenmez**, override et | `A.super.m()` ile çöz |
| `B extends A`, ikisi de `default` | **B** kazanır | Daha spesifik olan |
| `equals` bildiren arayüz | Hâlâ fonksiyonel olabilir | `Object` metotları sayılmaz |
| `@FunctionalInterface` yok | Lambda **yine** çalışır | Annotation isteğe bağlı |
| Arayüzde constructor | Derlenmez | Arayüz nesne üretmez |
| `interface A extends SomutSinif` | Derlenmez | Yalnızca arayüz genişletir |

## Sınavda nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — Statik kalıtılmaz**
> ```java
> interface I { static void m() {} }
> class C implements I {}
> C.m();
> ```
> → **Compilation fails.** Yalnızca `I.m()` geçerli.

**Kalıp 2 — Sınıf kazanır**
> ```java
> interface I { default String m() { return "I"; } }
> class A { public String m() { return "A"; } }
> class B extends A implements I {}
> new B().m();
> ```
> → **`A`**.

**Kalıp 3 — Diamond**
> ```java
> interface A { default void m() {} }
> interface B { default void m() {} }
> class C implements A, B {}
> ```
> → **Compilation fails.** `C` `m()`'i override etmeli.

**Kalıp 4 — Örtük public**
> ```java
> interface I { void m(); }
> class C implements I { void m() {} }
> ```
> → **Compilation fails.** `public` yazılmalı.

**Kalıp 5 — Fonksiyonel arayüz**
> ```java
> @FunctionalInterface
> interface I { void a(); void b(); }
> ```
> → **Compilation fails.** İki abstract metot.

## 60 saniyelik özet

- Arayüz metotları örtük **`public abstract`**, alanları örtük **`public static final`** (değer şart).
- Uygulayan sınıf metodu **`public`** yazmak zorunda.
- `default`, `static`, `private`, `private static` metotların **gövdesi zorunludur**.
- Arayüzün **`static` metodu kalıtılmaz** — yalnızca `Arayuz.metot()` ile çağrılır.
- `private` arayüz metotları yalnızca **arayüzün kendi içinden** çağrılır.
- Çakışmada **sınıf metodu arayüz `default`'unu yener**.
- İki bağımsız arayüz aynı `default`'u verirse sınıf **override etmek zorundadır**; `A.super.m()` kullanılır.
- Biri diğerini genişletiyorsa **daha spesifik** arayüz kazanır.
- Fonksiyonel arayüz = **tam bir abstract metot**; `default`/`static`/`private` ve `Object` metotları sayılmaz.
- `@FunctionalInterface` **isteğe bağlıdır**, yalnızca kuralı denetletir.
- Arayüz **constructor ve örnek alanı** barındıramaz; arayüz **sınıf genişletemez**.
