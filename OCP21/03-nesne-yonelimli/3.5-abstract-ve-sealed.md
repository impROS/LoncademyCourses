# 3.5 — Abstract Sınıflar ve Sealed Tipler

> **Alan:** Using Object-Oriented Concepts in Java — tahmini ~2 soru
> **Süre:** ~35 dakika okuma + 20 dakika pratik
> **Test:** [`3.5-test.html`](3.5-test.html) · 15 soru

---

## Neden bu konu

`abstract` eski ve bilinen bir konu; sınav buradan **kural ihlali** sorusu çıkarır
(`abstract` + `final` aynı anda olur mu, abstract sınıfın constructor'ı olur mu).

`sealed` ise Java 17'nin yeniliği ve **1Z0-830'un en ayırt edici konularından biri**.
Üç kelime var (`sealed`, `permits`, `non-sealed`), her birinin katı kuralı var ve
`switch` exhaustiveness'ıyla (2.1) doğrudan bağlantılı.

**Büyük fikir:** `abstract` "**bu sınıf tek başına anlamlı değil**" der. `sealed` ise
"**bu tipin alt tipleri şunlardır, başkası olamaz**" der — yani derleyiciye hiyerarşinin
**kapalı** olduğunu söyler ve karşılığında exhaustive `switch` kazandırır.

## 1. ⭐ Abstract sınıflar

| Kural | Detay |
|---|---|
| `new` ile üretilebilir mi | ❌ Hayır (anonim alt sınıfla dolaylı olarak evet — 3.8) |
| Constructor'ı olabilir mi | ✅ **Evet** — alt sınıf `super(...)` ile çağırır |
| Abstract metodu **olmak zorunda mı** | ❌ Hayır, hiç abstract metodu olmayan abstract sınıf geçerlidir |
| Somut metodu olabilir mi | ✅ |
| Alan, statik üye, initializer | ✅ Hepsi serbest |
| `abstract` + `final` | ❌ Çelişki, derleme hatası |
| `abstract` + `private` metot | ❌ Alt sınıf göremez ki uygulasın |
| `abstract` + `static` metot | ❌ Statik metot polimorfik değildir |
| Abstract metodun gövdesi | ❌ `{ }` bile yazılamaz; `;` ile biter |
| Somut alt sınıf | **Tüm** abstract metotları uygulamak zorunda |
| Abstract alt sınıf | Uygulamayabilir, sorumluluğu aşağı devreder |

```java
abstract class Sekil {
    private final String ad;             // alan serbest
    Sekil(String ad) { this.ad = ad; }   // constructor serbest
    abstract double alan();              // govde YOK, noktali virgul
    String tanit() { return ad + " alani=" + alan(); }   // somut metot
}

class Kare extends Sekil {
    private final double k;
    Kare(double k) { super("kare"); this.k = k; }
    @Override double alan() { return k * k; }
}
```

> ⚠️ **Tuzak:** `abstract void m() { }` — boş gövde bile **derleme hatasıdır**
> (*abstract methods cannot have a body*).

## 2. ⭐⭐⭐ Sealed tipler (Java 17+)

```java
public sealed interface Sekil permits Daire, Kare, Ucgen { }

public record Daire(double r) implements Sekil { }
public record Kare(double kenar) implements Sekil { }
public non-sealed class Ucgen implements Sekil { }
```

### Kurallar

| Kural | Detay |
|---|---|
| Nerede kullanılır | `class` ve `interface` üzerinde |
| `permits` listesi | İzin verilen **doğrudan** alt tipler |
| `permits` zorunlu mu | Alt tipler **aynı dosyadaysa** yazmasan da olur; ayrı dosyadaysa **zorunlu** |
| Alt tipler nerede olmalı | **Aynı paket** (adsız modülde) veya **aynı modül** |
| İzin verilen her alt tip | `final`, `sealed` veya **`non-sealed`** olmak **zorunda** |
| `permits`'te olup gerçekten extend etmeyen tip | ❌ Derleme hatası |
| Listede olmayan bir tip extend ederse | ❌ Derleme hatası |
| `record` alt tip | ✅ Zaten **implicitly final**, ek belirteç gerekmez |
| `abstract sealed` | ✅ Geçerli kombinasyon |
| `sealed` + `final` | ❌ Çelişki |
| `non-sealed` | Java'nın **tek tireli anahtar kelimesi**; zinciri yeniden açar |

### Üç kapanış seçeneği

Bir `sealed` tipin her alt tipi şu üçünden birini seçmek **zorundadır**:

| Belirteç | Anlamı |
|---|---|
| `final` | Zincir burada **biter** |
| `sealed` | Zincir **kontrollü** devam eder (kendi `permits`'i olur) |
| `non-sealed` | Zincir **serbestçe** açılır — herkes bunu genişletebilir |

> ⚠️⚠️ **Tuzak:** Üçünden hiçbirini yazmazsan **derleme hatası** alırsın:
> *sealed, non-sealed or final modifiers expected*. Sınav bunu çok sorar.

## 3. ⭐ Sealed'ın asıl kazancı: exhaustive switch

Derleyici alt tiplerin **tamamını** bildiği için `default` istemez:

```java
static double alan(Sekil s) {
    return switch (s) {
        case Daire d -> Math.PI * d.r() * d.r();
        case Kare k  -> k.kenar() * k.kenar();
        case Ucgen u -> u.alan();
        // default GEREKMEZ
    };
}
```

Hiyerarşiye yeni bir alt tip eklersen bu `switch` **derlenmez** ve derleyici sana söyler.
`default` yazsaydın **sessizce yanlış** çalışırdı — bu yüzden sealed hiyerarşide `default` yazmamak
bilinçli bir tercihtir.

> ⚠️ **`MatchException`:** `switch`'i derledikten **sonra** sealed hiyerarşiyi değiştirip yalnızca
> hiyerarşiyi yeniden derlersen, çalışma zamanında hiçbir dal eşleşmeyebilir → **`MatchException`**.

## 4. Abstract mı, interface mi, sealed mi?

| | **abstract class** | **interface** | **sealed** |
|---|---|---|---|
| Amaç | Ortak **durum + davranış** | Ortak **sözleşme** | **Kapalı** hiyerarşi |
| Alan | Her tür | Yalnızca `public static final` | Uygulandığı tipe bağlı |
| Constructor | ✅ | ❌ | Uygulandığı tipe bağlı |
| Çoklu | Tek `extends` | Çoklu `implements` | Her ikisiyle birleşir |
| Durum tutar mı | ✅ | ❌ | — |
| Exhaustive switch | ❌ | ❌ | ✅ |

**Seçim kuralı:** Ortak **durum** varsa `abstract class`; yalnızca **davranış sözleşmesi** varsa
`interface`; alt tip kümesi **bilinen ve kapalıysa** üzerine `sealed`.

| Abstract metodu olmayan abstract sınıf | ✅ Geçerli | Zorunluluk yok |
| `abstract void m() { }` | Derlenmez | Gövde yasak |

## Sınavda nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — Eksik belirteç**
> ```java
> sealed interface S permits A {}
> class A implements S {}
> ```
> → **Compilation fails.** `A` `final`, `sealed` veya `non-sealed` olmalı.

**Kalıp 2 — Record alt tip**
> ```java
> sealed interface S permits A {}
> record A() implements S {}
> ```
> → ✅ **Derlenir.** Record zaten implicitly final.

**Kalıp 3 — Abstract gövde**
> ```java
> abstract class A { abstract void m() {} }
> ```
> → **Compilation fails.** Abstract metodun gövdesi olamaz.

**Kalıp 4 — Abstract constructor**
> ```java
> abstract class A { A() { System.out.print("A"); } }
> class B extends A { }
> new B();
> ```
> → **`A`** yazılır. Abstract sınıfın constructor'ı çalışır.

**Kalıp 5 — Exhaustive switch**
> `sealed` arayüzün üç alt tipi var, `switch` üçünü de kapsıyor, `default` yok.
> → ✅ **Derlenir.** `default` gerekmez.

## 60 saniyelik özet

- `abstract` sınıf `new` edilemez ama **constructor'ı olabilir** ve alt sınıf onu çağırır.
- Abstract metodun **gövdesi olamaz**; `private`, `static` veya `final` olamaz.
- Abstract metodu olmayan bir abstract sınıf **geçerlidir**.
- Somut alt sınıf **tüm** abstract metotları uygulamalı; abstract alt sınıf devredebilir.
- `sealed` tipin izin verilen alt tipleri **aynı paket veya modülde** olmalı.
- Her alt tip **`final`**, **`sealed`** veya **`non-sealed`** olmak **zorunda** — yoksa derlenmez.
- `record` alt tipler zaten `final`; ek belirteç istemez.
- `permits`, alt tipler **aynı dosyadaysa** yazılmayabilir.
- `non-sealed`, Java'nın **tek tireli anahtar kelimesidir** ve zinciri yeniden açar.
- Sealed hiyerarşide `switch` **exhaustive** sayılır → `default` gerekmez, gereksizce yazma.
- Hiyerarşi derleme sonrası değişirse çalışma zamanında **`MatchException`** gelebilir.
- `abstract sealed` geçerli; `abstract final` ve `sealed final` **çelişkidir**.
