## Neden bu konu

Bu, OOP alanının en çok soru üreten konusu. Sınav iki şeyi test eder:
**(1)** bir metodun override edilip edilmediğini anlıyor musun, **(2)** hangi sürümün çalışacağını
bilebiliyor musun.

En sinsi tuzak: **alanlar override edilmez, gizlenir (hiding)** ve gizlenen alana erişim
**referans tipine** göre yapılır. Metotlarda ise **nesne tipine** göre. Aynı kodda ikisi yan yana
verilir ve iki farklı kural aynı anda işler.

**Büyük fikir:** **Metotlar nesneye, alanlar ve statikler referansa bağlıdır.**
Bu tek cümle bu konudaki soruların yarısını çözer.

## 2. ⭐⭐ Override kuralları — beş şart

Bir metodun **override** sayılması için:

| # | Şart | İhlali |
|---|---|---|
| 1 | **Aynı imza** (ad + parametre tipleri) | Farklıysa **overload** olur, override değil |
| 2 | Dönüş tipi **aynı veya alt tip** (covariant) | Üst tip döndürmek → derleme hatası |
| 3 | Erişim **daraltılamaz** | `public` → `protected` → derleme hatası |
| 4 | **Checked** exception genişletilemez | Yeni/daha geniş checked exception → hata. Unchecked serbest |
| 5 | Üst metot `final`, `static` veya `private` **olmamalı** | `final` override edilemez |

```java
class Ust {
    public Object f() throws IOException { return null; }
}
class Alt extends Ust {
    @Override public String f() { return ""; }        // OK: covariant + daha az exception
}
```

```java
class Ust { public void g() {} }
class Alt extends Ust {
    @Override protected void g() {}                   // DERLENMEZ: erisim daraltildi
}
```

> ⚠️ **Tuzak:** `@Override` **zorunlu değildir** ama yazdığında derleyici kuralı denetler.
> Sınavda `@Override` yokken de override gerçekleşir — annotation'ın varlığına bakma, **imzaya bak**.

### Erişim genişletme yönü

`private` → *(paket)* → `protected` → `public`. Alt sınıf **aynı seviyede veya daha açık** olabilir.

## 3. ⭐⭐⭐ Override mi, hiding mi, overload mu?

| Durum | Adı | Hangi sürüm çalışır |
|---|---|---|
| Örnek metot, aynı imza | **Override** | **Nesnenin** tipine göre (dinamik) |
| **Statik** metot, aynı imza | **Hiding** | **Referansın** tipine göre (statik) |
| **Alan**, aynı isim | **Hiding** | **Referansın** tipine göre (statik) |
| Farklı imza | **Overload** | Derleme zamanında seçilir |
| `private` metot, aynı imza | Alt sınıfta **yeni metot** | İlişki yok |

```java
class Ust {
    String ad = "ust";
    static String s() { return "ust-static"; }
    String i()        { return "ust-instance"; }
}
class Alt extends Ust {
    String ad = "alt";
    static String s() { return "alt-static"; }
    String i()        { return "alt-instance"; }
}

Ust u = new Alt();
u.ad;      // "ust"           <- ALAN: referans tipi
u.s();     // "ust-static"    <- STATIK: referans tipi
u.i();     // "alt-instance"  <- ORNEK METOT: nesne tipi
```

> ⚠️⚠️ **Bu üç satır sınavın klasiğidir.** Ezberle: **metot nesneye, alan ve statik referansa.**

## 4. Polimorfizm ve cast

### Yukarı çevrim (upcast) — otomatik

```java
Ust u = new Alt();          // her Alt bir Ust'tur
Object o = new Alt();
```

Referans tipi **neyi çağırabileceğini** belirler:

```java
Ust u = new Alt();
u.altaOzelMetot();          // DERLENMEZ: Ust'te boyle bir metot yok
((Alt) u).altaOzelMetot();  // OK
```

### Aşağı çevrim (downcast) — açık cast şart

| Durum | Sonuç |
|---|---|
| Nesne gerçekten alt tip | ✅ Çalışır |
| Nesne alt tip **değil** | ❌ **`ClassCastException`** (runtime) |
| Tipler **hiç ilişkili değil** | ❌ **Derleme hatası** (`inconvertible types`) |
| `null` cast'i | ✅ Her zaman geçerli, exception atmaz |

```java
Object o = "metin";
Integer i = (Integer) o;        // RUNTIME: ClassCastException
String s = (String) null;       // OK
Integer x = (Integer) "abc";    // DERLENMEZ: iliskisiz tipler
```

Güvenli yol — `instanceof` pattern (2.1):

```java
if (o instanceof Alt a) { a.altaOzelMetot(); }
```

`instanceof` `null` için **her zaman `false`** döner — NPE atmaz.

## 5. `Object` metotları: equals, hashCode, toString

| Metot | Varsayılan davranış | Sözleşme |
|---|---|---|
| `equals(Object)` | Referans karşılaştırır (`==`) | Yansımalı, simetrik, geçişli, tutarlı; `x.equals(null)` → `false` |
| `hashCode()` | Nesneye özgü sayı | **`equals` eşitse `hashCode` da eşit olmalı** (tersi şart değil) |
| `toString()` | `SinifAdi@hexHash` | — |

```java
class Nokta {
    int x;
    @Override public boolean equals(Object o) {          // imza TAM boyle olmali
        return o instanceof Nokta n && n.x == x;
    }
    @Override public int hashCode() { return x; }
}
```

> ⚠️⚠️ **Tuzak:** `public boolean equals(Nokta n)` yazarsan bu **override değil, overload**'dur.
> `HashSet`/`HashMap` `Object` parametreli sürümü çağırdığı için beklediğin davranışı **görmezsin**.
> `@Override` yazsaydın derleyici uyarırdı — bu yüzden yazılır.

> `equals`'ı override edip `hashCode`'u etmezsen `HashSet`'te aynı değere sahip iki nesne
> **ayrı elemanlar** olarak durur. Record'lar bu sorunu otomatik çözer (3.3).

| Soruda geçen | Doğru cevap | Neden diğeri değil |
|---|---|---|
| `Ust u = new Alt(); u.alan` | **Üst** sınıfın alanı | Alanlar gizlenir, override edilmez |
| `Ust u = new Alt(); u.ornekMetot()` | **Alt** sınıfın metodu | Dinamik bağlama |
| `Ust u = new Alt(); u.statikMetot()` | **Üst** sınıfın metodu | Statik hiding, referans tipi |
| Alt sınıfta erişim daraltma | Derlenmez | Yalnızca genişletilebilir |
| Alt sınıfta üst tip döndürme | Derlenmez | Covariant yalnızca **alt** tipe |
| Alt sınıfta yeni checked exception | Derlenmez | Unchecked serbest |
| `final` metodu override | Derlenmez | — |
| `private` metodu "override" | Yeni metot olur | Kalıtılmaz, ilişki yok |
| `@Override` yok | Yine de override olur | Annotation isteğe bağlı |
| `equals(Nokta)` | **Overload**, override değil | Parametre `Object` olmalı |
| İlişkisiz tipe cast | **Derleme hatası** | İlişkili ama yanlış tipse runtime |
| `null instanceof X` | `false` | NPE atmaz |
| `(String) null` | Geçerli | Cast null'ı bozmaz |

## Sınavda nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — Üçlü klasik**
> ```java
> Ust u = new Alt();
> System.out.println(u.ad + " " + u.s() + " " + u.i());
> ```
> → **Üst alan, üst statik, alt örnek metot.**

**Kalıp 2 — Erişim daraltma**
> ```java
> class A { public void m() {} }
> class B extends A { void m() {} }
> ```
> → **Compilation fails.** Paket-özel, `public`'ten dardır.

**Kalıp 3 — Covariant dönüş**
> ```java
> class A { Object m() { return null; } }
> class B extends A { String m() { return ""; } }
> ```
> → ✅ **Derlenir.** `String`, `Object`'in alt tipi.

**Kalıp 4 — ClassCastException**
> ```java
> Object o = Integer.valueOf(5);
> String s = (String) o;
> ```
> → **Runtime `ClassCastException`.** `Object` üzerinden cast derlenir.

**Kalıp 5 — equals imzası**
> ```java
> class P { public boolean equals(P p) { return true; } }
> System.out.println(new P().equals(new P()));
> ```
> → **`true`** (overload çalışır) ama `Set` içinde beklenen davranışı vermez.

## 60 saniyelik özet

- **Metotlar nesneye, alanlar ve statik metotlar referansa** bağlıdır. Bu tek cümle çok soru çözer.
- Override şartları: aynı imza · **covariant** dönüş · erişim **daraltılamaz** · checked exception
  **genişletilemez** · üst metot `final`/`static`/`private` olamaz.
- Statik metotta aynı imza → **hiding**; alanlarda aynı isim → **hiding**.
- `private` metot kalıtılmaz; alt sınıftaki aynı isimli metot **yeni bir metottur**.
- `@Override` isteğe bağlıdır ama kuralı **derleme zamanında** denetletir.
- Upcast otomatik, downcast açık cast ister; yanlış tip → **`ClassCastException`**, ilişkisiz tip →
  **derleme hatası**.
- `null` cast'i geçerli, `null instanceof X` → **`false`**.
- Referans tipi **neyi çağırabileceğini**, nesne tipi **hangi gövdenin çalışacağını** belirler.
- `equals` imzası **`equals(Object)`** olmalı; `equals(Tip)` yazmak overload'dur.
- `equals` override edildiyse `hashCode` da edilmeli.
- `super.super` **yoktur**; constructor'lar kalıtılmaz.
