# 5.1 — Test piramidi ve slice test'ler

> **Alan:** Test temelleri
> **Süre:** ~30 dakika okuma + 20 dakika pratik
> **Test:** [`5.1-test.html`](5.1-test.html) · 14 soru

---

## Neden bu konu

Spring test yazmak kolaydır. `@SpringBootTest` yazarsın, her şey çalışır. Sorun altı ay
sonra çıkar:

> "Testler 11 dakika sürüyor. Kimse çalıştırmıyor artık."

Test paketi yavaşladığında insanlar onu çalıştırmayı bırakır; çalıştırılmayan test,
olmayan testtir. Yani bu bir hız konusu değil, **testin var olup olmadığı** konusudur.

**Büyük fikir:** Her test bütün uygulamayı ayağa kaldırmak zorunda değil. Spring,
container'ın **yalnızca ilgili dilimini** kuran slice test (yalnızca tek bir katmanı ayağa
kaldıran test) anotasyonları sunar — ve fark ölçülebilir.

---

## 1. Ölçüm: aynı uç nokta, iki test ⭐

Aynı uç noktayı iki farklı biçimde test ettim. Gerçek sonuçlar:

```
Tests run: 1 ... Time elapsed: 0.174 s -- in SliceTest      (@WebMvcTest)
Tests run: 1 ... Time elapsed: 1.083 s -- in FullContextTest        (@SpringBootTest)
```

**Yaklaşık 6,5 kat.** Tek testte 1 saniye önemsiz; 300 testlik bir pakette dakikalar.

Ama asıl fark hızda değil. İki test **farklı sonuç** döndürdü:

| | `SliceTest` | `FullContextTest` |
|---|---|---|
| Anotasyon | `@WebMvcTest(SiparisKontrolcusu.class)` | `@SpringBootTest` + `@AutoConfigureMockMvc` |
| Container'da ne var | Yalnızca web katmanı + belirtilen kontrolcü | **Her şey** |
| `SiparisServisi` | `@MockitoBean` ile **mock** | **Gerçek** |
| Yanıt | `MOCK` | `GERCEK-A-1` |
| Süre | **0,174 sn** | 1,083 sn |

⭐ **İkisi farklı şeyler ölçüyor:** Slice test "kontrolcü, servisten gelen cevabı doğru
biçimde HTTP'ye çeviriyor mu?" diye sorar. Tam test "bütün parçalar birbirine bağlandığında
çalışıyor mu?" diye sorar. İkisi de gerekli — ama **aynı oranda değil.**

## 2. Test piramidi

```
        ╱╲          Uçtan uca / tam container testleri — AZ (birkaç tane)
       ╱  ╲         @SpringBootTest
      ╱────╲
     ╱      ╲       Slice test'ler — ORTA
    ╱        ╲      @WebMvcTest, @DataJpaTest, @JsonTest
   ╱──────────╲
  ╱            ╲    Saf birim testleri — ÇOK
 ╱______________╲   Spring hiç yok, sadece new
```

| Katman | Ne ölçer | Hızı | Kaç tane |
|---|---|---|---|
| **Birim** | Tek sınıfın mantığı | Milisaniye | Yüzlerce |
| **Slice** | Bir katmanın davranışı | ~0,2 sn | Onlarca |
| **Tam container** | Parçaların birleşimi | ~1 sn+ | Birkaç tane |

En alt katmanı unutma: Spring **hiç** gerekmeyen testler.

```java
class SiparisHesaplayiciTest {
    @Test
    void indirim_yuzde_on() {
        var h = new SiparisHesaplayici();                 // sadece new
        assertThat(h.indirimliTutar(10_000, 10)).isEqualTo(9_000);
    }
}
```

⭐ **İş mantığını Spring'e bağımlı olmayan sınıflara koyarsan**, en hızlı testleri
yazabilirsin. "Testim yavaş" şikâyetinin en sık çözümü, test aracını değiştirmek değil,
**mantığı Spring'den ayırmaktır.**

---

## 3. Slice anotasyonları

| Anotasyon | Container'a ne koyar |
|---|---|
| `@WebMvcTest` | Kontrolcüler, `@ControllerAdvice`, dönüştürücüler, filtreler — **`@Service` ve `@Repository` YOK** |
| `@DataJpaTest` | JPA depoları, `EntityManager`, gömülü veritabanı — **201'de** |
| `@JsonTest` | JSON dönüştürücüler |
| `@RestClientTest` | `RestClient` / `RestTemplate` ve mock sunucusu |
| `@JdbcTest` | `JdbcTemplate` ve veri kaynağı |

⚠️ **`@WebMvcTest` `@Service` sınıflarını container'a almaz.** Bu bir eksiklik değil,
tasarımdır: kontrolcünün bağımlılıklarını **sen** mock'larsın, böylece test yalnızca web
katmanını ölçer.

Bu yüzden [2.1](../02-anotasyon-haritasi/2.1-stereotype.md)'deki kural burada karşılığını
buluyor: **kontrolcüne `@Component` yazarsan `@WebMvcTest` onu bulmaz** — slice yalnızca
`@Controller` ailesini alır.

⚠️ **Slice anotasyonları birleştirilemez.** Aynı sınıfa hem `@WebMvcTest` hem `@DataJpaTest`
yazamazsın. İkisine birden ihtiyacın varsa, muhtemelen aslında iki ayrı teste ihtiyacın var.

## 4. Slice test yazmak

```java
package tr.loncademy.siparis;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.webmvc.test.autoconfigure.WebMvcTest;
import org.springframework.test.context.bean.override.mockito.MockitoBean;
import org.springframework.test.web.servlet.assertj.MockMvcTester;

import static org.assertj.core.api.Assertions.assertThat;
import static org.mockito.BDDMockito.given;

@WebMvcTest(SiparisKontrolcusu.class)
class SliceTest {

    @Autowired MockMvcTester mvc;          // istek atan araç
    @MockitoBean SiparisServisi servis;    // container'a mock servis koy

    @Test
    void mock_servis_ile_calisir() {
        given(servis.durum("A-1")).willReturn("MOCK");

        assertThat(mvc.get().uri("/siparisler/durum/A-1"))
                .hasStatusOk()
                .hasBodyTextEqualTo("MOCK");
    }
}
```

⚠️ **Paket adlarına dikkat** — Spring Boot 4'te ikisi de değişti
([2.4](../02-anotasyon-haritasi/2.4-starterlar.md)):

| Ne | Spring Boot 4 paketi |
|---|---|
| `@WebMvcTest` | `org.springframework.boot.webmvc.test.autoconfigure` |
| `@AutoConfigureMockMvc` | `org.springframework.boot.webmvc.test.autoconfigure` |

Spring Boot 3'te ikincisi `org.springframework.boot.test.autoconfigure.web.servlet` idi.
İnternetteki her örnek eski paketi kullanıyor ve `package ... does not exist` hatası
alırsın. `@MockitoBean` ve `MockMvcTester` [5.2](5.2-mockitobean.md)'nin konusu.

## 5. Tam container testi ⭐

```java
@SpringBootTest
@AutoConfigureMockMvc                 // ← Spring Boot 4'te ZORUNLU
class FullContextTest {
    @Autowired MockMvcTester mvc;

    @Test
    void gercek_servis_ile_calisir() {
        assertThat(mvc.get().uri("/siparisler/durum/A-1"))
                .hasStatusOk()
                .hasBodyTextEqualTo("GERCEK-A-1");      // gerçek servisin cevabı
    }
}
```

⭐ **Spring Boot 4'ün en çok takılınan test değişikliği burada:**

> Spring Boot 3'te `@SpringBootTest` yazınca MockMvc kendiliğinden gelirdi.
> **Spring Boot 4'te gelmiyor** — `@AutoConfigureMockMvc` yazman gerekiyor.

Aynısı `TestRestTemplate` için de geçerli: `@AutoConfigureTestRestTemplate` yazacaksın ve
sınıfın paketi de değişti (`org.springframework.boot.resttestclient`).

### `@SpringBootTest` ne zaman

| Kullan | Kullanma |
|---|---|
| Birkaç kritik akışın uçtan uca çalıştığını doğrulamak | Her kontrolcü için |
| Yapılandırmanın gerçekten yüklendiğini görmek | İş mantığı testi için |
| Bean bağlantılarının kurulduğunu doğrulamak | Hızlı geri bildirim istediğin yerde |

## 6. Context cache: neden bazı testler yavaş ⭐

Spring, aynı yapılandırmaya sahip testler için container'ı **bir kere kurar ve yeniden
kullanır** — buna context cache (kurulmuş container'ların yeniden kullanılması) denir. Bu
yüzden 50 `@SpringBootTest` sınıfı 50 container kurmaz, bir tane kurar.

**Ama** yapılandırmayı değiştiren her şey yeni bir container demektir:

| Bunu yazarsan | Sonuç |
|---|---|
| `@ActiveProfiles("test")` | O profil için **ayrı** container |
| `@TestPropertySource(properties = "x=1")` | Ayrı container |
| Farklı `@MockitoBean` kümesi | Ayrı container |
| `@DirtiesContext` | Container **atılır**, bir dahakine yeniden kurulur |

> 📌 **Sık yapılan hata:** Testler arası sızıntıyı `@DirtiesContext` ile çözmeye çalışmak.
> Her kullanımı bir container kurulumu demektir; 20 yere yazarsan test paketin dakikalarca
> uzar. Asıl sorun genelde **paylaşılan durumdur**
> ([1.5](../01-container-ve-bean/1.5-scope.md)) — onu düzelt.

**Ezberle:** Aynı yapılandırma = aynı container = hızlı.
**Tanı, yeter:** `@DirtiesContext`'in maliyeti.
**Girme:** Context cache anahtarı nasıl hesaplanıyor — gerektiğinde bakarsın.

## 7. Yanlış hâlleri

### ❌ Hata 1 — her şeye `@SpringBootTest`

```java
@SpringBootTest
class SiparisHesaplayiciTest {
    @Autowired SiparisHesaplayici hesaplayici;

    @Test
    void indirim() {
        assertThat(hesaplayici.indirimliTutar(10_000, 10)).isEqualTo(9_000);
    }
}
```

Saf bir hesaplama için bütün container ayağa kalkıyor.
✅ **Doğrusu:** `new SiparisHesaplayici()` — Spring'e hiç gerek yok, milisaniyede biter.

### ❌ Hata 2 — Türkçe test sınıfı adı

```java
class SiparisKontrolcusuTesti { ... }        // ← "Testi", "Test" değil
```

Bu, ölçerken kendi başıma geldi. Maven Surefire yalnızca şu kalıplara uyan sınıfları
çalıştırır: **`*Test`, `Test*`, `*Tests`, `*TestCase`**. `...Testi` hiçbirine uymaz.

```
[INFO] --- surefire:3.5.6:test ---
[INFO] BUILD SUCCESS
```

**Test hiç çalışmadı, ama derleme başarılı.** Yeşil bir yapı görürsün, testin yoktur.

✅ **Doğrusu:** Sınıf adını `SiparisKontrolcusuTest` yap. Metot adları Türkçe olabilir —
sınıf adı kalıba uymak zorunda.

📌 Bu, kursun en sinsi hatası: **başarısız olmayan, hiç çalışmayan test.**

### ❌ Hata 3 — Boot 4'te `@AutoConfigureMockMvc` unutmak

```java
@SpringBootTest                       // ← @AutoConfigureMockMvc yok
class FullContextTest {
    @Autowired MockMvcTester mvc;     // inject edilemez
}
```

```
No qualifying bean of type 'MockMvcTester' available
```

✅ **Doğrusu:** `@AutoConfigureMockMvc` ekle.

## Sık karıştırılanlar — tek tabloda

| Karışan | Doğrusu | Neden diğeri değil |
|---|---|---|
| `@WebMvcTest` / `@SpringBootTest` | Slice / tam container | Slice `@Service`'i **almaz**; sen mock'larsın |
| Slice test daha az değerli | **Farklı şey ölçer** | "Kontrolcü doğru çeviriyor mu" ile "hepsi bağlanıyor mu" ayrı sorular |
| `@SpringBootTest` MockMvc getirir | **Boot 4'te getirmez** | `@AutoConfigureMockMvc` yazman gerekir |
| `...Testi` adı çalışır | **Çalışmaz** | Surefire kalıbı: `*Test`, `Test*`, `*Tests`, `*TestCase` |
| Yavaş test = araç sorunu | Genelde **tasarım sorunu** | Mantığı Spring'den ayır, birim testle |
| `@DirtiesContext` güvenli çözüm | **Pahalı** | Her kullanımı yeni bir container kurulumu |
| Slice anotasyonları birleşir | **Birleşmez** | İki slice gerekiyorsa iki test gerekiyordur |

## 🖥 Pratik — iki testi yaz, süreleri karşılaştır

> **Amaç:** Slice test ile tam testin hız ve kapsam farkını ölçmek · **Süre:** 20 dk
> **💸 Maliyet:** Yok

### Adım 1 — Test edilecek kodu hazırla

`SiparisServisi`'ne bir metot ekle:

```java
@Service
public class SiparisServisi {
    public String durum(String no) { return "GERCEK-" + no; }
}
```

Kontrolcüye bir uç nokta ekle (servisi constructor'dan al):

```java
@GetMapping("/durum/{no}")
public String durum(@PathVariable String no) { return servis.durum(no); }
```

### Adım 2 — Slice test

`src/test/java/tr/loncademy/siparis/SliceTest.java` — 4. bölümdeki kodu yaz.

### Adım 3 — Tam test

`src/test/java/tr/loncademy/siparis/FullContextTest.java` — 5. bölümdeki kodu yaz.

### Adım 4 — Çalıştır ve ölç

```bash
./mvnw test
```

- [ ] **Kontrol:** İki test de geçti.

## Nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — "Testler 11 dakika sürüyor"**
> Her şey `@SpringBootTest`. Piramidi kur: birim → slice → tam.

**Kalıp 2 — `No qualifying bean of type 'MockMvcTester'`**
> Boot 4'te `@AutoConfigureMockMvc` eksik.

**Kalıp 3 — "Test yazdım ama çalışmıyor, hata da vermiyor"**

> Slice `@Service` almaz. `@MockitoBean` ile mock'la.

**Kalıp 5 — "Testler tek tek geçiyor, birlikte kalıyor"**
> Paylaşılan durum var. `@DirtiesContext` yerine kaynağı düzelt.

## 60 saniyelik özet

- Yavaş test paketi = **çalıştırılmayan** test paketi. Bu bir hız değil, varlık sorunu.
- Ölçüldü: `@WebMvcTest` **0,174 sn**, `@SpringBootTest` **1,083 sn** — ~6,5 kat.
- Piramit: çok **birim** (Spring yok) → orta **slice** → az **tam container**.
- En büyük kazanç: **iş mantığını Spring'den ayır**, `new` ile test et.
- `@WebMvcTest` **`@Service` almaz** — bağımlılıkları sen mock'larsın. Slice'lar birleştirilemez.
- ⭐ **Spring Boot 4'te `@SpringBootTest` MockMvc getirmez** — `@AutoConfigureMockMvc` yaz.
- Paketler değişti: `@WebMvcTest` ve `@AutoConfigureMockMvc` →
  `org.springframework.boot.webmvc.test.autoconfigure`.
- Aynı yapılandırma = **aynı container** (context cache). `@ActiveProfiles`,
  `@TestPropertySource`, `@DirtiesContext` yeni container demektir.
- ⚠️ Test sınıfı adı **`*Test` / `Test* `/ `*Tests` / `*TestCase`** olmalı — `...Testi`
  **sessizce hiç çalışmaz.**
