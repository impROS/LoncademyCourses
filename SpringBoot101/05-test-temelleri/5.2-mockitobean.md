# 5.2 — @MockitoBean ve Spring Boot 4 test değişiklikleri

> **Alan:** Test temelleri — kursun son konusu
> **Süre:** ~30 dakika okuma + 20 dakika pratik
> **Test:** [`5.2-test.html`](5.2-test.html) · 14 soru

---

## Neden bu konu

Spring Boot 4'e geçen bir projede **en çok kırılan yer testlerdir.** Ana kodun çoğu
çalışmaya devam eder; testler ise toplu hâlde derlenmez.

Sebebi tek bir kötü karar değil: Spring ekibi test anotasyonlarında yıllardır biriken
tutarsızlıkları temizledi. Sonuç daha iyi bir API — ama geçiş sırasında ekranı kırmızıya
boyayan bir liste.

Bu konuyu bitirdiğinde hem yeni yazımı bileceksin, hem de bir hata mesajına bakıp
"bu bir Spring Boot 4 geçiş hatası" diyebileceksin.

**Büyük fikir:** Mock bean (gerçeğinin yerine geçen, davranışını sen belirlediğin taklit
nesne), container'daki gerçek bean'in **yerine geçer**. Spring Boot 4'te adı `@MockitoBean`
oldu ve kimin sorumluluğunda olduğu netleşti.

---

## 1. `@MockitoBean` ne yapıyor ⭐

```java
@WebMvcTest(SiparisKontrolcusu.class)
class SliceTest {

    @Autowired MockMvcTester mvc;

    @MockitoBean SiparisServisi servis;      // ← container'a mock bir SiparisServisi koy

    @Test
    void mock_servis_ile_calisir() {
        given(servis.durum("A-1")).willReturn("MOCK");

        assertThat(mvc.get().uri("/siparisler/durum/A-1"))
                .hasStatusOk()
                .hasBodyTextEqualTo("MOCK");
    }
}
```

`@MockitoBean`, Mockito ile bir mock üretir ve onu **container'a bean olarak koyar**.
Kontrolcü `SiparisServisi`'ni inject ettiğinde gerçeğini değil, bu mock'u alır.

| Anotasyon | Ne yapar | Nerede |
|---|---|---|
| **`@MockitoBean`** | Bean'i mock ile **değiştirir** | Test sınıfının alanı |
| **`@MockitoSpyBean`** | Gerçek bean'i **sarar**; bazı metotları izler/değiştirir | Test sınıfının alanı |
| `@Mock` (Mockito'nun kendi anotasyonu) | Container'dan bağımsız mock | Saf birim testi |

⚠️ **`@MockitoBean` yalnızca test sınıfının alanına yazılır.** `@Configuration` sınıfına
yazamazsın — Spring Boot 3'te bu mümkündü, artık değil.

---

## 2. Spring Boot 4 geçiş tablosu ⭐

Bu tabloyu bir yere kaydet; eski bir projeyi taşırken doğrudan işine yarar:

| Spring Boot 3.x | Spring Boot 4.x |
|---|---|
| `@MockBean` | **`@MockitoBean`** |
| `@SpyBean` | **`@MockitoSpyBean`** |
| `@SpringBootTest` → MockMvc hazır | **`@AutoConfigureMockMvc` gerekir** |
| `@SpringBootTest` → `TestRestTemplate` hazır | **`@AutoConfigureTestRestTemplate` gerekir** |
| `org.springframework.boot.test.web.client.TestRestTemplate` | **`org.springframework.boot.resttestclient.TestRestTemplate`** |
| `org.springframework.boot.test.autoconfigure.web.servlet.*` | **`org.springframework.boot.webmvc.test.autoconfigure.*`** |
| Tek `spring-boot-starter-test` | **`spring-boot-starter-<teknoloji>-test`** |
| `@WithMockUser` genel test starter'ında | **`spring-boot-starter-security-test`** gerekir |
| `MockitoTestExecutionListener` `@Mock`'u işler | **Kaldırıldı** — Mockito'nun `MockitoExtension`'ını kullan |

⚠️ Son satır kolay gözden kaçar: test sınıfında `@Mock` ve `@Captor` kullanıyorsan artık
`@ExtendWith(MockitoExtension.class)` yazman gerekiyor. Yazmazsan alanlar `null` kalır ve
hata `NullPointerException` olarak, asıl sebebi göstermeden çıkar.

Bu kursta gördüğün sürümler (Spring Boot 4.1.1 ile gelenler): **JUnit Jupiter 6.0.3**,
**Mockito 5.23.0**, **AssertJ 3.27.7**.

## 3. `MockMvcTester`: AssertJ ile okunabilir testler

Spring Framework 7 ile gelen `MockMvcTester`, eski `MockMvc` yazımının yerini alıyor:

```java
// Eski yazım (hâlâ çalışır)
mockMvc.perform(get("/siparisler/durum/A-1"))
       .andExpect(status().isOk())
       .andExpect(content().string("MOCK"));

// MockMvcTester
assertThat(mvc.get().uri("/siparisler/durum/A-1"))
        .hasStatusOk()
        .hasBodyTextEqualTo("MOCK");
```

Üç somut kazanç:

| | Eski `MockMvc` | `MockMvcTester` |
|---|---|---|
| Statik `import` | `status()`, `content()`, `get()`… uzun liste | Yalnızca `assertThat` |
| `throws Exception` | Gerekir | **Gerekmez** |
| Hata çıktısı | Genel | AssertJ'nin ayrıntılı karşılaştırması |

JSON gövdeleri için:

```java
assertThat(mvc.get().uri("/siparisler/S-1"))
        .hasStatusOk()
        .bodyJson()
        .extractingPath("$.urunKodu").isEqualTo("ABC-1");
```

## 4. Mock'lamanın sınırı ⭐

Mock bean, tek satırla container'daki herhangi bir bean'i devre dışı bırakır — ve tam bu
kolaylık yüzünden fazla kullanılır.

```java
@SpringBootTest
class SiparisAkisiTest {
    @MockitoBean SiparisServisi servis;
    @MockitoBean StokServisi stok;
    @MockitoBean OdemeServisi odeme;
    @MockitoBean BildirimServisi bildirim;      // ← her şey mock
    ...
}
```

Bu test **hiçbir şey ölçmüyor.** Bütün gerçek davranış mock'landı; geriye yalnızca senin
mock'lara verdiğin cevapların doğru sırayla döndüğünü doğrulamak kaldı. Yani testin,
kodun değil **kendi varsayımlarının** testi.

**Kural:** Mock'la — ama yalnızca **test edilen sınırın dışını**:

| Mock'la | Mock'lama |
|---|---|
| Dış HTTP servisleri | Test ettiğin sınıfın kendisi |
| Ödeme, e-posta, SMS gibi yan etkisi olan servisler | Saf hesaplama yapan sınıflar |
| Yavaş ya da kırılgan bağımlılıklar | Değeri olan iş mantığı |

⚠️ Bir testte üçten fazla `@MockitoBean` varsa dur ve sor: **yanlış katmanda mı test
ediyorum?** Genelde cevap evettir — ya slice test yeterdi, ya da sınıfın çok fazla
bağımlılığı var (ki bu da [1.3](../01-container-ve-bean/1.3-dependency-injection.md)'te söylediğimiz
"constructor uzuyorsa tasarım konuşuyor" işaretidir).

⚠️ Her `@MockitoBean` kümesi **ayrı bir container** demektir
([5.1](5.1-slice-test.md)) — yani mock'lamak test paketini de yavaşlatır.

## 5. Ne doğrulanmalı

```java
@Test
void siparis_alinca_stok_dusulur() {
    servis.siparisAl(new Siparis("S-1", "ABC", 2));

    verify(stok).dus("ABC", 2);              // çağrıldı mı, doğru argümanlarla mı
}
```

| Doğrula | Doğrulama |
|---|---|
| Yan etkinin gerçekleştiğini (`verify`) | Her metot çağrısını tek tek |
| Dönen değerin doğruluğunu | Mock'un kendi davranışını |
| Sınırdaki sözleşmeyi | İç uygulama ayrıntısını |

> 📌 **Sık yapılan hata:** Her çağrıyı `verify` etmek. Böyle bir test, kodun **yapısını**
> dondurur: iç düzenlemeyi (refactor) değiştirdiğin an, davranış aynı kalsa bile test
> kırmızıya döner. Test, davranışı korumalı — yazım biçimini değil.

## 6. Yanlış hâlleri

### ❌ Hata 1 — `@MockBean` kullanmak

```java
@MockBean SiparisServisi servis;
```

```
cannot find symbol: class MockBean
```

✅ **Doğrusu:** `@MockitoBean` — paketi `org.springframework.test.context.bean.override.mockito`.

📌 İnternetteki **her** Spring Boot test örneği hâlâ `@MockBean` yazıyor. Bu hatayı çok
göreceksin; artık ne olduğunu biliyorsun.

### ❌ Hata 2 — `@Mock` ile `@MockitoBean`'i karıştırmak

```java
@SpringBootTest
class SiparisTest {
    @Mock SiparisServisi servis;             // ← container'a KOYMAZ
    @Autowired SiparisKontrolcusu kontrolcu; // gerçek servisi alır
}
```

`@Mock` Mockito'nun anotasyonu; mock üretir ama Spring container'ına dokunmaz. Kontrolcü
gerçek servisi almaya devam eder ve testin sessizce yanlış şeyi ölçer.

✅ **Doğrusu:** Container'daki bean'i değiştirmek istiyorsan **`@MockitoBean`**. Spring'siz
saf birim testinde `@Mock` + `@ExtendWith(MockitoExtension.class)`.

### ❌ Hata 3 — mock'lanmamış metodun `null` dönmesi

```java
@MockitoBean SiparisServisi servis;

@Test
void deneme() {
    // given(...) yazmayı unuttun
    assertThat(mvc.get().uri("/siparisler/durum/A-1")).hasStatusOk();
}
```

Bir mock'un **mock'lanmamış** metodu varsayılan değer döner: nesnelerde `null`,
`int`'te `0`, `boolean`'da `false`. Testin geçebilir — ama ölçtüğü şey yanlıştır.

✅ **Doğrusu:** Kullandığın her metot için `given(...)` yaz.

### ❌ Hata 4 — Mockito'nun kendini ekleme uyarısı

Testleri çalıştırdığında bunu göreceksin:

```
Mockito is currently self-attaching to enable the inline-mock-maker. This will no longer
work in future releases of the JDK. Please add Mockito as an agent to your build...
```

Bu bir **uyarıdır**, hata değil — testlerin geçmeye devam eder. Yeni JDK sürümlerinde
Mockito'nun kendini süreç içine iliştirmesi kısıtlanıyor. Şimdilik yok sayabilirsin;
gelecekte Mockito'yu Java aracısı (agent) olarak eklemen gerekecek.

**Tanı, yeter. Ezberleme.**

## Sık karıştırılanlar — tek tabloda

| Karışan | Doğrusu | Neden diğeri değil |
|---|---|---|
| `@MockBean` / `@MockitoBean` | Boot 4'te **`@MockitoBean`** | Eskisi kaldırıldı, derlenmez |
| `@Mock` / `@MockitoBean` | `@Mock` **container'a dokunmaz** | Spring bean'ini değiştirmek istiyorsan `@MockitoBean` |
| `@MockitoBean` / `@MockitoSpyBean` | Değiştirir / **sarar** | Spy'da mock'lamadığın metotlar gerçek kodu çalıştırır |
| Mock'lamak testi güçlendirir | **Zayıflatabilir** | Her şey mock ise test kendi varsayımlarını ölçer |
| `@MockitoBean` bedava | **Yeni container** demektir | Farklı mock kümesi = ayrı container kurulumu |
| Mock'lanmamış metot patlar | **`null`/`0`/`false` döner** | Test sessizce yanlış şeyi ölçer |
| Mockito uyarısı hatadır | **Uyarıdır** | Testler geçer; ileride aracı eklenecek |

## 🖥 Pratik — mock'lamanın sınırını gör

> **Amaç:** `@MockitoBean` ile `@Mock` farkını ve mock'lanmamış metot tuzağını görmek
> **Süre:** 20 dk · **💸 Maliyet:** Yok
> **Ön koşul:** [5.1](5.1-slice-test.md)'deki `SliceTest` ve `FullContextTest` duruyor olmalı.

### Adım 1 — Mock'lanmamış metot tuzağı

`SliceTest`'te `given(...)` satırını **yorum satırı yap** ve beklentiyi gevşet:

```java
@Test
void mocklanmamis_metot() {
    // given(servis.durum("A-1")).willReturn("MOCK");
    assertThat(mvc.get().uri("/siparisler/durum/A-1")).hasStatusOk();
}
```

```bash
./mvnw test
```

- [ ] **Kontrol:** Test **geçti.**
- [ ] **Kaydet:** Uç nokta ne döndürdü? ______ (Mock `null` döndürdü; testin bunu
      kontrol etmediği için geçti. Yeşil test her zaman doğru test demek değildir.)
- [ ] `given(...)` satırını geri aç.

### Adım 2 — `@Mock` ile `@MockitoBean` farkı

`FullContextTest`'e ekle:

```java
@Mock SiparisServisi mockServis;          // Mockito'nun anotasyonu

@Test
void mock_kaba_dokunmaz() {
    assertThat(mvc.get().uri("/siparisler/durum/A-1"))
            .hasStatusOk()
            .hasBodyTextEqualTo("GERCEK-A-1");     // gerçek servis hâlâ devrede
}
```

- [ ] **Kontrol:** Test geçti — `@Mock` yazmış olmana rağmen **gerçek** servis çalıştı.
- [ ] Şimdi `@Mock`'u `@MockitoBean` yap ve `given(mockServis.durum("A-1")).willReturn("MOCK")`
      ekleyip beklentiyi `"MOCK"` yap.
- [ ] **Kontrol:** Şimdi mock devrede.
- [ ] **Kaydet:** İki anotasyon arasındaki farkı bir cümleyle yaz: ______

### Adım 3 — Eski anotasyonu dene

`@MockitoBean` yerine `@MockBean` yaz.

- [ ] **Kontrol:** `cannot find symbol: class MockBean`. İnternetteki örneklerin çoğunda
      göreceğin yazım bu. Geri düzelt.

### Adım 4 — Mockito uyarısını fark et

Testleri çalıştırırken çıktıyı dikkatle oku.

- [ ] **Kontrol:** `Mockito is currently self-attaching...` uyarısını gördün. Testler yine
      de geçiyor — bu bir uyarı.

## 60 saniyelik özet

- **`@MockitoBean`** container'daki bean'i mock ile **değiştirir**; **`@MockitoSpyBean`** gerçeği **sarar**.
- **`@Mock` container'a dokunmaz** — Spring bean'ini değiştirmek istiyorsan `@MockitoBean`.
- Geçiş: `@MockBean` → `@MockitoBean`, `@SpyBean` → `@MockitoSpyBean`.
- `@SpringBootTest` artık MockMvc ve `TestRestTemplate` **getirmiyor** —
  `@AutoConfigureMockMvc` / `@AutoConfigureTestRestTemplate` yaz.
- Paketler taşındı: `org.springframework.boot.webmvc.test.autoconfigure.*`,
  `org.springframework.boot.resttestclient.TestRestTemplate`.
- `@Mock`/`@Captor` için artık **`@ExtendWith(MockitoExtension.class)`** gerekiyor.
- **`MockMvcTester`**: statik `import` yok, `throws Exception` yok, AssertJ hata çıktısı.
- **Mock'lanmamış metot `null`/`0`/`false` döner** — test sessizce yanlış şeyi ölçebilir.
- Üçten fazla `@MockitoBean` varsa **yanlış katmanda test ediyorsundur**.
- Her farklı mock kümesi **yeni bir container** demektir; mock'lamak bedava değildir.
- Mockito'nun `self-attaching` çıktısı bir **uyarıdır**, hata değil.
