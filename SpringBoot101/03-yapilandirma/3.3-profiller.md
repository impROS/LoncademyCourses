# 3.3 — Profiller

> **Alan:** Yapılandırma
> **Süre:** ~25 dakika okuma + 15 dakika pratik
> **Test:** [`3.3-test.html`](3.3-test.html) · 14 soru

---

## Neden bu konu

Aynı uygulama üç yerde çalışacak: senin makinen, test ortamı, üretim. Üçünde de veritabanı
adresi, günlük seviyesi ve timeout'lar farklı.

En kötü çözüm — ve maalesef en yaygın olanı:

```java
if (System.getenv("ORTAM").equals("uretim")) {
    veritabani = "jdbc:postgresql://uretim-db:5432/siparis";
} else {
    veritabani = "jdbc:h2:mem:test";
}
```

Bu kodun derdi: **ortam bilgisi kaynak koda sızdı.** Yeni bir ortam eklemek kod
değiştirmek, derlemek ve yeniden dağıtmak demek.

**Büyük fikir:** Profil, "bu ayar kümesi yalnızca şu ortamda geçerli" demenin yoludur.
Kod hiç değişmez; hangi profilin açık olduğunu **dışarıdan** söylersin.

---

## 1. En sade hâl: profil dosyaları ⭐

Dosya adı kalıbı: `application-<profil>.properties`

```
src/main/resources/
├── application.properties            ← her zaman okunur (ortak taban)
├── application-yerel.properties      ← yalnızca "yerel" profili açıksa
└── application-uretim.properties     ← yalnızca "uretim" profili açıksa
```

`application.properties`:

```properties
siparis.magaza-adi=varsayilan-magaza
siparis.zaman-asimi=3000
siparis.bekleme=45s
siparis.sunucular[0]=a.sirket.com
```

`application-uretim.properties`:

```properties
siparis.magaza-adi=uretim-magazasi
siparis.zaman-asimi=1000
```

Profili açmadan çalıştırınca — gerçek çıktı:

```
INFO ... : No active profile set, falling back to 1 default profile: "default"
### AYAR = SiparisAyarlari[magazaAdi=varsayilan-magaza, zamanAsimi=3000,
                           bekleme=PT45S, sunucular=[a.sirket.com]]
```

Profili açınca:

```
### AYAR = SiparisAyarlari[magazaAdi=uretim-magazasi, zamanAsimi=1000,
                           bekleme=PT45S, sunucular=[a.sirket.com]]
```

⭐ **Bu çıktıdaki en önemli ayrıntı:** `bekleme` ve `sunucular` **değişmedi.**
`application-uretim.properties` dosyasında o iki ayar yok — ama kaybolmadılar.

**Profil dosyası, ana dosyanın yerine geçmez; üzerine biner.** Yalnızca kendi yazdığı
anahtarları ezer, gerisi tabandan gelir.

> 📌 **Sık yapılan hata:** Profil dosyasına ayarların **tamamını** kopyalamak. O an çalışır,
> ama tabana yeni bir ayar eklendiğinde profil dosyalarına eklemeyi unutan kişi sessiz bir
> tutarsızlık yaratır. **Profil dosyasına yalnızca farkı yaz.**

---

## 2. Profil nasıl açılır

Öncelik sırası [3.1](3.1-oncelik-sirasi.md)'dekiyle aynı — dıştaki içtekini ezer:

| Yöntem | Yazımı | Nerede |
|---|---|---|
| Komut satırı | `--spring.profiles.active=uretim` | Dağıtım betiği |
| Ortam değişkeni | `SPRING_PROFILES_ACTIVE=uretim` | ⭐ **Docker/Kubernetes'te bu** |
| Sistem özelliği | `-Dspring.profiles.active=uretim` | Betikler |
| Ayar dosyası | `spring.profiles.active=yerel` | Yalnızca **geliştirme** varsayılanı için |
| Test sınıfı | `@ActiveProfiles("test")` | Testler |

Birden çok profil virgülle:

```bash
--spring.profiles.active=uretim,izleme
```

⚠️ **Sıra önemli:** Çakışan bir ayar varsa **sondaki kazanır**. `uretim,izleme` yazarsan
`izleme` dosyasındaki değer `uretim` dosyasındakini ezer.

⚠️ **`application.properties` içine `spring.profiles.active=uretim` yazma.** Uygulamayı
üretim profiline **varsayılan olarak** kilitlemiş olursun ve dışarıdan ezmek isteyen
herkesin bunu bilmesi gerekir. Kaynak kodda bir ortam adı görüyorsan durup düşün.

---

## 3. Ortam değişkeni yazımı

[3.1](3.1-oncelik-sirasi.md)'deki relaxed binding kuralı burada da geçerli:

```
spring.profiles.active   →   SPRING_PROFILES_ACTIVE
```

Docker Compose'da:

```yaml
services:
  siparis:
    image: siparis-servisi:1.0
    environment:
      SPRING_PROFILES_ACTIVE: uretim
```

Bu, "aynı imaj, farklı ortam" fikrinin tamamıdır. İmajı bir kere üretir, üç ortamda farklı
ortam değişkeniyle çalıştırırsın.

---

## 4. Profile bağlı bean: `@Profile` ⭐

Ayar dosyası yetmiyorsa, **bean seviyesinde** de ayrım yapabilirsin:

```java
@Configuration
public class BildirimYapilandirmasi {

    @Bean
    @Profile("uretim")
    public BildirimServisi gercekBildirim() {
        return new SmsBildirimServisi(...);       // gerçekten SMS gönderir
    }

    @Bean
    @Profile("!uretim")                            // ← "uretim DEĞİLSE"
    public BildirimServisi sahteBildirim() {
        return mesaj -> System.out.println("SMS (sahte): " + mesaj);
    }
}
```

`@Profile` ifadeleri:

| Yazım | Anlamı |
|---|---|
| `@Profile("uretim")` | Yalnızca `uretim` açıksa |
| `@Profile("!uretim")` | `uretim` **açık değilse** |
| `@Profile({"test", "yerel"})` | İkisinden **biri** açıksa |
| `@Profile("uretim & izleme")` | **İkisi de** açıksa |

⚠️ **`@Profile` bir güvenlik aracı değildir.** "Üretimde bu uç noktayı kapatırım" diye
`@Profile("!uretim")` yazarsan ve biri profili yanlış ayarlarsa uç nokta açılır. Güvenlik,
güvenlik katmanıyla yapılır (**401**).

---

## 5. Tek dosyada çoklu profil

Ayrı dosya açmak istemiyorsan, YAML'da `---` ile belge ayır:

```yaml
siparis:
  magaza-adi: varsayilan-magaza
  zaman-asimi: 3000

---
spring:
  config:
    activate:
      on-profile: uretim
siparis:
  magaza-adi: uretim-magazasi
  zaman-asimi: 1000
```

⚠️ **Anahtarın adı `spring.config.activate.on-profile`.** Spring Boot 2.4'ten önce
`spring.profiles` idi ve o **artık çalışmaz.** İnternette bulacağın eski örneklerin çoğu
eski adı kullanır ve — tahmin ettiğin gibi — **sessizce hiçbir şey yapmaz.**

| | Ayrı dosyalar | Tek dosya, `---` ile |
|---|---|---|
| Okunabilirlik | Her ortam kendi dosyasında | Hepsi bir arada, uzun dosya |
| Fark görme | İki dosyayı yan yana açarsın | Tek ekranda |
| Tercih | **Üçten fazla ayar farkı varsa** | Küçük farklar için |

---

## 6. Hangi profillerin açık olduğunu görmek

Tahmin etme, sor. Açılış günlüğünün **ikinci satırı** her zaman bunu yazar:

```
INFO ... : No active profile set, falling back to 1 default profile: "default"
```

ya da:

```
INFO ... : The following 1 profile is active: "uretim"
```

Actuator açıksa çalışırken de sorabilirsin:

```bash
curl -s http://localhost:8080/actuator/env | grep activeProfiles
```

> 📌 Bir sorunu araştırırken **ilk bakılacak yer** bu satırdır. "Ayar okunmuyor" diyen
> vakaların önemli bir kısmı, beklenen profilin hiç açılmamış olmasıdır.

## 7. Yanlış hâlleri

### ❌ Hata 1 — profil adında yazım hatası

```bash
--spring.profiles.active=uretmi          # ← harfler yer değiştirmiş
```

Spring **hata vermez.** `application-uretmi.properties` diye bir dosya arar, bulamaz,
sessizce geçer. Uygulama varsayılan ayarlarla açılır — yani üretimde test veritabanına
bağlanabilir.

✅ **Doğrusu:** Açılış günlüğündeki `The following 1 profile is active:` satırını **her
dağıtımda** kontrol et. Kritik ortamlarda ayar doğrulaması ([3.2](3.2-configuration-properties.md))
ile ikinci bir savunma kur — yanlış profil, eksik zorunlu ayar olarak patlar.

### ❌ Hata 2 — eski `spring.profiles` anahtarı

```yaml
---
spring:
  profiles: uretim            # ← Spring Boot 2.4'ten beri çalışmıyor
```

✅ **Doğrusu:** `spring.config.activate.on-profile: uretim`

### ❌ Hata 3 — kaynak kodda ortam adı

```properties
# application.properties
spring.profiles.active=uretim
```

✅ **Doğrusu:** Profili **dışarıdan** ver. Kaynak kodda ortam adı görünmemeli.

## Sık karıştırılanlar — tek tabloda

| Karışan | Doğrusu | Neden diğeri değil |
|---|---|---|
| Profil dosyası ana dosyanın **yerine** geçer | **Üzerine biner** | Yazmadığı anahtarlar tabandan gelmeye devam eder |
| Yanlış profil adı hata verir | **Vermez** | Dosya bulunamaz, sessizce geçilir |
| `spring.profiles` / `spring.config.activate.on-profile` | **İkincisi** | Birincisi 2.4'ten beri çalışmıyor, sessizce |
| Çoklu profilde sıra önemsiz | **Önemli** | Çakışmada **sondaki** kazanır |
| `@Profile` güvenlik sağlar | **Sağlamaz** | Yanlış profil ayarı korumayı kaldırır |
| Profili ayar dosyasına yazmak | Dışarıdan verilir | Kaynak kodda ortam adı, dağıtımı kilitler |

## 🖥 Pratik — profil katmanını gör

> **Amaç:** Profilin ezme değil **binme** olduğunu ölçmek · **Süre:** 15 dk
> **💸 Maliyet:** Yok
> **Ön koşul:** [3.2](3.2-configuration-properties.md)'deki `SiparisAyarlari` sınıfı duruyor olmalı.

### Adım 1 — Taban ve profil dosyası

`src/main/resources/application.properties`:

```properties
siparis.magaza-adi=varsayilan-magaza
siparis.zaman-asimi=3000
siparis.bekleme=45s
siparis.sunucular[0]=a.sirket.com
```

`src/main/resources/application-uretim.properties`:

```properties
siparis.magaza-adi=uretim-magazasi
siparis.zaman-asimi=1000
```

Dikkat: profil dosyasında **yalnızca iki ayar** var.

### Adım 2 — Profilsiz çalıştır

```bash
./mvnw spring-boot:run
```

- [ ] **Kontrol:** Günlükte `No active profile set, falling back to 1 default profile: "default"`
- [ ] **Kontrol:** `magazaAdi=varsayilan-magaza`

### Adım 3 — Profili aç

```bash
./mvnw spring-boot:run -Dspring-boot.run.arguments=--spring.profiles.active=uretim
```

- [ ] **Kontrol:** `magazaAdi=uretim-magazasi`, `zamanAsimi=1000`
- [ ] **Kaydet:** `bekleme` ve `sunucular` ne oldu? ______
      (Beklenen: değişmedi — `PT45S` ve `[a.sirket.com]`. **Binme, ezme değil.**)

### Adım 4 — Ortam değişkeniyle aç

```bash
SPRING_PROFILES_ACTIVE=uretim ./mvnw spring-boot:run
```

- [ ] **Kontrol:** Aynı sonuç. Docker ve Kubernetes bu yolu kullanır.

### Adım 5 — Sessiz hatayı üret

```bash
./mvnw spring-boot:run -Dspring-boot.run.arguments=--spring.profiles.active=uretmi
```

- [ ] **Kontrol:** Hata **yok**. Ama `magazaAdi=varsayilan-magaza` — profil hiç uygulanmadı.
- [ ] **Kaydet:** Bunu günlüğün hangi satırından anlarsın? ______

Bu adımı atlama. Üretimde yanlış yazılmış bir profil adının nasıl göründüğünü bilmek,
bir gün sana çok zaman kazandıracak.

### Temizlik

Dosyaları bırak. `Ctrl+C`.

## Nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — "Üretimde test veritabanına bağlandık"**
> Profil hiç açılmamış ya da adı yanlış yazılmış. Açılış günlüğüne bak.

**Kalıp 2 — "Profil dosyasındaki ayar okunuyor ama diğerleri kayboldu"**
> Beklenmedik bir durum değil — kaybolmazlar. Tabanda da yoklarsa sorun tabandadır.

**Kalıp 3 — "YAML'daki profil bloğu çalışmıyor"**
> Eski `spring.profiles` anahtarı kullanılmış. `spring.config.activate.on-profile` yaz.

**Kalıp 4 — "İki profil açtım, biri diğerini eziyor"**
> Beklenen davranış: sondaki kazanır. Sırayı değiştir.

**Kalıp 5 — "Kubernetes'te profil geçmiyor"**
> `SPRING_PROFILES_ACTIVE` yazımını kontrol et.

## 60 saniyelik özet

- Profil dosyası: `application-<profil>.properties`, ve **ana dosyanın üzerine biner** — yerine geçmez.
- **Profil dosyasına yalnızca farkı yaz**, tamamını kopyalama.
- Profili **dışarıdan** aç: `--spring.profiles.active=` ya da `SPRING_PROFILES_ACTIVE=`.
- Kaynak koddaki `spring.profiles.active=uretim` satırı, dağıtımı kaynak koda kilitler.
- Çoklu profilde çakışmada **sondaki kazanır**.
- ⚠️ **Yanlış yazılan profil adı hata vermez** — sessizce yok sayılır.
- Açılış günlüğünün ikinci satırı hangi profillerin açık olduğunu yazar; **ilk oraya bak**.
- Tek dosyada profil: `spring.config.activate.on-profile` (eski `spring.profiles` **çalışmaz**).
- `@Profile` bean seçimi içindir, **güvenlik aracı değildir**.
