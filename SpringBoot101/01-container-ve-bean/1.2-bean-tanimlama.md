# 1.2 — Bean tanımlamanın iki yolu

> **Alan:** Container ve bean'ler
> **Süre:** ~25 dakika okuma + 15 dakika pratik
> **Test:** [`1.2-test.html`](1.2-test.html) · 14 soru

---

## Neden bu konu

Bir sınıfı bean yapmanın iki yolu var ve öğrenenlerin çoğu yalnızca birini bilir:
`@Component` ailesi. Sonra bir gün **kendi yazmadığın** bir sınıfı bean yapmak gerekir —
`ObjectMapper`, `RestClient`, üçüncü parti bir kütüphanenin sınıfı — ve o sınıfın başına
anotasyon yazamazsın, çünkü kaynağı sende değil.

İşte ikinci yol tam olarak bunun için var. Bu konuyu bitirdiğinde hangi durumda hangisini
kullanacağını düşünmeden bileceksin.

**Büyük fikir:** `@Component` "bu sınıfı bul ve kur" der; `@Bean` "bu nesneyi ben kurdum,
al sakla" der. Birincisi **sınıfa**, ikincisi **metoda** yazılır.

---

## 1. Yol A — Component scan (`@Component` ailesi)

Sınıfın başına anotasyon koyarsın, tarama onu bulur:

```java
package tr.loncademy.siparis;

import org.springframework.stereotype.Service;

@Service
public class SiparisServisi {
    public String durum(String no) { return "HAZIRLANIYOR"; }
}
```

Bu kadar. Container açılırken tarar, bulur, kurar.

**Bean'in adı ne olur?** Sınıf adının ilk harfi küçültülür: `SiparisServisi` →
`siparisServisi`. Kendin vermek istersen:

```java
@Service("siparisIslemleri")
```

⚠️ Bir istisna: sınıf adının **ilk iki harfi de büyükse** ilk harf küçültülmez.
`URLIstemcisi` → bean adı `URLIstemcisi` olur, `uRLIstemcisi` değil.

### Ne zaman kullanılır

Yazdığın **kendi** sınıfların için. Servis, depo (repository), kontrolcü (controller) —
uygulamanın kendi parçaları.

---

## 2. Yol B — `@Bean` metodu ⭐

Nesneyi sen kurarsın, container sonucu saklar:

```java
package tr.loncademy.siparis;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.client.RestClient;

@Configuration
public class IstemciYapilandirmasi {

    @Bean
    public RestClient stokIstemcisi() {
        return RestClient.builder()
                .baseUrl("https://stok.sirket.com")
                .build();
    }
}
```

Dört ayrıntı:

| Ayrıntı | Kural |
|---|---|
| Metot nerede | `@Configuration` işaretli bir sınıfın içinde |
| Bean adı | **Metodun adı** — burada `stokIstemcisi` |
| Bean türü | Metodun **dönüş türü** — burada `RestClient` |
| Kim çağırıyor | Container. Sen bu metodu elle çağırmazsın (sebebi [2.2](../02-anotasyon-haritasi/2.2-configuration.md)) |

### Ne zaman kullanılır

Üç durumda `@Bean` şart:

1. **Sınıf senin değil.** `RestClient`, `ObjectMapper`, `DataSource` — kaynak kodu Spring'de
   ya da üçüncü partide. Başına `@Service` yazamazsın.
2. **Kurulum mantık istiyor.** Nesneyi kurarken `if` yazman, ayar okuman, birden çok adım
   atman gerekiyor.
3. **Aynı türden birden çok nesne lazım.** İki farklı adrese bakan iki `RestClient`:

   ```java
   @Bean
   public RestClient stokIstemcisi() {
       return RestClient.builder().baseUrl("https://stok.sirket.com").build();
   }

   @Bean
   public RestClient odemeIstemcisi() {
       return RestClient.builder().baseUrl("https://odeme.sirket.com").build();
   }
   ```

   İki bean, aynı tür, farklı adlar. (Bu durumun injection'da yarattığı sorunu
   [1.3](1.3-dependency-injection.md)'te çözüyoruz.)

## 3. İkisinin karşılaştırması ⭐

| | **`@Component` ailesi** | **`@Bean` metodu** |
|---|---|---|
| Nereye yazılır | **Sınıfın** başına | `@Configuration` sınıfındaki **metodun** başına |
| Bean adı | Sınıf adı, ilk harf küçük | **Metot adı** |
| Kimin sınıfı | Senin yazdığın | Herkesin — özellikle senin olmayan |
| Kurulumu kim yapar | Container (constructor'u çağırır) | **Sen** (metodun gövdesinde) |
| Aynı türden çoklu | Zor — her biri ayrı sınıf olmalı | Kolay — farklı adlı metotlar |
| Nerede görünür | Sınıfın kendisinde | Yapılandırma sınıfında, sınıftan uzakta |

> 📌 **Sık yapılan hata:** Kendi yazdığın basit bir servisi `@Bean` metoduyla tanımlamak.
> Çalışır ama kurulum bilgisini sınıftan uzağa taşır; okuyan kişi sınıfa bakıp bean olup
> olmadığını anlayamaz. **Kendi sınıfın → `@Component` ailesi. Başkasının sınıfı → `@Bean`.**

---

## 4. Yanlış hâlleri

### ❌ Hata 1 — `@Bean` metodunu `@Configuration` dışına koymak

```java
@Service                          // ← @Configuration değil
public class SiparisServisi {

    @Bean
    public RestClient stokIstemcisi() {              // ← burada
        return RestClient.builder().build();
    }
}
```

Bu **hata vermez** — ve tehlikeli olan da bu. Metot bir bean üretir ama `@Configuration`
dışında olduğu için **"lite mode" (lite mode)** çalışır: metodu her çağıran yeni bir nesne
alır, singleton garantisi kaybolur. Sessiz bir hata.

✅ **Doğrusu ve sebebi:** `@Bean` metotları `@Configuration` sınıfında durur. Farkın
mekanizması [2.2](../02-anotasyon-haritasi/2.2-configuration.md)'de.

### ❌ Hata 2 — aynı ada sahip iki bean

```java
@Configuration
public class Yapilandirma {
    @Bean
    public RestClient istemci() { ... }
}

@Configuration
public class DigerYapilandirma {
    @Bean
    public RestClient istemci() { ... }         // ← aynı metot adı = aynı bean adı
}
```

Çalıştırınca:

```
The bean 'istemci', defined in class path resource [DigerYapilandirma.class], could not
be registered. A bean with that name has already been defined in class path resource
[Yapilandirma.class] and overriding is disabled.
```

✅ **Doğrusu ve sebebi:** Bean adları container genelinde benzersizdir. Metot adını değiştir
(`stokIstemcisi` / `odemeIstemcisi`).

⚠️ Hata mesajının sonundaki `overriding is disabled` kısmına dikkat: Spring Boot 2.1'den
beri bean üzerine yazma **kapalıdır**. `spring.main.allow-bean-definition-overriding=true`
ile açılabilir — **açma.** Bu ayar, hatayı çözmez; onu sessiz bir "hangisi kazandı?"
bilmecesine çevirir.

### ❌ Hata 3 — sınıfı `new` ile kurup bean sanmak

```java
@Service
public class SiparisServisi {
    private final StokIstemcisi stok = new StokIstemcisi();   // ← bean değil
}
```

`SiparisServisi` bir bean, ama içindeki `StokIstemcisi` **değil**. Container ona injection
yapmaz, ayar okumaz, ileride `@Transactional` ya da `@Retryable` gibi anotasyonlarını
işlemez. [1.1](1.1-container-nedir.md)'deki cümle: **bean olmak, var olmak değildir.**

✅ **Doğrusu:** Constructor'dan al (`1.3`).

## 5. Bir bean'i koşullu hâle getirmek

`@Bean` metodunun asıl gücü, kurulumu **koşula** bağlayabilmen:

```java
@Bean
@ConditionalOnMissingBean(RestClient.class)     // sadece başka biri tanımlamadıysa
public RestClient varsayilanIstemci() {
    return RestClient.create();
}
```

Bu satır, Spring Boot'un auto-configuration'ının kullandığı mekanizmanın ta kendisi:
"kullanıcı kendi `RestClient`'ini tanımladıysa benimkini kurma". `@Conditional` ailesini
[2.3](../02-anotasyon-haritasi/2.3-auto-configuration.md)'te açıyoruz.

**Şimdilik tanı, yeter:** böyle bir şeyin var olduğunu bil. **Ezberleme.**

---

## Sık karıştırılanlar — tek tabloda

| Karışan | Doğrusu | Neden diğeri değil |
|---|---|---|
| `@Component` / `@Bean` | `@Component` **sınıfa**, `@Bean` **metoda** | İkisi de bean üretir ama biri "bul ve kur", diğeri "ben kurdum, al" der |
| Bean adı | `@Component`'te sınıf adı, `@Bean`'de **metot adı** | `@Bean` metodunun döndürdüğü sınıfın adı bean adı **değildir** |
| `@Bean` metodunu çağırmak | Container çağırır, sen çağırmazsın | Elle çağırırsan `@Configuration` dışında singleton garantisi bozulur (2.2) |
| İki aynı türde bean | Sorun değil, farklı **ad** verilir | Sorun injection'da çıkar (1.3), tanımlamada değil |
| İki aynı **adda** bean | Hata — açılış patlar | Ad benzersiz olmak zorunda; `allow-bean-definition-overriding` açma |

## 🖥 Pratik — iki yolu da kullan

> **Amaç:** Kendi sınıfını ve senin olmayan bir sınıfı bean yapmak · **Süre:** 15 dk
> **💸 Maliyet:** Yok

### Adımlar

1. `tr/loncademy/siparis/IstemciYapilandirmasi.java` oluştur:

   ```java
   package tr.loncademy.siparis;

   import org.springframework.context.annotation.Bean;
   import org.springframework.context.annotation.Configuration;
   import org.springframework.web.client.RestClient;

   @Configuration
   public class IstemciYapilandirmasi {

       @Bean
       public RestClient stokIstemcisi() {
           return RestClient.builder().baseUrl("https://stok.ornek.com").build();
       }

       @Bean
       public RestClient odemeIstemcisi() {
           return RestClient.builder().baseUrl("https://odeme.ornek.com").build();
       }
   }
   ```

2. `main` metodunda ikisini de listele:

   ```java
   var istemciler = container.getBeansOfType(RestClient.class);
   istemciler.forEach((ad, nesne) -> System.out.println(ad + " -> " + nesne));
   ```

3. Çalıştır: `./mvnw spring-boot:run`

- [ ] **Kontrol:** İki satır göreceksin: `stokIstemcisi -> ...` ve `odemeIstemcisi -> ...`
- [ ] **Kaydet:** Bean adları metot adlarıyla aynı mı? ______

4. **Şimdi bilerek boz.** `odemeIstemcisi` metodunun adını `stokIstemcisi` yap (iki metot
   aynı adda olamayacağı için birini başka bir `@Configuration` sınıfına taşı) ve çalıştır.

- [ ] **Kontrol:** `A bean with that name has already been defined` hatasını gördün.

5. Geri al.

6. Son olarak: `getBeansOfType(RestClient.class)` çağrısının kaç sonuç döndürdüğüne bak.
   Bu sayıyı aklında tut — [1.3](1.3-dependency-injection.md)'te bu iki bean yüzünden injection
   patlayacak.

### Temizlik

Kaynak yok, silinecek şey yok. Oluşturduğun `IstemciYapilandirmasi` sınıfını **bırak** —
sonraki konuda kullanacağız. `Ctrl+C`.

## Nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — "`ObjectMapper`'ı nasıl özelleştiririm?"**
> `@Bean` metoduyla kendi `ObjectMapper`'ını tanımlarsın; senin olmayan bir sınıf.

**Kalıp 2 — `A bean with that name has already been defined`**
> İki `@Bean` metodu aynı ada sahip ya da bir `@Component` ile bir `@Bean` çakışıyor.

**Kalıp 3 — "Aynı sınıftan iki tane lazım"**
> `@Bean` metoduyla iki farklı adlı bean tanımlanır.

**Kalıp 4 — "Kütüphane sınıfına `@Service` yazamıyorum"**
> Yazamazsın, kaynağı sende değil. `@Bean` metodu bunun için var.

**Kalıp 5 — "Bean'im her seferinde yeni nesne dönüyor"**
> `@Bean` metodu `@Configuration` dışında bir sınıfta (2.2).

---

## 60 saniyelik özet

- İki yol: **`@Component` ailesi** (sınıfa) ve **`@Bean` metodu** (`@Configuration` içindeki metoda).
- `@Component`'te bean adı = sınıf adı ilk harfi küçük; `@Bean`'de bean adı = **metot adı**.
- **Kendi sınıfın → `@Component`. Başkasının sınıfı → `@Bean`.**
- `@Bean` üç durumda şart: sınıf senin değil, kurulum mantık istiyor, aynı türden çok nesne lazım.
- Bean adları container genelinde **benzersiz**; çakışma açılışta patlar.
- `spring.main.allow-bean-definition-overriding=true` **açma** — hatayı gizler, çözmez.
- `@Bean` metodunu `@Configuration` dışına koymak sessiz bir hatadır: singleton garantisi bozulur.
- `new` ile kurduğun nesne bean değildir; Spring anotasyonları onda işlemez.
