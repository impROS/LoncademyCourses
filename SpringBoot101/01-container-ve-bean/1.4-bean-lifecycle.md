# 1.4 — Bean lifecycle

> **Alan:** Container ve bean'ler
> **Süre:** ~25 dakika okuma + 15 dakika pratik
> **Test:** [`1.4-test.html`](1.4-test.html) · 14 soru

---

## Neden bu konu

Bir nesnenin **kurulmuş** olmasıyla **kullanıma hazır** olması aynı şey değil. Aradaki
boşluk, Spring'te en sinsi hataların çıktığı yer:

- Constructor'da bir bağlantı açmaya çalışırsın — ayar henüz okunmamıştır.
- Constructor'da `@Transactional` bir metodu çağırırsın — proxy (bean'in etrafına geçirilen,
  çağrıları araya girip yöneten nesne) henüz hazır değildir, transaction hiç açılmaz ve
  **hata da vermez** (**201**).
- Kapanışta kaynağını bırakmayı unutursun — bağlantılar sızar.

Bu konuyu bitirdiğinde "bu kodu constructor'a mı, `@PostConstruct`'a mı yazmalıyım?"
sorusuna düşünmeden cevap vereceksin.

**Büyük fikir:** Bir bean'in lifecycle'ı (kuruluşundan yok oluşuna kadar geçirdiği aşamalar
dizisi) üçe ayrılır — **kurul → hazırlan → yok ol.** Constructor birinci aşamadadır ve
orada nesne henüz eksiktir.

---

## 1. Dert: constructor'da iş yapmak

```java
@Service
public class StokServisi {
    private final RestClient istemci;

    public StokServisi(RestClient istemci) {
        this.istemci = istemci;
        this.onbellek = istemci.get().uri("/stoklar").retrieve().body(Map.class);  // ← ağ çağrısı
    }
}
```

Bu kodun üç derdi var:

| Dert | Sonucu |
|---|---|
| Açılış, ağın hızına bağlanır | Stok servisi yavaşsa uygulaman açılmaz |
| Test edilemez | `new StokServisi(mock)` bile ağa çıkmaya çalışır |
| Hata mesajı yanıltıcı olur | Constructor'daki exception "bean oluşturulamadı" diye çıkar, asıl sebep kaybolur |

### En sade hâl: kurulumu ikiye ayır

```java
@Service
public class StokServisi {
    private final RestClient istemci;
    private Map<String, Integer> onbellek;

    public StokServisi(RestClient istemci) {      // 1. AŞAMA: sadece ata
        this.istemci = istemci;
    }

    @PostConstruct
    public void hazirla() {                       // 2. AŞAMA: asıl iş
        this.onbellek = istemci.get().uri("/stoklar").retrieve().body(Map.class);
    }
}
```

Kural basit: **constructor'da atama yap, iş yapma.**

## 2. Lifecycle'ın sırası ⭐

Bir bean'in başından geçenler, sırasıyla:

| # | Aşama | Ne olur | Sen ne yazarsın |
|---|---|---|---|
| 1 | Kurulum | Constructor çağrılır, bağımlılıklar verilir | Constructor — **sadece atama** |
| 2 | Alan/setter injection | `@Autowired` alanlar, `@Value` değerleri doldurulur | — |
| 3 | `Aware` arayüzleri | `BeanNameAware` vb. çağrılır | (nadiren) |
| 4 | **`@PostConstruct`** | Başlangıç metodun çağrılır | **Hazırlık işleri burada** |
| 5 | Proxy'lenme | `@Transactional`, `@Cacheable` gibi anotasyonlar için nesne sarmalanır | — |
| 6 | Kullanıma hazır | Container bu bean'i başkalarına verebilir | — |
| ⋯ | *(uygulama çalışır)* | | |
| 7 | **`@PreDestroy`** | Kapanışta temizlik metodun çağrılır | **Kaynak bırakma burada** |

**Ezberlenecek tek şey 1 ile 4 arasındaki fark**: constructor'da nesne henüz eksiktir,
`@PostConstruct`'ta tamdır.

⚠️ **5. adım kritik ve sonraki kurslarda geri gelecek:** proxy'lenme `@PostConstruct`'tan
**sonra** olur. Yani `@PostConstruct` içinde kendi `@Transactional` metodunu çağırırsan,
transaction açılmaz — proxy henüz devrede değildir. Resmî belgede bu açıkça yazar. Bunu
**201**'de ayrıntısıyla göreceğiz; şimdilik **tanı, yeter.**

## 3. `@PostConstruct` ve `@PreDestroy`

```java
import jakarta.annotation.PostConstruct;
import jakarta.annotation.PreDestroy;

@Service
public class BaglantiHavuzu {

    @PostConstruct
    public void ac() {
        System.out.println("havuz açılıyor");
    }

    @PreDestroy
    public void kapat() {
        System.out.println("havuz kapanıyor");
    }
}
```

⚠️ **Paket adına dikkat: `jakarta.annotation`, `javax.annotation` değil.** Spring Boot 3'ten
beri Jakarta EE'ye geçildi. İnternette bulacağın eski örneklerin çoğunda `javax` yazar ve
Spring Boot 4'te **derlenmez** — ya da daha kötüsü, yanlış paketten bir sınıf içeri alırsan
derlenir ama anotasyon **hiç çalışmaz.**

| Kural | Ayrıntı |
|---|---|
| Dönüş türü | `void` |
| Parametre | Yok |
| Erişim | `public` olması gerekmez, ama gelenek `public` |
| Kaç tane | Sınıf başına birden çok olabilir, ama **sırası garanti değildir** — bir tane yaz |
| Exception atarsa | `@PostConstruct` atarsa uygulama açılmaz (bu genelde istediğin şeydir) |

## 4. Kapanış: `@PreDestroy` ne zaman çalışmaz ⭐

Bu, üretimde kaynak sızıntısının en sık sebebi.

| Durum | `@PreDestroy` çalışır mı |
|---|---|
| `Ctrl+C` / `SIGTERM` (normal kapanış) | ✅ Evet |
| `kill -9` / `SIGKILL` | ❌ **Hayır** — işletim sistemi süreci anında öldürür |
| Elektrik kesilmesi, Docker container'ının zorla durdurulması | ❌ Hayır |
| **Prototype scope'lu** bean | ❌ **Hayır** — bkz. [1.5](1.5-scope.md) |
| `System.exit()` | ✅ Evet (kapanış kancası çalışır) |

> 📌 **Sık yapılan hata:** Veri bütünlüğünü `@PreDestroy`'a emanet etmek. "Kapanırken
> bekleyen kayıtları veritabanına yazarım" dersen, `kill -9` yediğin gün o kayıtlar yok
> olur. `@PreDestroy` **kaynak bırakmak** içindir (bağlantı kapatma, dosya kapatma), veri
> güvenliği için değil.

Kubernetes gibi ortamlarda süreç önce `SIGTERM` alır, belirli bir süre sonra `SIGKILL`.
Aradaki sürede Spring Boot **graceful shutdown** yapar: yeni istek kabul etmez, devam
edenleri bitirir, sonra kapanır. Günlükte şöyle görünür:

```
INFO ... o.s.boot.tomcat.GracefulShutdown : Commencing graceful shutdown. Waiting for active requests to complete
INFO ... o.s.boot.tomcat.GracefulShutdown : Graceful shutdown complete
```

⭐ **Spring Boot 4 değişikliği:** Bu davranış artık **varsayılan**. İlgili iki ayarın
resmî varsayılan değerleri:

| Ayar | Varsayılan |
|---|---|
| `server.shutdown` | **`graceful`** |
| `spring.lifecycle.timeout-per-shutdown-phase` | `30s` |

> ⚠️ Spring Boot 3.x'te `server.shutdown` varsayılanı **`immediate`** idi ve graceful shutdown
> için bu satırı elle yazman gerekirdi. Eski projelerde `server.shutdown=graceful` satırını
> görürsen: artık gereksiz, ama zararsız.

## 5. `@Lazy`: kurulumu ertelemek

Varsayılan olarak singleton bean'ler **açılışta** kurulur. `@Lazy` bunu ilk kullanıma erteler:

```java
@Service
@Lazy
public class AgirRaporServisi { ... }
```

| | Varsayılan (erken) | `@Lazy` (tembel) |
|---|---|---|
| Ne zaman kurulur | Açılışta | İlk istendiğinde |
| Açılış süresi | Uzar | Kısalır |
| Hata ne zaman çıkar | ✅ **Açılışta** | ⚠️ İlk kullanımda — belki üretimde saat 3'te |

⚠️ **`@Lazy`'yi varsayılan yapma.** Açılışta patlamak bir **özelliktir**: hatayı dağıtım
anında görürsün. `@Lazy`, o güvenceyi ağır ve nadiren kullanılan bir bean için bilinçli
olarak takas etmektir. "Açılış yavaş" diye her yere `@Lazy` yazmak, hataları üretime taşır.

**Ezberle:** varsayılan erken kurulum, ve bu iyidir.
**Tanı, yeter:** `@Lazy`'nin var olduğunu.
**Girme:** `spring.main.lazy-initialization=true` ile hepsini birden tembelleştirmek —
geliştirme sırasında açılışı hızlandırmak için kullanılır, üretimde değil.

## 6. Yanlış hâlleri

### ❌ Hata 1 — `javax.annotation.PostConstruct`

```java
import javax.annotation.PostConstruct;      // ← eski paket
```

Spring Boot 4'te bu paket classpath'te yoktur:

```
package javax.annotation does not exist
```

✅ **Doğrusu:** `import jakarta.annotation.PostConstruct;`

### ❌ Hata 2 — constructor'da bağımlılığı kullanmak

```java
@Service
public class RaporServisi {
    private final SiparisDeposu depo;

    public RaporServisi(SiparisDeposu depo) {
        this.depo = depo;
        this.toplam = depo.hepsiniSay();     // ← burada veritabanına gidiyor
    }
}
```

Bu bazen çalışır, bazen çalışmaz — ve **çalışmadığında sebebi bulmak zordur**. Depo bean'i
kurulmuş olabilir ama proxy'si henüz oluşturulmamış olabilir; veri kaynağı henüz hazır
olmayabilir.

✅ **Doğrusu:** İşi `@PostConstruct`'a taşı.

### ❌ Hata 3 — `@PreDestroy`'a veri yazma işi vermek

```java
@PreDestroy
public void kapat() {
    bekleyenKayitlar.forEach(depo::kaydet);   // ← kill -9 gelirse hepsi kaybolur
}
```

✅ **Doğrusu:** Veriyi geldiği anda kalıcı hâle getir; `@PreDestroy`'da yalnızca kaynak bırak.

---

## Sık karıştırılanlar — tek tabloda

| Karışan | Doğrusu | Neden diğeri değil |
|---|---|---|
| Constructor / `@PostConstruct` | Yapıcıda **atama**, `@PostConstruct`'ta **iş** | Constructor'da nesne eksiktir; injection ve proxy'lenme henüz bitmemiştir |
| `javax.annotation` / `jakarta.annotation` | **`jakarta`** | `javax` Spring Boot 3'ten beri yok; eski örneklerin hepsinde geçer |
| `@PreDestroy` her zaman çalışır | **Çalışmaz** | `kill -9` ve prototype scope'ta çağrılmaz |
| `@Lazy` iyileştirmedir | **Takastır** | Açılış hızını, hatayı erken görme güvencesiyle takas edersin |
| Kurulmuş = hazır | Değil | Proxy'lenme `@PostConstruct`'tan sonra olur (201) |

## Nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — `package javax.annotation does not exist`**
> Eski paket adı. `jakarta.annotation` yaz.

**Kalıp 2 — "Constructor'da veritabanına gidiyorum, bazen patlıyor"**
> İşi `@PostConstruct`'a taşı.

**Kalıp 3 — "Kapanışta bağlantılar kapanmıyor"**
> Süreç `kill -9` alıyor olabilir; ya da `server.shutdown=graceful` ayarlanmamış.

**Kalıp 4 — "Uygulama açılıyor ama ilk istekte patlıyor"**
> `@Lazy` bir bean var; hatası kurulduğu ana ertelenmiş.

**Kalıp 5 — "`@PostConstruct` içinde `@Transactional` metodumu çağırıyorum, transaction açılmıyor"**
> Proxy'lenme `@PostConstruct`'tan sonra olur. (201)

## 60 saniyelik özet

- Sıra: **constructor → injection → `@PostConstruct` → proxy'lenme → hazır → `@PreDestroy`.**
- **Constructor'da atama yap, iş yapma.** Hazırlık işleri `@PostConstruct`'ta.
- Paket: **`jakarta.annotation`**, `javax` değil.
- `@PreDestroy` **`kill -9`'da ve prototype bean'lerde çalışmaz** — veri güvenliği için kullanma.
- Graceful shutdown Spring Boot 4'te **varsayılan** (`server.shutdown=graceful`, bekleme `30s`);
  3.x'te varsayılan `immediate` idi.
- Varsayılan **erken** kurulum bir özelliktir: hata dağıtım anında çıkar.
- `@Lazy` bir takastır, iyileştirme değil — açılış hızını hata güvencesiyle değişirsin.
- Proxy, `@PostConstruct`'tan **sonra** devreye girer. (201'de geri gelecek.)
