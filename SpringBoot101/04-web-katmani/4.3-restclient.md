# 4.3 — RestClient ile dışarıya çağrı

> **Alan:** Web katmanı
> **Süre:** ~25 dakika okuma + 20 dakika pratik
> **Test:** [`4.3-test.html`](4.3-test.html) · 14 soru

---

## Neden bu konu

Gerçek bir servis tek başına yaşamaz. Sipariş servisin stok servisini, stok servisi
depo servisini çağırır. Her çağrı bir **ağ** çağrısıdır ve ağ üç şeyi yapabilir: doğru
cevap verir, hata verir, ya da **hiç cevap vermez**.

Üçüncüsü en tehlikelisi. Timeout (bir çağrının en fazla ne kadar bekleyeceğini belirleyen
sınır) ayarlamadan yaptığın bir çağrı, karşı taraf donduğunda senin thread'ini de dondurur.
Yeterince istek gelirse bütün thread havuzu tükenir ve **senin** servisin de çöker — kendi
kodunda hiçbir hata olmadan.

**Büyük fikir:** Spring'in bugünkü önerilen HTTP istemcisi **`RestClient`**. Zincirleme
(fluent) bir arayüzü vardır, hataları exception'a çevirir ve timeout'u **sen**
ayarlarsın.

---

## 1. Hangi istemci ⭐

Spring'de üç HTTP istemcisi görürsün ve internetteki örnekler üçünü de kullanır:

| İstemci | Durum (Spring Framework 7.0) | Ne zaman |
|---|---|---|
| **`RestClient`** | ✅ **Önerilen** | Bloklayan çağrılar — yani senin işin |
| `WebClient` | ✅ Destekleniyor, kaldırılmıyor | Reaktif akış (streaming) gerekiyorsa |
| `RestTemplate` | ⚠️ Kullanımdan kaldırılma **niyeti açıklandı** | Yeni kodda kullanma |

⚠️ **`RestTemplate` şu an hâlâ `@Deprecated` işaretli değil.** Resmî plan: 7.1'de (Kasım
2026) işaretlenecek, 8.0'da kaldırılacak. Yani mevcut projendeki `RestTemplate` bugün
uyarı vermiyor — ama yeni kod yazarken `RestClient` seç.

📌 `RestClient`, `RestTemplate`'in altyapısını kullanır. Geçiş, sıfırdan öğrenmek değil,
yazım biçimini değiştirmektir.

## 2. En sade hâl

```java
@Configuration
public class IstemciYapilandirmasi {

    @Bean
    public RestClient stokIstemcisi() {
        return RestClient.builder()
                .baseUrl("https://stok.sirket.com")
                .build();
    }
}
```

```java
@Service
public class StokServisi {
    private final RestClient istemci;

    public StokServisi(@Qualifier("stokIstemcisi") RestClient istemci) {
        this.istemci = istemci;
    }

    public StokBilgisi getir(String urunKodu) {
        return istemci.get()
                .uri("/stoklar/{kod}", urunKodu)        // ← placeholder kullan
                .retrieve()
                .body(StokBilgisi.class);
    }
}
```

Gerçek çıktı (kendi uç noktamı çağırdım):

```
### BASARILI = Yanit[no=S-1, urunKodu=ABC-1, adet=2]
```

⚠️ **Adresi `+` ile birleştirme.** `"/stoklar/" + urunKodu` yazarsan, kodda `/` ya da `?`
geçtiğinde adres bozulur. `{kod}` placeholder'ını kullan — `RestClient` kaçış (URL encoding)
işini kendisi yapar.

## 3. Hata gelince ne oluyor ⭐

`retrieve()` başarısız durum kodlarını **exception'a çevirir**. Gerçek ölçüm:

```
### ISTISNA SINIFI = org.springframework.web.client.HttpClientErrorException$NotFound
### DURUM = 404 NOT_FOUND
### GOVDE = {"detail":"Sipariş bulunamadı: yok","instance":"/siparisler/yok",
             "status":404,"title":"Sipariş bulunamadı",
             "type":"https://loncademy.tr/hatalar/siparis-bulunamadi"}
```

İki şey öğreniyoruz:

1. **Exception sınıfı duruma özgü:** `HttpClientErrorException$NotFound`. 4xx için
   `HttpClientErrorException`, 5xx için `HttpServerErrorException` — ikisi de
   `RestClientResponseException` altındadır.
2. **Hata gövdesi kayıp değil:** `getResponseBodyAsString()` ile karşı tarafın
   `ProblemDetail`'ini okuyabiliyorsun ([4.2](4.2-exception-handling.md)'de ürettiğimiz gövdenin
   ta kendisi).

### Kendi işleyicini yaz

```java
public StokBilgisi getir(String urunKodu) {
    return istemci.get()
            .uri("/stoklar/{kod}", urunKodu)
            .retrieve()
            .onStatus(HttpStatusCode::is4xxClientError, (istek, yanit) -> {
                throw new StokBulunamadi(urunKodu);        // kendi exception'ın
            })
            .body(StokBilgisi.class);
}
```

### Ya da durumu kendin oku

```java
ResponseEntity<StokBilgisi> yanit = istemci.get()
        .uri("/stoklar/{kod}", urunKodu)
        .retrieve()
        .toEntity(StokBilgisi.class);

if (yanit.getStatusCode() == HttpStatus.NOT_FOUND) { ... }
```

| Yöntem | Ne döner |
|---|---|
| `.body(T.class)` | Yalnızca gövde |
| `.toEntity(T.class)` | Gövde + **durum kodu** + başlıklar |
| `.toBodilessEntity()` | Gövdesiz — yalnızca durum ve başlıklar |

## 4. Timeout: en kritik ayar ⭐

**Varsayılan olarak timeout yoktur.** Karşı taraf cevap vermezse istek sonsuza kadar
bekler. Üretimde bu, tek bir yavaş servisin bütün sistemi durdurmasının yoludur.

Spring Boot 4'te auto-configuration ile kurulan tüm istemciler için tek yerden ayarlanır:

```properties
spring.http.clients.connect-timeout=2s
spring.http.clients.read-timeout=5s
```

| Ayar | Neyi sınırlar | Makul başlangıç |
|---|---|---|
| `connect-timeout` | Bağlantı **kurulana** kadar | 1–3 sn |
| `read-timeout` | İlk yanıt baytı gelene kadar | 3–10 sn |

⭐ **`connect-timeout` her zaman `read-timeout`'tan küçük olmalı.** Bağlantı kurulamıyorsa
karşı taraf ayakta değildir; beklemenin anlamı yok.

⚠️ Timeout bir **çözüm değil, sınırdır**. "5 saniyede cevap gelmezse ne yapacağım?"
sorusunun cevabı hâlâ sende: yeniden dene, önbellekten dön, ya da hata ver. Retry
(`@Retryable`), circuit breaker ve timeout stratejileri **301**'in konusu.

**Ezberle:** varsayılan timeout **yoktur**, sen koymalısın.
**Tanı, yeter:** `spring.http.clients.*` ayar ailesi.
**Girme:** connection pool boyutlandırma, bağlantı ömrü — 401'de.

## 5. Bean tasarımı: her servise bir istemci ⭐

```java
@Configuration
public class IstemciYapilandirmasi {

    @Bean
    public RestClient stokIstemcisi(RestClient.Builder kurucu) {
        return kurucu.baseUrl("https://stok.sirket.com").build();
    }

    @Bean
    public RestClient odemeIstemcisi(RestClient.Builder kurucu) {
        return kurucu.baseUrl("https://odeme.sirket.com").build();
    }
}
```

⭐ **`RestClient.Builder`'ı inject et**, `RestClient.builder()` diye sıfırdan kurma.
Spring Boot'un auto-configuration ile kurduğu builder, timeout ayarlarını ve observability
(metrik/iz toplama) eklerini **zaten içerir**. Sıfırdan kurarsan hepsini kaybedersin ve
bunu fark etmezsin.

📌 [1.3](../01-container-ve-bean/1.3-dependency-injection.md)'ü hatırla: iki `RestClient` bean'i olduğu
için tüketen tarafta `@Qualifier` gerekir.

## 6. Yanlış hâlleri

### ❌ Hata 1 — timeout koymamak

```java
@Bean
public RestClient istemci() {
    return RestClient.builder().baseUrl("https://yavas.servis.com").build();
}
```

Yerelde ve testte kusursuz çalışır. Üretimde karşı taraf donduğu gün senin servisin de
cevap veremez hâle gelir. Kendi günlüklerinde hata görünmez — sadece her şey yavaşlar.

✅ **Doğrusu:** `spring.http.clients.read-timeout` ayarla ve `RestClient.Builder`'ı inject et.

### ❌ Hata 2 — adres birleştirme

```java
.uri("/stoklar/" + urunKodu)        // urunKodu = "A/B?x=1" ise adres bozulur
```

✅ **Doğrusu:** `.uri("/stoklar/{kod}", urunKodu)`

### ❌ Hata 3 — exception'ı yutmak

```java
try {
    return istemci.get().uri("/stoklar/{kod}", kod).retrieve().body(StokBilgisi.class);
} catch (Exception e) {
    return null;                     // ← "stok yok" ile "servis çökmüş" aynı şey oldu
}
```

Çağıran taraf `null` görür ve "stok yok" sanır. Oysa belki ödeme servisi çökmüştür ve
siparişi **almaman** gerekiyordu.

✅ **Doğrusu:** 4xx ile 5xx'i ayır. `404` → "yok" anlamına gelebilir; `500` → kendi
exception'ına çevir ve yukarı at.

### ❌ Hata 4 — her çağrıda yeni istemci kurmak

```java
public StokBilgisi getir(String kod) {
    var istemci = RestClient.create();       // ← her çağrıda yeni connection pool
    ...
}
```

✅ **Doğrusu:** `RestClient` bir **bean** olsun, bir kere kurulsun.

## Sık karıştırılanlar — tek tabloda

| Karışan | Doğrusu | Neden diğeri değil |
|---|---|---|
| `RestTemplate` kaldırıldı | **Henüz `@Deprecated` bile değil** | Niyet açıklandı; 7.1'de işaretlenecek. Yine de yeni kodda `RestClient` kullan |
| `WebClient` kaldırılıyor | **Kaldırılmıyor** | Reaktif ve akış işleri için önerilmeye devam ediyor |
| `connect-timeout` / `read-timeout` | Bağlantı kurulumu / ilk yanıt baytı | Biri ağ erişilebilirliğini, diğeri karşı tarafın hızını sınırlar |
| Timeout varsayılanı makul | **Varsayılan yok** | Sonsuza kadar bekler |
| `RestClient.builder()` ile `Builder` injection'ı aynı | **Değil** | Inject edilen builder Boot'un ayarlarını taşır; sıfırdan kurulan taşımaz |
| `.body()` yeterli | Durum kodu lazımsa **`.toEntity()`** | `.body()` yalnızca gövdeyi verir |
| 4xx ile 5xx aynı | **Farklı** | 4xx senin isteğin hatalı; 5xx karşı taraf bozuk — tepkileri farklı olmalı |

## 🖥 Pratik — kendi servisini kendin çağır

> **Amaç:** Başarı, hata ve timeout yollarını görmek · **Süre:** 20 dk
> **💸 Maliyet:** Yok — dış servis yok, uygulama kendi kendini çağırıyor
> **Ön koşul:** [4.2](4.2-exception-handling.md)'deki kontrolcü ve hata işleyici duruyor olmalı.

### Adım 1 — Çağıran bileşeni yaz

`tr/loncademy/siparis/DisServisDenemesi.java`:

```java
package tr.loncademy.siparis;

import org.springframework.boot.CommandLineRunner;
import org.springframework.stereotype.Component;
import org.springframework.web.client.RestClient;
import org.springframework.web.client.RestClientResponseException;

@Component
public class DisServisDenemesi implements CommandLineRunner {

    record Yanit(String no, String urunKodu, int adet) {}

    private final RestClient istemci;

    public DisServisDenemesi(RestClient.Builder kurucu) {      // ← Boot'un kurucusu
        this.istemci = kurucu.baseUrl("http://localhost:8080").build();
    }

    @Override
    public void run(String... args) {
        Yanit y = istemci.get().uri("/siparisler/{no}", "S-1")
                         .retrieve().body(Yanit.class);
        System.out.println("### BASARILI = " + y);

        try {
            istemci.get().uri("/siparisler/yok").retrieve().body(Yanit.class);
            System.out.println("### 404 istisna ATMADI");
        } catch (RestClientResponseException e) {
            System.out.println("### ISTISNA SINIFI = " + e.getClass().getName());
            System.out.println("### DURUM = " + e.getStatusCode());
            System.out.println("### GOVDE = " + e.getResponseBodyAsString());
        }
    }
}
```

`CommandLineRunner`, uygulama hazır olduğunda bir kere çalışan bir arayüzdür — bu deneme
için kullanışlı.

### Adım 2 — Çalıştır

```bash
./mvnw spring-boot:run
```

- [ ] **Kontrol:** `### BASARILI = Yanit[no=S-1, urunKodu=ABC-1, adet=2]`
- [ ] **Kontrol:** `### ISTISNA SINIFI = ...HttpClientErrorException$NotFound`
- [ ] **Kaydet:** `### GOVDE` satırında ne var? ______
      (4.2'de kendi ürettiğin `ProblemDetail` — çağıran taraf onu okuyabiliyor. Hata
      sözleşmesi yazmanın karşılığı tam olarak bu.)

### Adım 3 — Timeout'u ölç

`application.properties`:

```properties
spring.http.clients.connect-timeout=2s
spring.http.clients.read-timeout=1s
```

Kontrolcüye yavaş bir uç nokta ekle:

```java
@GetMapping("/yavas")
public String yavas() throws InterruptedException {
    Thread.sleep(3000);            // 3 saniye — read-timeout'un üstünde
    return "geç geldim";
}
```

`DisServisDenemesi`'ne çağrısını ekle ve çalıştır.

- [ ] **Kontrol:** Bir timeout exception'ı aldın (`ResourceAccessException` ailesinden).
- [ ] **Kaydet:** İstek kaç saniye sonra vazgeçti? ______ (Beklenen: ~1 sn.)
- [ ] Şimdi `read-timeout` satırını **sil** ve tekrar çalıştır: istek 3 saniye bekleyip
      başarıyla döner. **Varsayılan timeout'un olmadığını** böyle görmüş olursun.

### Temizlik

`DisServisDenemesi` ve `/yavas` uç noktasını silebilirsin. Timeout ayarlarını **bırak** —
doğru alışkanlık. `Ctrl+C`.

## Nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — "Bir servis yavaşladı, hepsi çöktü"**
> Timeout yok; thread'ler bekleyerek tükendi.

**Kalıp 2 — `HttpClientErrorException$NotFound`**
> Karşı taraf 404 döndü. `onStatus` ile kendi exception'ına çevir.

**Kalıp 3 — "Ürün kodunda `/` olunca 404 alıyoruz"**
> Adres `+` ile birleştirilmiş. Placeholder kullan.

**Kalıp 4 — "Timeout ayarladık ama çalışmıyor"**
> `RestClient.builder()` ile sıfırdan kurulmuş; Boot'un ayarlarını taşımıyor. `Builder`'ı inject et.

**Kalıp 5 — "Stok servisi çöktü ama biz sipariş almaya devam ettik"**
> Exception yutulmuş; 4xx ile 5xx ayrılmamış.

## 60 saniyelik özet

- Yeni kodda **`RestClient`** kullan. `WebClient` reaktif işler için kalıyor;
  `RestTemplate` **henüz `@Deprecated` değil** ama yeni kodda kullanılmaz.
- Adreste **placeholder** kullan: `.uri("/stoklar/{kod}", kod)` — `+` ile birleştirme.
- `retrieve()` hatayı exception'a çevirir: 4xx → `HttpClientErrorException`,
  5xx → `HttpServerErrorException`; ikisi de `RestClientResponseException` altında.
- `getResponseBodyAsString()` ile karşı tarafın hata gövdesini **okuyabilirsin**.
- `.body()` gövdeyi, **`.toEntity()`** gövde + durum + başlıkları verir.
- ⭐ **Varsayılan timeout yoktur.** `spring.http.clients.connect-timeout` ve
  `read-timeout` ayarla; `connect` her zaman `read`'den küçük.
- **`RestClient.Builder`'ı inject et**, sıfırdan kurma — Boot'un ayarlarını kaybedersin.
- Her dış servis için **ayrı bean**, `@Qualifier` ile seç.
- **4xx ile 5xx'i ayır**; exception'ı `null` döndürerek yutma.
