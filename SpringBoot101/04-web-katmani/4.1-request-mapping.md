# 4.1 — Request mapping ve body binding

> **Alan:** Web katmanı
> **Süre:** ~30 dakika okuma + 20 dakika pratik
> **Test:** [`4.1-test.html`](4.1-test.html) · 14 soru

---

## Neden bu konu

Buraya kadar container'ı (nesneleri kuran ve birbirine bağlayan yapı), bean'leri ve
ayarları öğrendin — hepsi uygulamanın **içi**. Şimdi dışarıya açılıyoruz.

Web katmanının işi tek cümleyle özetlenebilir: **gelen HTTP isteğini bir Java metot
çağrısına, dönen Java nesnesini bir HTTP yanıtına çevirmek.** Bu çeviri sırasında pek çok
karar veriliyor ve o kararları bilmeyen biri, "neden 400 alıyorum?" sorusunu cevaplayamaz.

**Büyük fikir:** `@RestController` metodun bir HTTP uç noktasıdır. Parametreleri istekten
doldurulur, dönüş değeri gövdeye yazılır, ve bu iki çeviri de **sessizce başarısız
olabilir** — bu yüzden doğrulama şart.

---

## 1. En sade hâl

```java
package tr.loncademy.siparis.web;

import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/siparisler")               // ortak önek
public class SiparisKontrolcusu {

    public record Siparis(String no, String urunKodu, int adet) {}

    @GetMapping("/{no}")                     // GET /siparisler/S-100
    public Siparis getir(@PathVariable String no) {
        return new Siparis(no, "ABC-1", 2);
    }
}
```

```bash
curl -i localhost:8080/siparisler/S-100
```

```
HTTP/1.1 200
Content-Type: application/json

{"no":"S-100","urunKodu":"ABC-1","adet":2}
```

`record`'u JSON'a kim çevirdi? Jackson — `spring-boot-starter-webmvc` ile gelen JSON
kütüphanesi. Sen dönüştürme kodu yazmadın.

⚠️ Spring Boot 4'te bu **Jackson 3**'tür: paket `tools.jackson`, `com.fasterxml.jackson`
değil ([2.4](../02-anotasyon-haritasi/2.4-starterlar.md)).

## 2. İstekten değer almanın dört yolu ⭐

| Anotasyon | Nereden okur | Örnek istek |
|---|---|---|
| `@PathVariable` | Adresin içinden | `GET /siparisler/S-100` |
| `@RequestParam` | Sorgu dizesinden | `GET /siparisler?durum=yeni&sayfa=2` |
| `@RequestBody` | İstek gövdesinden (JSON) | `POST` + JSON gövde |
| `@RequestHeader` | Başlıktan | `X-Izleme-No: abc` |

```java
@GetMapping
public List<Siparis> ara(
        @RequestParam(defaultValue = "hepsi") String durum,
        @RequestParam(required = false) Integer sayfa,
        @RequestHeader(value = "X-Izleme-No", required = false) String izleme) {
    ...
}
```

⚠️ **`required = false` yazacaksan tür wrapper olmalı.** `int sayfa` yazıp
`required = false` dersen, parametre gelmediğinde `null`'ı `int`'e atamaya çalışır ve
patlar. `Integer` yaz — ya da `defaultValue` ver.

📌 `defaultValue` yazdığın anda `required` zaten `false` sayılır; ikisini birden yazma.

## 3. Gövde bağlama ve doğrulama ⭐

```java
public record YeniSiparis(@NotBlank String urunKodu, @Min(1) int adet) {}

@PostMapping
public ResponseEntity<Siparis> olustur(@Valid @RequestBody YeniSiparis istek) {
    var s = new Siparis("S-100", istek.urunKodu(), istek.adet());
    return ResponseEntity.created(URI.create("/siparisler/" + s.no())).body(s);
}
```

Geçerli istek — gerçek çıktı:

```
$ curl -i -X POST localhost:8080/siparisler \
    -H 'Content-Type: application/json' -d '{"urunKodu":"ABC-1","adet":2}'

HTTP/1.1 201
Location: /siparisler/S-100
Content-Type: application/json
```

⭐ **`201 Created` + `Location` başlığı**, yeni kaynak üreten uç noktaların doğru
yanıtıdır. `ResponseEntity.created(...)` ikisini birden ayarlar. `200 OK` dönmek yanlış
değil ama eksik: istemci yeni kaynağın adresini öğrenemez.

Geçersiz istek — gerçek çıktı:

```
$ curl -i -X POST localhost:8080/siparisler \
    -H 'Content-Type: application/json' -d '{"urunKodu":"","adet":0}'

HTTP/1.1 400
Content-Type: application/json

{"timestamp":"...","status":400,"error":"Bad Request","path":"/siparisler"}
```

⚠️ **`@Valid` yazmayı unutursan** bu 400 hiç gelmez: `urunKodu=""` ve `adet=0` sorunsuz
içeri girer. Kısıtlar `record`'da duruyor olabilir ama **onları çalıştıran şey
`@Valid`'dir** — [3.2](../03-yapilandirma/3.2-configuration-properties.md)'deki
`@Validated` ile aynı aileden bir tuzak: *doğrulama koyduğunu sanmak, koymamış olmak.*

> 📌 Yukarıdaki 400 yanıtının gövdesine dikkat: hangi alanın neden geçersiz olduğunu
> **söylemiyor.** İstemci "bir şey yanlış" bilgisinden fazlasını alamıyor. Bunu
> [4.2](4.2-exception-handling.md)'de düzelteceğiz.

## 4. Eşleme anotasyonları

| Kısayol | Karşılığı |
|---|---|
| `@GetMapping` | `@RequestMapping(method = GET)` |
| `@PostMapping` | `@RequestMapping(method = POST)` |
| `@PutMapping` / `@PatchMapping` / `@DeleteMapping` | … |

Sınıf düzeyindeki `@RequestMapping("/siparisler")` metotlardaki yolla **birleşir**.

⚠️ **Eşleşmeyen metot 405 verir**, 404 değil — gerçek çıktı:

```
$ curl -i -X DELETE localhost:8080/siparisler/1

HTTP/1.1 405
Allow: GET
```

`Allow: GET` başlığı, o adresin hangi metotları kabul ettiğini söyler. Bir uç noktayla
uğraşırken bu başlık, "adres mi yanlış, metot mu yanlış" sorusunu tek bakışta cevaplar:

| Aldığın | Anlamı |
|---|---|
| **404** | Bu adres **hiç** eşleşmiyor |
| **405** + `Allow:` | Adres doğru, **metot** yanlış |

---

## 5. Dönüş türü ne olmalı

| Dönüş | Ne zaman |
|---|---|
| Nesne (`Siparis`) | En sade durum — `200 OK` + JSON gövde |
| `ResponseEntity<T>` | Durum kodunu ya da başlığı **sen** belirleyeceksen |
| `void` | Gövdesiz yanıt — `200 OK` |
| `List<T>` / `Map<K,V>` | JSON dizi/nesne |

⚠️ **Varlık (entity) sınıfını doğrudan döndürme.** Veritabanı sınıfını JSON'a çevirirsen:
- Veritabanı şeman dış dünyaya sızar,
- Bir alan eklediğinde istemcilere haber vermeden API'yi değiştirmiş olursun,
- JPA kullanıyorsan tembel yüklenen alanlar beklenmedik sorgular tetikler (**201**).

Ayrı bir **DTO** (Data Transfer Object — dışarıya ne verdiğini açıkça listeleyen ayrı
sınıf) kullan; yukarıdaki `Siparis` ve `YeniSiparis` `record`'ları tam olarak bunlar.

## 6. Yanlış hâlleri

### ❌ Hata 1 — `@Valid` unutmak

```java
@PostMapping
public ResponseEntity<Siparis> olustur(@RequestBody YeniSiparis istek) {   // ← @Valid yok
```

Boş `urunKodu` ve `adet=0` içeri girer, `201` dönersin, veritabanına çöp yazarsın.
✅ **Doğrusu:** `@Valid @RequestBody`.

### ❌ Hata 2 — `Content-Type` başlığını unutmak

```bash
curl -X POST localhost:8080/siparisler -d '{"urunKodu":"ABC-1","adet":2}'
```

`curl`, `-H` verilmezse `application/x-www-form-urlencoded` gönderir ve **415 Unsupported
Media Type** alırsın. Kodunda hata yoktur; istemcinin başlığı eksiktir.

✅ **Doğrusu:** `-H 'Content-Type: application/json'`

### ❌ Hata 3 — `int` + `required = false`

```java
@RequestParam(required = false) int sayfa      // ← parametre gelmezse patlar
```

✅ **Doğrusu:** `Integer sayfa` ya da `@RequestParam(defaultValue = "1") int sayfa`.

### ❌ Hata 4 — varlık sınıfını döndürmek

```java
@GetMapping("/{no}")
public SiparisVarligi getir(@PathVariable String no) { ... }   // ← veritabanı sınıfı
```

✅ **Doğrusu:** Bir DTO `record`'una çevir.

## Sık karıştırılanlar — tek tabloda

| Karışan | Doğrusu | Neden diğeri değil |
|---|---|---|
| 404 / 405 | 404 = adres yok; **405 = adres var, metot yanlış** | 405 yanıtındaki `Allow:` başlığı hangi metotların kabul edildiğini söyler |
| `@RequestParam` / `@PathVariable` | Sorgu dizesi / adresin içi | `?durum=yeni` ile `/siparisler/S-100` farklı yerler |
| `@Valid` isteğe bağlı | **Zorunlu** | Kısıtlar `@Valid` olmadan çalışmaz — sessizce |
| 400 / 415 | 400 = gövde geçersiz; **415 = `Content-Type` desteklenmiyor** | 415'te gövdeye hiç bakılmamıştır |
| Nesne döndürmek yeter | Yeni kaynakta **`201` + `Location`** | `200` istemciye yeni kaynağın adresini vermez |
| Varlık döndürmek pratik | **DTO döndür** | Veritabanı şeması API sözleşmesine dönüşür |
| `required=false` + `int` | `Integer` ya da `defaultValue` | `null` ilkel türe atanamaz |

## 🖥 Pratik — uç noktayı kur ve dört yanıtı da gör

> **Amaç:** 201, 400, 405 ve 415'i kendi elinle üretmek · **Süre:** 20 dk
> **💸 Maliyet:** Yok

### Adım 1 — Kontrolcüyü yaz

`tr/loncademy/siparis/web/SiparisKontrolcusu.java`:

```java
package tr.loncademy.siparis.web;

import jakarta.validation.Valid;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;
import java.net.URI;

@RestController
@RequestMapping("/siparisler")
public class SiparisKontrolcusu {

    public record YeniSiparis(@NotBlank String urunKodu, @Min(1) int adet) {}
    public record Siparis(String no, String urunKodu, int adet) {}

    @GetMapping("/{no}")
    public Siparis getir(@PathVariable String no) {
        return new Siparis(no, "ABC-1", 2);
    }

    @PostMapping
    public ResponseEntity<Siparis> olustur(@Valid @RequestBody YeniSiparis istek) {
        var s = new Siparis("S-100", istek.urunKodu(), istek.adet());
        return ResponseEntity.created(URI.create("/siparisler/" + s.no())).body(s);
    }
}
```

`./mvnw spring-boot:run`

### Adım 2 — Dört yanıtı üret

```bash
# 1) 201 Created
curl -i -X POST localhost:8080/siparisler \
  -H 'Content-Type: application/json' -d '{"urunKodu":"ABC-1","adet":2}'

# 2) 400 Bad Request (doğrulama)
curl -i -X POST localhost:8080/siparisler \
  -H 'Content-Type: application/json' -d '{"urunKodu":"","adet":0}'

# 3) 405 Method Not Allowed
curl -i -X DELETE localhost:8080/siparisler/1

# 4) 415 Unsupported Media Type (Content-Type yok)
curl -i -X POST localhost:8080/siparisler -d '{"urunKodu":"ABC-1","adet":2}'
```

- [ ] **Kontrol (1):** `201` ve `Location: /siparisler/S-100`
- [ ] **Kontrol (2):** `400`
- [ ] **Kontrol (3):** `405` ve `Allow: GET` başlığı
- [ ] **Kontrol (4):** `415`
- [ ] **Kaydet:** 2. yanıtın gövdesi hangi alanın neden geçersiz olduğunu söylüyor mu? ______
      (Beklenen: hayır. [4.2](4.2-exception-handling.md)'de düzelteceğiz.)

### Adım 3 — Doğrulamayı sessizce kapat

`@Valid` anotasyonunu sil, yeniden çalıştır ve 2. isteği tekrarla.

- [ ] **Kontrol:** Artık `201` alıyorsun — boş `urunKodu` ve `adet=0` ile.
      Doğrulama yok, hata da yok. `@Valid`'i geri koy.

### Temizlik

Kontrolcüyü bırak — 4.2 ve 4.3'te üstüne ekleyeceğiz. `Ctrl+C`.

## Nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — `415 Unsupported Media Type`**
> İstemci `Content-Type: application/json` göndermiyor. Sunucu kodunda sorun yok.

**Kalıp 2 — "Geçersiz veri veritabanına yazılıyor"**
> `@Valid` unutulmuş.

**Kalıp 3 — `405` + `Allow:` başlığı**
> Adres doğru, HTTP metodu yanlış.

**Kalıp 4 — "API'ye alan ekledik, istemciler bozuldu"**
> Varlık sınıfı doğrudan döndürülüyor; DTO yok.

**Kalıp 5 — "`?sayfa=` göndermeyince 500 alıyorum"**
> `int` + `required = false`. `Integer` ya da `defaultValue` kullan.

## 60 saniyelik özet

- `@RestController` metodu = HTTP uç noktası. Parametreler istekten dolar, dönüş gövdeye yazılır.
- Dört kaynak: `@PathVariable`, `@RequestParam`, `@RequestBody`, `@RequestHeader`.
- ⭐ **`@Valid` olmadan kısıtlar çalışmaz** — sessizce.
- Yeni kaynak üretiyorsan **`201 Created` + `Location`** dön: `ResponseEntity.created(...)`.
- **404 = adres yok. 405 = metot yanlış** (+ `Allow:` başlığı hangilerinin geçerli olduğunu söyler).
- **415** = `Content-Type` eksik/desteklenmiyor; gövdeye hiç bakılmamıştır.
- `required = false` ile ilkel tür kullanma — `Integer` ya da `defaultValue`.
- **Varlık sınıfını döndürme, DTO döndür.**
- Varsayılan 400 yanıtı **hangi alanın hatalı olduğunu söylemez** — 4.2'de düzeltiyoruz.
