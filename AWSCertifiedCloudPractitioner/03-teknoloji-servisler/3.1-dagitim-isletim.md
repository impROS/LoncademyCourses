## Neden bu konu

Bu konu "AWS ile nasıl konuşurum ve işimi nasıl kurarım" sorusunu cevaplar. Üç soru kümesi:

## 1. AWS'e erişim yolları

| Yol | Ne | Ne zaman |
|---|---|---|
| **AWS Management Console** | Tarayıcıdaki grafik arayüz | Öğrenirken, keşfederken, tek seferlik işlerde |
| **AWS CLI** | Komut satırı aracı (`aws s3 ls`) | Betikleme, otomasyon, tekrarlı işler |
| **AWS SDK** | Programlama dili kütüphaneleri (Java, Python/boto3, JavaScript, Go, .NET...) | Uygulama içinden AWS servisi çağırma |
| **AWS API** | Hepsinin altındaki HTTPS arayüzü | Doğrudan çağrı; CLI ve SDK aslında bunu çağırır |
| **AWS CloudShell** | Tarayıcıda çalışan, kimliği hazır gelen terminal | Kurulum yapmadan CLI kullanmak |
| **AWS Tools for PowerShell** | PowerShell cmdlet'leri | Windows ortamları |

> Hepsi aynı **API**'ye gider, hepsi **IAM** tarafından yetkilendirilir ve hepsi **CloudTrail**'e loglanır.

---

## 2. Infrastructure as Code (IaC) — AWS CloudFormation

**Ne yapar:** Altyapını **JSON veya YAML şablonu** olarak yazarsın; CloudFormation onu okuyup kaynakları
oluşturur, günceller ve siler. Oluşan kaynak grubuna **stack** denir.

**Faydaları:**
- **Tekrarlanabilirlik:** Aynı şablonla dev/test/prod ortamlarını birebir kurarsın
- **Sürüm kontrolü:** Altyapı da kod gibi Git'te durur
- **Otomatik geri alma (rollback):** Bir kaynak oluşamazsa CloudFormation **her şeyi geri alır**
- **Toplu silme:** Stack'i silersin, içindeki tüm kaynaklar gider (temizlik için birebir!)
- **Ücretsiz** — sadece oluşturduğu kaynakların ücretini ödersin

Ek kavramlar: **StackSets** (birden çok hesap/Region'a aynı stack), **Change Sets** (uygulamadan önce farkı gör),
**AWS CDK** (altyapıyı gerçek bir programlama diliyle yazıp CloudFormation şablonuna dönüştürme).

> Refleks: "infrastructure as code", "repeatable environments", "template" → **CloudFormation**

---

## 3. AWS Elastic Beanstalk

**Ne yapar:** Uygulama kodunu yüklersin (JAR, ZIP, Docker imajı); Beanstalk **EC2, Auto Scaling, Load Balancer,
izleme ve kapasiteyi** senin yerine kurar ve yönetir.

- Desteklediği platformlar: Java, .NET, PHP, Node.js, Python, Ruby, Go, Docker
- **Altyapı yine senin hesabında görünür** (EC2'leri görebilir, SSH ile bağlanabilirsin)
- **Ücretsizdir** — altında oluşan kaynaklar (EC2, ELB) ücretlidir
- Kolay dağıtım seçenekleri: all-at-once, rolling, blue/green

| | **CloudFormation** | **Elastic Beanstalk** |
|---|---|---|
| Girdi | Altyapı **şablonu** | Uygulama **kodu** |
| Kontrol | Tam kontrol, her kaynağı sen tanımlarsın | AWS uygun altyapıyı seçer |
| Kullanım | Her tür altyapı | Web uygulaması / API dağıtımı |
| Refleks kelimesi | "infrastructure as code", "template" | "just deploy my application code", "PaaS" |

> Bunlarla akraba diğer araçlar: **AWS CodePipeline / CodeBuild / CodeDeploy** (CI/CD), **AWS Amplify** (web/mobil ön yüz),
> **AWS App Runner** (konteynerden doğrudan yönetilen web servisi), **AWS Systems Manager** (işletim/otomasyon).

## 4. Dağıtım (deployment) modelleri

| Model | Tanım | AWS'te karşılığı |
|---|---|---|
| **Cloud / all-in cloud** | Her şey bulutta çalışır | Klasik AWS kullanımı |
| **Hybrid** | Bir kısmı bulutta, bir kısmı şirket içinde; ikisi bağlı | Direct Connect / VPN + **Outposts**, **Storage Gateway** |
| **On-premises / private cloud** | Her şey kendi veri merkezinde (sanallaştırma ile) | **AWS Outposts** ile AWS servisleri yerinde |

### AWS Outposts
- **AWS'in fiziksel donanımını senin veri merkezine** koyar.
- Aynı AWS API'leri, aynı servisler (EC2, EBS, S3 on Outposts, RDS, ECS/EKS) **yerinde** çalışır.
- Ne zaman: **çok düşük gecikme** gerektiren yerel işleme, **veri yerelleştirme** zorunluluğu, yerel sistemlere bağımlılık.

> Refleks: "run AWS services in my own data center" → **Outposts**

### Diğer uç/edge seçenekleri
| Servis | Ne için |
|---|---|
| **AWS Local Zones** | Büyük şehirlere yakın, **tek haneli milisaniye** gecikme gerektiren uygulamalar |
| **AWS Wavelength** | **5G mobil ağların** içinde çalışan, ultra düşük gecikmeli uygulamalar |
| **AWS Snow ailesi** | Bağlantısız/uzak sahada veri toplama ve işleme |

---

## 5. Bağlantı seçenekleri

| Seçenek | Nedir | Ne zaman |
|---|---|---|
| **İnternet üzerinden (public endpoint)** | Varsayılan; HTTPS ile AWS API'lerine erişim | Çoğu senaryo |
| **AWS Site-to-Site VPN** | Şirket ağı ile VPC arasında **internet üzerinden şifreli tünel** | Hızlı kurulur, ucuzdur, internet dalgalanmasına tabidir |
| **AWS Direct Connect** | AWS'e **özel fiziksel hat** (internet kullanılmaz) | **Tutarlı düşük gecikme**, yüksek/kararlı bant genişliği, büyük veri akışı. Kurulumu haftalar sürer, pahalıdır |
| **AWS PrivateLink / VPC endpoint** | Bir AWS servisine veya başka bir VPC'deki servise **internete çıkmadan, AWS omurgası üzerinden** erişim | "traffic must not traverse the public internet" |
| **VPC Peering** | İki VPC'yi birbirine bağlama (1'e 1) | Az sayıda VPC |
| **Transit Gateway** | Çok sayıda VPC ve şirket içi ağı **tek merkezden** bağlama (hub) | Onlarca VPC olduğunda |

> ⭐ **VPN vs Direct Connect:** *"encrypted connection over the internet, set up quickly"* → **VPN.**
> *"dedicated private connection, consistent bandwidth, does not use the internet"* → **Direct Connect.**
> Not: Direct Connect tek başına şifreli değildir; şifreleme isteniyorsa **Direct Connect + VPN** birlikte kullanılır.

## 6. Sık karıştırılanlar

| Soruda geçen | Doğru cevap |
|---|---|
| "define infrastructure in a YAML/JSON template" | **CloudFormation** |
| "upload application code, AWS handles capacity and load balancing" | **Elastic Beanstalk** |
| "automate tasks from a script / terminal" | **AWS CLI** |
| "call AWS from Python application code" | **AWS SDK** |
| "browser-based shell with credentials preconfigured" | **CloudShell** |
| "run AWS infrastructure inside my own data center" | **Outposts** |
| "encrypted tunnel over the internet to my VPC" | **Site-to-Site VPN** |
| "dedicated, private, consistent network connection" | **Direct Connect** |
| "access S3 without traffic leaving the AWS network" | **VPC endpoint / PrivateLink** |
| "connect hundreds of VPCs centrally" | **Transit Gateway** |
| "single-digit millisecond latency in a specific metro area" | **Local Zones** |
| "ultra-low latency over 5G networks" | **Wavelength** |

## 🖥 Pratik — CLI ve CloudFormation ile altyapı kur/yık (30 dk)

**💸 Maliyet:** Bu pratikte oluşturulan tek kaynak boş bir **S3 bucket**'tır (boş bucket ücretsizdir).
Sonunda stack'i silerek her şeyi kaldıracaksın. **CloudFormation ve CloudShell ücretsizdir.**

### A. CLI ile keşif (CloudShell)
1. Konsolda sağ üstteki **CloudShell** ikonuna tıkla.
2. Sırayla çalıştır ve çıktıları oku:

```bash
aws sts get-caller-identity
```
```bash
aws s3 ls
```
```bash
aws ec2 describe-instances --query "Reservations[].Instances[].[InstanceId,State.Name]" --output table
```
Boş dönmeli — çalışan instance yoksa temizliklerin doğru demektir. ✅

```bash
aws iam list-users --output table
```

- [ ] **Gözlem:** Aynı işleri konsolda tıklayarak da yapabilirdin. CLI = **otomasyon**; konsol = **keşif**.

### B. CloudFormation şablonu yaz
3. CloudShell'de bir şablon dosyası oluştur:

```bash
cat > ~/ilk-stack.yaml <<'YAML'
AWSTemplateFormatVersion: '2010-09-09'
Description: CLF-C02 ilk CloudFormation denemesi

Parameters:
  BucketSuffix:
    Type: String
    Description: Bucket adina eklenecek benzersiz sonek

Resources:
  CalismaBucket:
    Type: AWS::S3::Bucket
    Properties:
      BucketName: !Sub "clfc02-cfn-${BucketSuffix}"
      PublicAccessBlockConfiguration:
        BlockPublicAcls: true
        BlockPublicPolicy: true
        IgnorePublicAcls: true
        RestrictPublicBuckets: true
      Tags:
        - Key: Amac
          Value: clfc02-calisma

Outputs:
  BucketAdi:
    Description: Olusturulan bucket adi
    Value: !Ref CalismaBucket
YAML
```

4. Şablonun geçerli olup olmadığını doğrula:
```bash
aws cloudformation validate-template --template-body file://~/ilk-stack.yaml
```
Hata yoksa parametre listesi ve açıklama döner. ✅

### C. Stack'i oluştur
5. Benzersiz bir sonek belirle (adının baş harfleri + rastgele sayı) ve stack'i başlat:
```bash
aws cloudformation create-stack \
  --stack-name clfc02-ilk-stack \
  --template-body file://~/ilk-stack.yaml \
  --parameters ParameterKey=BucketSuffix,ParameterValue=ra20260823
```
6. Durumu izle:
```bash
aws cloudformation describe-stacks --stack-name clfc02-ilk-stack --query "Stacks[0].StackStatus"
```
`CREATE_IN_PROGRESS` → `CREATE_COMPLETE` olmalı.

7. **Konsolda gör:** `CloudFormation` → **Stacks** → `clfc02-ilk-stack`:
   - **Events** sekmesi: kaynakların hangi sırayla oluştuğu
   - **Resources** sekmesi: oluşan S3 bucket
   - **Outputs** sekmesi: şablondaki `BucketAdi` çıktısı
   - **Template** sekmesi: şablonun kendisi

8. `S3` konsoluna git — bucket **orada**. Ama sen onu elle oluşturmadın: **kod oluşturdu.**

### D. Değişikliği kodla yap (IaC'nin asıl faydası)
9. Şablonda `Value: clfc02-calisma` etiketini `Value: clfc02-guncellendi` yap:
```bash
sed -i 's/clfc02-calisma/clfc02-guncellendi/' ~/ilk-stack.yaml
```
10. Stack'i güncelle:
```bash
aws cloudformation update-stack \
  --stack-name clfc02-ilk-stack \
  --template-body file://~/ilk-stack.yaml \
  --parameters ParameterKey=BucketSuffix,UsePreviousValue=true
```
11. S3'te bucket → **Properties** → **Tags** bölümünde etiketin değiştiğini gör.

- [ ] **Gözlem:** Altyapıyı konsolda tıklayarak değil, **şablonu değiştirerek** güncelledin. Bu, **infrastructure as code**'dur.

### E. Elastic Beanstalk'ı incele (kurma)
12. Konsol araması → `Elastic Beanstalk` → **Create application** ekranını aç.
13. **Platform** listesine bak (Java, Node.js, Python, Docker...). **Application code** bölümünde
    "Sample application" seçeneğini gör.
14. **💸 Create'e BASMA** — bir EC2, bir Load Balancer ve Auto Scaling grubu açar (ELB ücretlidir). **Cancel** ile çık.

- [ ] **Gözlem:** CloudFormation'a **şablon** verdin; Beanstalk'a **kod** verirdin. Fark bu.

### 💸 Temizlik — tek komut
15. ```bash
aws cloudformation delete-stack --stack-name clfc02-ilk-stack
```
16. Doğrula:
```bash
aws cloudformation describe-stacks --stack-name clfc02-ilk-stack
```
`Stack with id ... does not exist` hatası alman **doğru sonuçtur.** ✅
17. `S3` konsolunu yenile — bucket **gitti.**

> **Bu neden önemli:** IaC'nin en büyük pratik faydası budur — tek komutla **her şeyi geri alabilmek.**
> Sürpriz fatura riskini de bu şekilde yönetirsin.

## Sınavda nasıl sorulur — örnek kalıplar

**Kalıp 1**
> *A company wants to define and version its AWS infrastructure using YAML templates so environments can be recreated identically.* → **AWS CloudFormation**

**Kalıp 2**
> *A developer wants to upload application code and have AWS provision and manage the underlying capacity, load balancing and scaling.* → **AWS Elastic Beanstalk**

**Kalıp 3**
> *A company requires a dedicated network connection to AWS that does not traverse the public internet and delivers consistent performance.* → **AWS Direct Connect**

**Kalıp 4**
> *An application must access Amazon S3 without traffic leaving the AWS network.* → **VPC endpoint (AWS PrivateLink)**

**Kalıp 5**
> *A company needs to run AWS compute and storage services inside its own data center for low-latency processing.* → **AWS Outposts**

## 60 saniyelik özet

- **Erişim:** Console (keşif) · CLI (betik) · SDK (uygulama kodu) · API (altyapı) · CloudShell (hazır terminal).
- **CloudFormation:** şablon → stack; tekrarlanabilir, rollback'li, ücretsiz; **stack silinince her şey gider.**
- **Elastic Beanstalk:** kodu ver, altyapıyı AWS kursun (PaaS).
- **Modeller:** cloud · hybrid · on-premises. **Outposts** = AWS donanımı senin veri merkezinde.
- **VPN** = internet üzerinden şifreli, hızlı kurulur · **Direct Connect** = özel hat, tutarlı, pahalı/yavaş kurulum.
- **PrivateLink/VPC endpoint** = internete çıkmadan servise erişim · **Transit Gateway** = çok VPC'yi merkezden bağla.
