## Neden bu konu

Cloud Practitioner'da ağ **derinlemesine** sorulmaz — CIDR hesabı, routing tablosu yazımı yoktur.
Sorular **"bu bileşen ne işe yarar"** düzeyindedir: VPC, subnet, Internet Gateway, NAT Gateway,
Route 53, CloudFront, API Gateway, Direct Connect, VPN, PrivateLink.

---

## 1. Amazon VPC (Virtual Private Cloud)

**Ne:** AWS içinde sana ayrılmış, **mantıksal olarak izole** sanal ağ. Kendi IP aralığını (CIDR),
alt ağlarını, yönlendirme tablonu ve güvenlik kurallarını sen tanımlarsın.

- VPC **bir Region'a** aittir ve o Region'ın **AZ'lerine yayılabilir.**
- Her hesapta her Region'da bir **default VPC** hazır gelir.

### Subnet (alt ağ)
VPC'nin **bir AZ içindeki** bir dilimi. İkiye ayrılır:

| | **Public subnet** | **Private subnet** |
|---|---|---|
| Tanımı | Route table'ında **Internet Gateway'e** giden bir yol var | İnternete doğrudan yolu yok |
| İçinde ne olur | Web sunucusu, load balancer, bastion | Veritabanı, uygulama sunucusu |
| İnternete çıkış | Doğrudan (IGW üzerinden) | **NAT Gateway** üzerinden (sadece giden yönde) |

> ⭐ Bir subnet'i "public" yapan şey **adı değil, route table'ıdır.**

### Ağ bileşenleri

| Bileşen | Ne yapar |
|---|---|
| **Route table** | Trafiğin nereye gideceğini belirleyen kurallar |
| **Internet Gateway (IGW)** | VPC'yi internete bağlar — **çift yönlü** |
| **NAT Gateway** | Private subnet'teki kaynakların **internete çıkmasını** sağlar, ama internetten **içeri girilmesine izin vermez** (yama indirme, API çağırma). 💸 **Saatlik + veri işleme ücreti vardır** |
| **Security Group** | Instance seviyesinde **stateful** güvenlik duvarı (sadece allow) |
| **Network ACL** | Subnet seviyesinde **stateless** filtre (allow + deny) |
| **Elastic Network Interface (ENI)** | Sanal ağ kartı |
| **Elastic IP** | Statik public IPv4 adresi. 💸 **Bağlı olmadığında ücretlenir** |
| **VPC endpoint / PrivateLink** | AWS servislerine **internete çıkmadan** erişim |
| **VPC Peering** | İki VPC'yi bire bir bağlar (geçişli değildir) |
| **Transit Gateway** | Çok sayıda VPC + şirket içi ağı **merkezî hub** ile bağlar |
| **VPC Flow Logs** | VPC'deki ağ trafiği meta verisini kaydeder (kim kiminle konuştu) |

**Tipik 3 katmanlı mimari:**
`Internet → IGW → public subnet (ALB) → private subnet (uygulama sunucuları) → private subnet (RDS)`

## 2. Amazon Route 53

**Ne:** AWS'in yönetilen **DNS** servisi. Adı 53, DNS'in çalıştığı porttan gelir.

Üç ana işi:
1. **Domain kaydı** (alan adı satın alma)
2. **DNS yönlendirme** (alan adını IP'ye/servise çevirme)
3. **Sağlık kontrolü (health check)** ve arızalı hedeften uzaklaştırma

### Yönlendirme politikaları (temel düzeyde bilmen yeter)
| Politika | Ne yapar |
|---|---|
| **Simple** | Tek hedefe yönlendirir |
| **Weighted** | Trafiği yüzdelere göre böler (A/B testi, kademeli geçiş) |
| **Latency-based** | Kullanıcıyı **en düşük gecikmeli** Region'a yönlendirir |
| **Failover** | Birincil arızalanınca yedeğe geçer |
| **Geolocation** | Kullanıcının **konumuna** göre yönlendirir (içerik yerelleştirme, mevzuat) |
| **Geoproximity** | Coğrafi yakınlık + ağırlık (bias) |
| **Multivalue answer** | Birden fazla sağlıklı IP döner |

> Refleks: "route users to the Region with the lowest latency" → **latency-based routing**
> "route European users to the EU site" → **geolocation routing**

---

## 3. Amazon CloudFront

**Ne:** AWS'in **CDN**'i (Content Delivery Network). İçeriği **edge location**'larda önbellekler.

- Faydaları: **düşük gecikme**, kaynak sunucu yükünün azalması, **çıkış (data transfer out) maliyetinin düşmesi**
- Kaynak (origin): S3, ALB, EC2, hatta AWS dışı bir sunucu
- **AWS Shield Standard**, **AWS WAF** ve **ACM sertifikaları** ile entegre çalışır
- Statik **ve** dinamik içeriği hızlandırır
- **Lambda@Edge / CloudFront Functions:** kodun edge'de çalışması

> ⭐ **CloudFront vs Global Accelerator:** Önbelleklenebilir HTTP içerik → **CloudFront.**
> TCP/UDP, statik IP, hızlı bölgesel failover → **Global Accelerator.**

## 4. Bağlantı seçenekleri (3.1'in tekrarı — sınavda tekrar tekrar çıkar)

| Seçenek | Nedir | Anahtar kelime |
|---|---|---|
| **Site-to-Site VPN** | İnternet üzerinden **şifreli tünel** | "encrypted", "quick to set up", "lower cost" |
| **Direct Connect** | AWS'e **özel fiziksel hat** | "dedicated", "consistent", "does not use the internet", "high bandwidth" |
| **PrivateLink / VPC endpoint** | Servise **AWS ağı üzerinden** erişim | "traffic must not traverse the public internet" |
| **VPC Peering** | İki VPC arasında bire bir bağlantı | "connect two VPCs" |
| **Transit Gateway** | Merkezî hub | "hundreds of VPCs", "central hub" |
| **Client VPN** | Tekil kullanıcıların (dizüstü) VPC'ye bağlanması | "remote employees connect to VPC" |

> ⚠️ **Direct Connect kurulumu haftalar sürer** ve pahalıdır. Soruda *"as quickly as possible"* geçiyorsa
> cevap genelde **VPN**'dir; sonradan Direct Connect'e geçilir.

---

## 5. API Gateway

**Ne:** REST, HTTP ve WebSocket **API'leri oluşturma, yayınlama ve yönetme** servisi.

- **Serverless** — sunucu yönetmezsin
- Lambda, EC2, HTTP uç noktaları veya diğer AWS servisleriyle entegre olur
- Sağladıkları: yetkilendirme (Cognito/IAM), **throttling / rate limiting**, önbellekleme, sürümleme, izleme
- Tipik serverless mimari: **API Gateway → Lambda → DynamoDB**

## 🖥 Pratik — Kendi VPC'ni kur ve haritasını oku (30 dk)

**💸 Maliyet:** VPC, subnet, route table ve Internet Gateway **ücretsizdir.**
**NAT Gateway ÜCRETLİDİR (~32 USD/ay)** — sihirbazda **"NAT gateways: None"** seçeceksin. Bunu atlama.

### A. Önce varsayılan VPC'yi incele
1. Konsol araması → `VPC` → **Your VPCs**. `default` VPC'yi gör, **IPv4 CIDR**'ını not et (genelde `172.31.0.0/16`).
2. Sol menü → **Subnets**: her AZ için bir subnet olduğunu gör. **Availability Zone** sütununa bak.
3. Sol menü → **Route tables** → varsayılan route table'a tıkla → **Routes** sekmesi:
   - `172.31.0.0/16 → local` (VPC içi trafik)
   - `0.0.0.0/0 → igw-xxxx` (**internete çıkış**)
   - **İşte bir subnet'i "public" yapan satır budur.**
4. Sol menü → **Internet gateways**: varsayılan VPC'ye bağlı bir IGW var.

### B. Kendi VPC'ni oluştur (NAT olmadan)
5. `VPC` → **Create VPC**
6. **VPC settings:** `VPC and more` seç (sihirbaz)
7. Ayarlar:
   - **Name tag auto-generation:** `clfc02`
   - **IPv4 CIDR block:** `10.10.0.0/16`
   - **Number of Availability Zones (AZs):** `2`
   - **Number of public subnets:** `2`
   - **Number of private subnets:** `2`
   - **💸 NAT gateways:** **`None`** ← **BUNU MUTLAKA None YAP**
   - **VPC endpoints:** `None`
8. Sağdaki **önizleme diyagramına dik dik bak**: VPC → 2 AZ → 4 subnet → route table'lar → IGW.
   **Bu diyagram sınavda anlatılan mimarinin ta kendisidir.**
9. **Create VPC** → oluşum ekranını izle.

### C. Oluşan yapıyı oku
10. **Your VPCs** → `clfc02-vpc` → **Resource map** sekmesini aç. Görsel harita:
    hangi subnet hangi route table'a, hangi route table IGW'ye bağlı — hepsi burada.
11. **Subnets** → `clfc02-subnet-public1-...` seç → **Route table** sekmesi:
    `0.0.0.0/0 → igw-...` satırını gör. ✅ **Public.**
12. `clfc02-subnet-private1-...` seç → **Route table** sekmesi:
    **`0.0.0.0/0` satırı YOK**, sadece `local` var. ✅ **Private.**

- [ ] **Gözlem:** İki subnet arasındaki tek fark **route table**'daki bir satır.

### D. Güvenlik katmanlarını gör
13. Sol menü → **Security groups**: yeni VPC'nin `default` security group'unu gör. **Inbound rules:**
    sadece aynı security group'tan gelen trafiğe izin var.
14. Sol menü → **Network ACLs**: yeni VPC'nin NACL'i, `100 Allow` ve `* Deny` kuralları ile. (2.4'ten hatırla.)

### E. Route 53 ve CloudFront'a bak (oluşturma)
15. Konsol araması → `Route 53` → **Hosted zones**.
    **💸 Hosted zone oluşturma** — aylık 0,50 USD ücreti vardır. Sadece **Create hosted zone** ekranını aç,
    **Cancel** ile çık.
16. `Route 53` → **Health checks** ekranını gör (sağlık kontrolü + failover mantığı).
17. Konsol araması → `CloudFront` → **Create distribution** ekranını aç:
    - **Origin domain** alanında S3 bucket'larının ve load balancer'ların listelendiğini gör
    - **Viewer protocol policy** → `Redirect HTTP to HTTPS` seçeneğini gör
    - **Web Application Firewall (WAF)** bölümünü gör
    - **Cancel** ile çık.

### 💸 Temizlik — ŞART
18. `VPC` → **Your VPCs** → `clfc02-vpc` seç → **Actions** → **Delete VPC**.
19. Silme ekranı, birlikte silinecek kaynakları listeler (subnet'ler, route table'lar, IGW).
    `delete` yazarak onayla.
- [ ] **Kontrol:** Sadece `default` VPC kaldı. NAT Gateway **hiç oluşturulmadı** (💸 kontrol et:
      **NAT gateways** sayfası boş olmalı).
- [ ] **Kontrol:** **Elastic IPs** sayfası boş olmalı.

## Sınavda nasıl sorulur — örnek kalıplar

**Kalıp 1**
> *Which service provides a logically isolated section of the AWS Cloud where a customer can launch resources in a virtual network they define?* → **Amazon VPC**

**Kalıp 2**
> *EC2 instances in a private subnet must download OS patches from the internet but must not be reachable from the internet.* → **NAT Gateway**

**Kalıp 3**
> *A company wants to route users to the AWS Region that provides the lowest latency.* → **Amazon Route 53 latency-based routing**

**Kalıp 4**
> *A media company wants to reduce load times for video files for a global audience.* → **Amazon CloudFront**

**Kalıp 5**
> *Which service lets a company build and manage REST APIs that invoke AWS Lambda functions?* → **Amazon API Gateway**

## 60 saniyelik özet

- **VPC** = izole sanal ağ, bir Region'da, AZ'lere yayılır. **Subnet** = bir AZ'deki dilim.
- **Public subnet**: route table'da IGW var. **Private subnet**: yok.
- **IGW** çift yönlü internet · **NAT Gateway** sadece giden yön (💸 ücretli).
- **Route 53** = DNS + domain + health check; **latency-based**, **geolocation**, **failover**, **weighted** politikaları.
- **CloudFront** = CDN, edge önbellek, WAF/Shield/ACM ile entegre, çıkış maliyetini düşürür.
- **API Gateway** = sunucusuz API katmanı (API Gateway → Lambda → DynamoDB).
- **Peering** 1'e 1 · **Transit Gateway** merkezî hub · **PrivateLink** internete çıkmadan erişim.
- **Flow Logs** = ağ trafiği meta verisi.
