## 1. Yönetilen veritabanı vs EC2'ye kendin kurmak

| | **EC2 üzerine kendin kur** | **Amazon RDS (yönetilen)** |
|---|---|---|
| OS yaması | **Sen** | **AWS** |
| DB motoru yaması | **Sen** | **AWS** |
| Yedekleme | **Sen kurarsın** | **Otomatik** (yapılandırılabilir saklama süresi) |
| Yüksek erişilebilirlik | Kendin kurarsın | **Multi-AZ** tek tıkla |
| Ölçekleme | Manuel | Konsoldan boyut değiştirme, read replica |
| Kontrol | **Tam** (OS'a erişim, özel eklentiler) | Sınırlı (OS'a erişemezsin) |
| Ne zaman | Motorun desteklenmeyen bir sürümü/eklentisi şart | **Neredeyse her zaman** |

> ⭐ Sınav refleksi: **"LEAST operational overhead"** + ilişkisel veritabanı → **Amazon RDS** (veya Aurora).
> EC2'ye kurmak doğru cevap **sadece** "OS seviyesinde erişim gerekiyor" dendiğinde olur.

---

## 2. İlişkisel: Amazon RDS ve Amazon Aurora

### Amazon RDS
Yönetilen ilişkisel veritabanı. Desteklediği motorlar:
**MySQL · PostgreSQL · MariaDB · Oracle · Microsoft SQL Server · Amazon Aurora · IBM Db2**

Özellikleri: otomatik yedekleme ve **point-in-time recovery**, snapshot, otomatik yama, şifreleme (KMS),
Multi-AZ, read replica, **RDS Proxy** (bağlantı havuzu).

### Amazon Aurora
AWS'in bulut için sıfırdan tasarladığı, **MySQL ve PostgreSQL uyumlu** ilişkisel veritabanı.
- MySQL'e göre **~5x**, PostgreSQL'e göre **~3x** performans (AWS'in beyanı)
- Veriyi otomatik olarak **3 AZ'de 6 kopya** halinde tutar
- Depolama **otomatik büyür**
- **Aurora Serverless:** kapasiteyi otomatik ayarlar, kullanılmayan zamanda küçülür → değişken/aralıklı iş yükleri için

### ⭐ Multi-AZ vs Read Replica — sınavın klasiği

| | **Multi-AZ deployment** | **Read replica** |
|---|---|---|
| **Amacı** | **Yüksek erişilebilirlik / felaket dayanıklılığı** | **Okuma performansını artırmak** |
| Kopyalama | **Senkron** | **Asenkron** |
| Standby'a okuma yapılır mı | Klasik Multi-AZ'de **hayır** (sadece yedek bekler) | **Evet**, okuma trafiği alır |
| Arıza durumu | **Otomatik failover** (DNS kaydı standby'a döner) | Otomatik failover yok (elle terfi ettirilir) |
| Farklı Region'da olabilir mi | Aynı Region'ın farklı AZ'lerinde | **Evet**, cross-Region olabilir |

**Ezber cümlesi:**
> **Multi-AZ = ayakta kal. Read Replica = hızlan.**

## 3. NoSQL: Amazon DynamoDB

- **Tamamen yönetilen, sunucusuz, anahtar-değer / doküman** veritabanı.
- **Milisaniye altı (single-digit millisecond)** gecikme, sınırsıza yakın ölçek.
- Sunucu yönetmezsin; kapasite modeli: **On-demand** (kullandığın kadar) veya **Provisioned**.
- **Global Tables:** çok Region'lı, çok yazarlı replikasyon.
- **DynamoDB Accelerator (DAX):** DynamoDB önünde **mikrosaniye** seviyesinde önbellek.
- Şema esnektir; karmaşık JOIN'ler ve ilişkisel sorgular için uygun değildir.

> Refleks: "key-value", "serverless NoSQL", "single-digit millisecond at any scale", "no schema" → **DynamoDB**

---

## 4. Diğer veritabanı servisleri — tek cümlelik tanımlar

| Servis | Türü | Tek cümlelik işi | Tetikleyici |
|---|---|---|---|
| **Amazon ElastiCache** | Bellek içi önbellek | Veritabanı önüne **Redis** veya **Memcached** önbelleği koyar | "reduce database load", "in-memory cache", "microsecond latency" |
| **Amazon MemoryDB** | Bellek içi **veritabanı** | Redis uyumlu, **kalıcı** bellek içi veritabanı | "durable in-memory database" |
| **Amazon Redshift** | **Veri ambarı (OLAP)** | Petabayt ölçeğinde analitik SQL sorguları | "data warehouse", "business intelligence", "complex analytical queries" |
| **Amazon DocumentDB** | Doküman | **MongoDB uyumlu** yönetilen doküman veritabanı | "MongoDB compatible" |
| **Amazon Neptune** | **Graf** | İlişki ağlarını sorgular | "graph database", "social network", "fraud detection relationships", "recommendation engine" |
| **Amazon Keyspaces** | Geniş sütun | **Apache Cassandra** uyumlu | "Cassandra compatible" |
| **Amazon Timestream** | Zaman serisi | IoT/telemetri zaman serisi verisi | "time series", "IoT sensor data" |
| **Amazon RDS Proxy** | Bağlantı havuzu | Veritabanı bağlantılarını havuzlar, dayanıklılığı artırır | "too many database connections from Lambda" |

### OLTP vs OLAP (sınavda geçer)
- **OLTP (Online Transaction Processing):** Çok sayıda küçük işlem — sipariş kaydetme, kullanıcı girişi → **RDS, Aurora, DynamoDB**
- **OLAP (Online Analytical Processing):** Az sayıda, büyük ve karmaşık analiz sorgusu → **Redshift**

## 5. Veritabanı göçü (1.3'ün tekrarı)

| Araç | İşi |
|---|---|
| **AWS DMS** | Kaynak **çalışırken** veritabanını AWS'e taşır (minimum kesinti) |
| **AWS SCT** | **Farklı motora** geçerken şemayı/kodu dönüştürür (Oracle → Aurora PostgreSQL) |

> Aynı motor → **sadece DMS.** Motor değişiyor → **SCT + DMS.**

## 6. Hangi iş yüküne hangi veritabanı? (karar tablosu)

| İhtiyaç | Cevap |
|---|---|
| Klasik ilişkisel uygulama, en az yönetim | **Amazon RDS** |
| Yüksek performanslı, bulut için tasarlanmış ilişkisel | **Amazon Aurora** |
| Değişken/aralıklı ilişkisel iş yükü | **Aurora Serverless** |
| Sunucusuz anahtar-değer, çok yüksek ölçek | **DynamoDB** |
| Veritabanı yükünü azaltacak önbellek | **ElastiCache** |
| Milisaniye altından da hızlı DynamoDB okuması | **DAX** |
| Petabayt ölçeğinde analitik / BI | **Redshift** |
| MongoDB uyumluluğu | **DocumentDB** |
| İlişki ağı, öneri motoru, dolandırıcılık grafikleri | **Neptune** |
| Cassandra uyumluluğu | **Keyspaces** |
| IoT zaman serisi | **Timestream** |
| Okuma performansını artır | **Read replica** |
| Veritabanı ayakta kalsın (otomatik failover) | **Multi-AZ** |
| S3 üzerindeki veriye SQL sorgusu | **Athena** (3.7) |

## 🖥 Pratik — DynamoDB tablosu kur, yaz, oku, sil (30 dk)

**💸 Maliyet:** DynamoDB'nin ücretsiz kullanım katmanı **25 GB depolama** ve önemli miktarda istek içerir.
Bu pratikte birkaç satır yazacaksın — maliyeti **sıfıra yakındır.** Yine de sonunda tabloyu sileceksin.

### A. Tabloyu oluştur
1. Konsol araması → `DynamoDB` → **Tables** → **Create table**
2. **Table name:** `clfc02-notlar`
3. **Partition key:** `konuId` (String)
4. **Sort key:** `tarih` (String) — **Add sort key** ile ekle
5. **Table settings:** `Customize settings` seç →
   **Table class:** `DynamoDB Standard` ·
   **Read/write capacity settings:** **`On-demand`** *(💸 provisioned yerine on-demand seç: kullanmadığında ödeme yok)*
6. **Create table** → durum `Active` olana kadar bekle (birkaç saniye).

### B. Veri yaz (konsoldan)
7. Tabloya gir → **Explore table items** → **Create item**
8. **JSON view**'a geç ve şunu yapıştır → **Create item**:
```json
{
  "konuId": "2.1",
  "tarih": "2026-08-23",
  "baslik": "Paylasilan sorumluluk modeli",
  "skor": 92,
  "tamamlandi": true
}
```
9. Aynı şekilde ikinci bir kayıt ekle:
```json
{
  "konuId": "2.1",
  "tarih": "2026-08-25",
  "baslik": "Paylasilan sorumluluk tekrar",
  "skor": 100,
  "tamamlandi": true
}
```
10. Üçüncüsü farklı bir konu için:
```json
{
  "konuId": "3.3",
  "tarih": "2026-08-26",
  "baslik": "Compute",
  "skor": 78,
  "tamamlandi": false
}
```

### C. Sorgula — Query vs Scan farkını gör
11. **Explore table items** ekranında üstte **Query** seçeneğini işaretle.
    - **Partition key `konuId`** = `2.1` → **Run**
    - Yalnızca `2.1` kayıtları döner. **Query, partition key ile doğrudan gider — hızlı ve ucuzdur.**
12. Şimdi **Scan**'i seç → **Run**.
    - **Tüm tablo** taranır. Büyük tablolarda **yavaş ve pahalıdır.**

- [ ] **Gözlem:** Query hedefli, Scan her şeyi okur. Bu, NoSQL tasarımının temel dersidir.

### D. Aynı işi CLI ile yap
13. CloudShell'i aç:
```bash
aws dynamodb put-item --table-name clfc02-notlar \
  --item '{"konuId":{"S":"3.4"},"tarih":{"S":"2026-08-27"},"baslik":{"S":"Veritabanlari"},"skor":{"N":"88"}}'
```
```bash
aws dynamodb query --table-name clfc02-notlar \
  --key-condition-expression "konuId = :k" \
  --expression-attribute-values '{":k":{"S":"3.4"}}' --output json
```
```bash
aws dynamodb describe-table --table-name clfc02-notlar \
  --query "Table.[TableName,TableStatus,ItemCount,BillingModeSummary.BillingMode]" --output table
```

- [ ] **Gözlem:** Sunucu açmadın, kapasite planlamadın, yama yapmadın. **Serverless veritabanı budur.**

### E. RDS'i incele — Multi-AZ ve read replica'yı gör (kurma 💸)
14. Konsol araması → `RDS` → **Create database** ekranını aç.
15. Şunları **gözlemle, oluşturma**:
   - **Engine options:** MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, **Aurora**
   - **Templates:** Production / Dev-Test / **Free tier**
   - **Availability and durability:** burada **Multi-AZ DB instance** seçeneğini gör →
     *"Creates a standby in a different Availability Zone for failover support"* açıklamasını **oku.**
   - **Backup** bölümü: **Backup retention period** (otomatik yedek saklama süresi) ve **point-in-time recovery**
   - **Encryption:** KMS anahtarı seçimi
16. **💸 "Create database"e BASMA** → sayfadan çık. (Kurulum 10+ dakika sürer ve Free Tier dışına çıkma riski vardır.)

- [ ] **Gözlem:** Multi-AZ'nin açıklamasında **failover** kelimesi geçiyor, **okuma performansı** geçmiyor.
      Read replica ise **Actions → Create read replica** altındadır. **İkisi farklı problemi çözer.**

### 💸 Temizlik
17. `DynamoDB` → **Tables** → `clfc02-notlar` seç → **Delete** → `confirm` yazarak onayla.
- [ ] **Kontrol:** Tablo listesi boş. RDS'te hiç veritabanı yok.

## Sınavda nasıl sorulur — örnek kalıplar

**Kalıp 1 — Multi-AZ vs read replica**
> *A company wants its RDS database to fail over automatically to another Availability Zone during an outage.* → **Multi-AZ deployment**
> *A company wants to offload heavy reporting queries from the primary database.* → **Read replica**

**Kalıp 2 — DynamoDB**
> *Which service provides a fully managed NoSQL key-value database with single-digit millisecond performance at any scale?* → **Amazon DynamoDB**

**Kalıp 3 — Redshift**
> *A company needs to run complex analytical queries over petabytes of data for business intelligence.* → **Amazon Redshift**

**Kalıp 4 — ElastiCache**
> *An application repeatedly reads the same data from a database, causing high load. Which service reduces this?* → **Amazon ElastiCache**

**Kalıp 5 — Neptune**
> *Which database service is purpose-built for highly connected data such as social networks and recommendation engines?* → **Amazon Neptune**

## 60 saniyelik özet

- **RDS** = yönetilen ilişkisel (MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, Db2, Aurora).
- **Aurora** = bulut için tasarlanmış, MySQL/PostgreSQL uyumlu, 3 AZ'de 6 kopya; **Serverless** sürümü var.
- **Multi-AZ = erişilebilirlik/failover (senkron)** · **Read replica = okuma performansı (asenkron)**.
- **DynamoDB** = sunucusuz NoSQL, milisaniye altı; **DAX** = mikrosaniye önbellek; **Global Tables** = çok Region.
- **ElastiCache** = Redis/Memcached önbellek · **Redshift** = veri ambarı (OLAP) · **DocumentDB** = MongoDB uyumlu ·
  **Neptune** = graf · **Keyspaces** = Cassandra · **Timestream** = zaman serisi.
- **EC2'ye kendin kurmak** = tam kontrol ama tüm sorumluluk sende.
