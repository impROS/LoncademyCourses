## Neden bu konu

Depolama, 3. alanın en yoğun soru üreten ikinci parçasıdır. İki şey ezber gerektirir:
1. **Nesne / blok / dosya** ayrımı → **S3 / EBS / EFS**
2. **S3 depolama sınıfları** → hangi erişim sıklığında hangisi

---

## 1. ⭐ Üç depolama tipi

| | **Object storage (nesne)** | **Block storage (blok)** | **File storage (dosya)** |
|---|---|---|---|
| Servis | **Amazon S3** | **Amazon EBS**, instance store | **Amazon EFS**, **Amazon FSx** |
| Nasıl çalışır | Veri + meta veri + benzersiz anahtar; düz bir alan | Ham disk blokları; üzerine dosya sistemi kurulur | Ağ üzerinden paylaşılan klasör hiyerarşisi |
| Erişim | HTTP/HTTPS API | Bir EC2'ye **bağlanır (mount)** | **Aynı anda birçok** sunucu bağlanır |
| Değiştirme | Nesne **tamamen** yeniden yazılır | Blok blok değiştirilir | Dosya bazlı değiştirilir |
| Tipik kullanım | Yedek, medya, veri gölü, statik site, log | İşletim sistemi diski, veritabanı diski | Paylaşılan içerik, ortak dosya alanı, CMS |

**Hafıza kancası:**
- **S3** = internetteki dev bir dosya kutusu (URL'i var)
- **EBS** = tek sunucuya takılan sanal disk (USB gibi, tek AZ'de)
- **EFS** = ağ paylaşımı (birçok sunucu aynı anda kullanır)

## 2. Amazon S3 (Simple Storage Service)

- **Sınırsız** kapasite; tek nesne en fazla **5 TB**
- Nesneler **bucket**'larda tutulur; **bucket adı dünya genelinde benzersiz**
- **%99,999999999 (11 dokuz) dayanıklılık** — veri bir Region içinde birden çok AZ'ye kopyalanır
- Varsayılan olarak **gizlidir** (Block Public Access açık gelir)
- Ücret bileşenleri: **depolanan GB + istek sayısı + veri çıkışı (+ sınıflar arası geçiş ücreti)**

### Önemli S3 özellikleri
| Özellik | Ne yapar |
|---|---|
| **Versioning** | Aynı anahtara yazılan her sürümü saklar; **yanlışlıkla silme/üzerine yazmaya karşı koruma** |
| **Lifecycle rules** | Nesneleri yaşına göre otomatik olarak **başka sınıfa taşır** veya **siler** |
| **Server-side encryption** | Sunucu tarafında şifreleme (SSE-S3, SSE-KMS, SSE-C) |
| **Bucket policy / Block Public Access** | Erişim kontrolü |
| **Replication (CRR/SRR)** | Bucket'ı başka bir Region'a veya aynı Region'a kopyalar |
| **S3 Object Lock** | Bir kez yazılır, sonra belirli süre **silinemez** (mevzuat için) |
| **Static website hosting** | Statik siteyi doğrudan S3'ten yayınlama |
| **Presigned URL** | Süreli, imzalı geçici erişim linki |
| **S3 Transfer Acceleration** | Uzak kullanıcılardan yüklemeyi edge üzerinden hızlandırır |

### ⭐ S3 depolama sınıfları (mutlaka ezberle)

| Sınıf | Erişim | AZ | Minimum saklama | Erişim süresi | Ne zaman |
|---|---|---|---|---|---|
| **S3 Standard** | Sık | ≥3 | Yok | Anında | Aktif veri, web içeriği |
| **S3 Intelligent-Tiering** | **Bilinmiyor/değişken** | ≥3 | Yok | Anında | Erişim deseni tahmin edilemiyorsa — **otomatik** katman değiştirir |
| **S3 Standard-IA** | Seyrek ama hızlı gerekiyor | ≥3 | 30 gün | Anında | Yedek, eski raporlar |
| **S3 One Zone-IA** | Seyrek, **yeniden üretilebilir** veri | **1** | 30 gün | Anında | Kopyası başka yerde olan veri (💡 AZ kaybında veri gider) |
| **S3 Glacier Instant Retrieval** | Nadiren (çeyrekte bir), **anında** | ≥3 | 90 gün | **Milisaniye** | Tıbbi görüntü, medya arşivi |
| **S3 Glacier Flexible Retrieval** | Arşiv | ≥3 | 90 gün | **Dakikalar–saatler** | Klasik arşiv, yılda 1–2 erişim |
| **S3 Glacier Deep Archive** | **En ucuz arşiv** | ≥3 | 180 gün | **Saatler (≈12 saat)** | 7–10 yıl saklanacak mevzuat verisi |

**Karar kuralı:**
- Erişim deseni **belli değil** → **Intelligent-Tiering**
- Seyrek ama **anında** lazım → **Standard-IA**
- Kaybolsa yeniden üretilebilir + ucuz → **One Zone-IA**
- Arşiv, **saatler beklenebilir**, en ucuz → **Glacier Deep Archive**

> ⚠️ Sınav tuzağı: "en ucuz" ifadesi tek başına yeterli değil. **Erişim süresi kabul edilebilir mi?**
> "must be available within milliseconds" diyorsa Deep Archive **yanlış** cevaptır.

## 3. Amazon EBS (Elastic Block Store)

- EC2'ye takılan **ağ tabanlı blok disk**
- **Tek bir AZ'de** yaşar; aynı AZ'deki bir instance'a bağlanır *(io2 Block Express gibi Multi-Attach senaryoları istisnadır)*
- **Snapshot**'ları **S3'te** saklanır (artımlı — sadece değişen bloklar) ve başka AZ/Region'a taşınabilir
- Instance terminate edilince kök disk **varsayılan olarak silinir** (ayarlanabilir)

| Tür | Kısaltma | Ne için |
|---|---|---|
| **General Purpose SSD** | gp3, gp2 | Varsayılan; işletim sistemi, çoğu iş yükü |
| **Provisioned IOPS SSD** | io2, io1 | Saniyede çok sayıda disk işlemi ([IOPS ↗](../00-baslangic/03-kavram-sozlugu.md#iops)) gerektiren kritik veritabanları |
| **Throughput Optimized HDD** | st1 | Büyük, sıralı okuma (büyük veri, log işleme) |
| **Cold HDD** | sc1 | **En ucuz**, nadiren erişilen veri |

**EBS vs Instance Store:**
| | **EBS** | **Instance store** |
|---|---|---|
| Kalıcılık | **Kalıcı** — instance dursa/silinse bile yaşayabilir | **Geçici (ephemeral)** — instance durunca/silinince **veri gider** |
| Nerede | Ağ üzerinden bağlı | **Fiziksel olarak host makinede** |
| Hız | Yüksek | **Çok yüksek** |
| Kullanım | Genel amaçlı, veritabanı | Geçici önbellek, scratch alanı |

---

## 4. Amazon EFS ve Amazon FSx

### Amazon EFS (Elastic File System)
- Linux'un standart ağ dosya sistemi protokolüyle (NFS) çalışan **yönetilen dosya sistemi**
- **Birden çok EC2 aynı anda** bağlanabilir, **birden çok AZ**'den erişilebilir
- **Otomatik büyür/küçülür**, kullandığın kadar ödersin
- Sınıfları: Standard, One Zone, Infrequent Access (lifecycle ile otomatik geçiş)

### Amazon FSx
Belirli dosya sistemleri için yönetilen servis:
| Tür | Ne için |
|---|---|
| **FSx for Windows File Server** | Windows'un dosya paylaşım protokolü (SMB) ve Active Directory ile bütünleşik paylaşımlar |
| **FSx for Lustre** | **Yüksek performanslı hesaplama (HPC)**, makine öğrenmesi, S3 ile entegre |
| **FSx for NetApp ONTAP / OpenZFS** | Mevcut ONTAP/ZFS iş yüklerinin taşınması |

> ⭐ Refleks: "shared file system for Linux instances" → **EFS.**
> "Windows file share with SMB / Active Directory" → **FSx for Windows File Server.**
> "high-performance computing file system" → **FSx for Lustre.**

## 5. Hibrit ve yedekleme servisleri

| Servis | Tek cümlelik işi | Tetikleyici |
|---|---|---|
| **AWS Storage Gateway** | Şirket içi uygulamalara **bulut depolamayı yerel gibi** sunar (File/Volume/Tape Gateway) | "hybrid storage", "extend on-premises storage to the cloud", "replace tape backups" |
| **AWS Backup** | Birçok AWS servisinin yedeğini **tek yerden** merkezî politikayla yönetir | "centrally manage backups across services" |
| **AWS Elastic Disaster Recovery** | Sunucuları AWS'e sürekli çoğaltır, felakette hızlı devreye alır | "disaster recovery", "minimize RTO/RPO" |
| **AWS DataSync** | Şirket içi ↔ AWS arasında **otomatik veri senkronizasyonu** | "online data transfer", "sync NFS/SMB to S3/EFS" |
| **AWS Snow ailesi** | **Fiziksel** veri taşıma | "petabytes", "limited bandwidth" |
| **AWS Transfer Family** | SFTP/FTPS/FTP ile S3/EFS'e aktarım | "SFTP" |

## 🖥 Pratik — S3'ün tüm kritik özelliklerini tek turda gör (35 dk)

**💸 Maliyet:** Birkaç KB'lık dosyalarla çalışacaksın; maliyet **sıfıra yakın**. Sonunda her şeyi sileceksin.

### A. Bucket oluştur ve versiyonlamayı aç
1. `S3` → **Create bucket** → **Bucket name:** `clfc02-storage-<rastgele>` → **Create bucket**
2. Bucket'a gir → **Properties** sekmesi → **Bucket Versioning** → **Edit** → **Enable** → **Save changes**

### B. Versiyonlamanın ne işe yaradığını gör
3. CloudShell'i aç ve bir dosya oluşturup yükle (bucket adını kendi adınla değiştir):
```bash
BUCKET=clfc02-storage-<rastgele>
echo "birinci surum" > deneme.txt
aws s3 cp deneme.txt s3://$BUCKET/deneme.txt
echo "ikinci surum" > deneme.txt
aws s3 cp deneme.txt s3://$BUCKET/deneme.txt
```
4. Konsolda bucket → **Objects** → sağ üstteki **Show versions** anahtarını **aç**.
   **Aynı dosyanın iki sürümünü** ve farklı **Version ID**'lerini gör.
5. Sürümlerden birini indirip içeriğini kontrol et. **Eski sürüm hâlâ duruyor.** ✅
6. Şimdi dosyayı sil: **Show versions kapalıyken** `deneme.txt` seç → **Delete**.
7. **Show versions**'ı tekrar aç: dosya gitmedi, üzerine bir **Delete marker** kondu.
   Delete marker'ı silersen dosya **geri gelir.**

- [ ] **Gözlem:** Versioning = **yanlışlıkla silme ve üzerine yazmaya karşı sigorta.** Sınav bunu böyle sorar.

### C. Depolama sınıflarını gözle gör
8. **Objects** → bir nesneye tıkla → **Properties** → **Storage class**: `Standard` yazıyor.
9. Nesneyi seç → **Actions** → **Edit storage class**. Açılan listede **tüm sınıfları** gör:
   Standard · Intelligent-Tiering · Standard-IA · One Zone-IA · Glacier Instant Retrieval ·
   Glacier Flexible Retrieval · Glacier Deep Archive
10. Her sınıfın yanındaki **açıklamayı ve minimum saklama süresini oku.** (Değiştirmene gerek yok, **Cancel**.)

- [ ] **Kaydet:** Deep Archive'ın minimum saklama süresi kaç gün? ______

### D. Lifecycle kuralı yaz (maliyet optimizasyonunun kalbi)
11. Bucket → **Management** sekmesi → **Create lifecycle rule**
12. **Rule name:** `eskiyi-ucuza-tasi`
13. **Choose a rule scope:** `Apply to all objects in the bucket` → uyarı kutusunu onayla
14. **Lifecycle rule actions** — şu ikisini işaretle:
    - ✅ **Move current versions of objects between storage classes**
      - `Standard-IA` · **Days after object creation:** `30`
      - **Add transition** → `Glacier Flexible Retrieval` · `90`
      - **Add transition** → `Glacier Deep Archive` · `180`
    - ✅ **Permanently delete noncurrent versions of objects** → **Days after objects become noncurrent:** `30`
15. Altta oluşan **zaman çizelgesi özetini oku** → **Create rule**

- [ ] **Gözlem:** Tek bir kural, veriyi yaşlandıkça otomatik ucuzlatıyor. **Sınavda "reduce storage cost automatically" sorusunun cevabı budur.**

### E. Erişim kontrolünü test et
16. Bir nesneye tıkla → **Object URL**'i kopyala → tarayıcıda aç → **AccessDenied** ✅ (varsayılan gizlilik)
17. **Permissions** sekmesi → **Block public access** ayarlarının **açık** olduğunu doğrula. **Kapatma.**

### F. EBS türlerini incele (kurma)
18. `EC2` → **Volumes** → **Create volume** ekranını aç.
19. **Volume type** listesini gör: `gp3`, `gp2`, `io2`, `io1`, `st1`, `sc1`, `standard`.
    Her birinin altındaki açıklamayı oku (IOPS, throughput, kullanım alanı).
20. **💸 Create'e basma**, **Cancel** ile çık.
21. Sol menü → **Snapshots**: boş olmalı. Snapshot'ların **artımlı** olduğunu ve **S3'te** saklandığını hatırla.

### G. EFS ve FSx'e bak (kurma)
22. Konsol araması → `EFS` → **Create file system** ekranını aç.
    **Availability and durability** kısmında `Regional` (çok AZ) vs `One Zone` seçeneğini gör. **Cancel.**
23. Konsol araması → `FSx` → **Create file system**: dört seçeneği gör
    (Windows File Server, Lustre, NetApp ONTAP, OpenZFS). **Cancel.**

### 💸 Temizlik — versiyonlu bucket'ta dikkat!
24. CloudShell'de (versiyonlu bucket'ı boşaltmanın en kolay yolu):
```bash
aws s3 rm s3://$BUCKET --recursive
```
25. Sonra tüm sürümleri ve delete marker'ları temizle:
```bash
aws s3api list-object-versions --bucket $BUCKET \
  --query "[Versions,DeleteMarkers][].{Key:Key,VersionId:VersionId}" --output json > /tmp/v.json
python3 - <<'PY'
import json,subprocess,os
b=os.environ["BUCKET"]
items=json.load(open("/tmp/v.json")) or []
for it in items:
    if it and it.get("Key"):
        subprocess.run(["aws","s3api","delete-object","--bucket",b,"--key",it["Key"],"--version-id",it["VersionId"]])
print("temizlendi:",len(items))
PY
```
26. Bucket'ı sil:
```bash
aws s3api delete-bucket --bucket $BUCKET
```
- [ ] **Kontrol:** `aws s3 ls` boş dönüyor. EC2 → Volumes boş, Snapshots boş.

> **Ders:** Versiyonlama açıkken "sildim" demek yetmez — **eski sürümler ücretlenmeye devam eder.**
> Bu, gerçek hayatta sürpriz S3 faturasının bir numaralı sebebidir. Lifecycle kuralındaki
> *"permanently delete noncurrent versions"* tam da bunun içindir.

## Sınavda nasıl sorulur — örnek kalıplar

**Kalıp 1 — Sınıf seçimi**
> *Data must be archived for 7 years, is almost never accessed, and retrieval within 12 hours is acceptable. Which is the MOST cost-effective storage class?* → **S3 Glacier Deep Archive**

**Kalıp 2 — Intelligent-Tiering**
> *Access patterns for a dataset are unknown and change over time. Which class minimizes cost without operational effort?* → **S3 Intelligent-Tiering**

**Kalıp 3 — Tip ayrımı**
> *Which service provides a shared file system that can be mounted by multiple Linux EC2 instances simultaneously?* → **Amazon EFS**

**Kalıp 4 — Versioning**
> *How can a company protect S3 objects from accidental deletion or overwrite?* → **Enable versioning**

**Kalıp 5 — Instance store**
> *What happens to data on an instance store volume when the instance is stopped?* → **Veri kaybolur (ephemeral)**

**Kalıp 6 — Storage Gateway**
> *An on-premises application needs cloud-backed storage while keeping low-latency local access.* → **AWS Storage Gateway**

## 60 saniyelik özet

- **S3** nesne (HTTP, 11 dokuz, sınırsız) · **EBS** blok (tek AZ, tek instance) · **EFS/FSx** dosya (çoklu erişim).
- **Sınıflar:** Standard → Intelligent-Tiering (bilinmeyen desen) → Standard-IA → One Zone-IA (tek AZ) →
  Glacier Instant (ms) → Glacier Flexible (dk–saat) → **Deep Archive (en ucuz, saatler)**.
- **Versioning** = yanlışlıkla silmeye karşı · **Lifecycle** = otomatik ucuzlatma/silme · **Object Lock** = belirli süre silinemez · WORM.
- **EBS türleri:** gp3 (varsayılan) · io2 (yüksek IOPS) · st1 (sıralı throughput) · sc1 (en ucuz).
- **Instance store geçicidir**, instance durunca veri gider.
- **Storage Gateway** hibrit · **AWS Backup** merkezî yedek · **Elastic Disaster Recovery** felaket kurtarma.
