## Neden bu konu

IAM (Identity and Access Management), AWS'te **her şeyin kapısıdır.** Sınav burada üç şey sorar:

1. **Root kullanıcı** — ne yapar, neden kullanılmaz, sadece root'un yapabildikleri
2. **User / Group / Role / Policy** ayrımı — özellikle **rol ne zaman kullanılır**
3. **İzin değerlendirme mantığı** — explicit deny > allow > implicit deny

> **IAM ücretsizdir ve globaldir** (Region'a bağlı değildir). Bu iki bilgi tek başına soru olabilir.

---

## 1. Root kullanıcı

Hesabı açtığında oluşan, **e-posta adresiyle giriş yapan** kullanıcıdır. Hesaptaki **her şeyi** yapabilir ve
**yetkisi kısıtlanamaz** (SCP bile yönetim hesabının root'unu tam kısıtlayamaz).

### Root için altın kurallar
1. **MFA tak** (ilk iş).
2. **Günlük kullanma.** Günlük iş için IAM kullanıcısı veya IAM Identity Center kullan.
3. **Root için access key oluşturma.** Varsa sil.
4. Parolayı güçlü tut ve paylaşma.

### Sadece root'un yapabildiği işler (sınavda çıkar)
- **Hesabı kapatmak**
- **Hesap ayarlarını değiştirmek** (hesap adı, e-posta, root parolası)
- **Ödeme yöntemini / fatura bilgisini değiştirmek**
- **Destek planını değiştirmek** (Basic → Business gibi)
- **IAM kullanıcı izinlerini geri yüklemek** (kendini kilitleyen bir IAM yöneticisini kurtarmak)
- **S3'te MFA Delete'i yapılandırmak**
- Tüm principal'ları reddeden hatalı bir **S3 bucket politikasını düzeltmek**
- **Reserved Instance Marketplace'te satıcı olarak kaydolmak**
- **AWS GovCloud** hesabı açmak

> **Sınav refleksi:** Soruda *"which task requires the root user"* geçiyorsa cevap genelde
> **hesap kapatma / destek planı değiştirme / ödeme bilgisi değiştirme**dir.

## 2. Dört temel kavram: User, Group, Role, Policy

### IAM User (kullanıcı)
Bir **kişiyi veya uygulamayı** temsil eden kalıcı kimlik. İki tür erişimi olabilir:
- **Konsol erişimi:** kullanıcı adı + parola (+ MFA)
- **Programatik erişim:** **access key ID + secret access key** (CLI, SDK, API için)

> ⚠️ Access key'i **koda gömme**, GitHub'a **pushlama**, e-postayla **paylaşma**. Düzenli **rotate** et.

### IAM Group (grup)
Kullanıcı **koleksiyonu**. Politikayı gruba bağlarsın, gruptaki herkes o izni alır.
- Grup **kimlik değildir**; grup adına giriş yapılamaz, grubun access key'i olmaz.
- Grup içine **grup konulamaz** (iç içe grup yok).
- Bir kullanıcı **birden çok gruba** üye olabilir.
- **Roller gruba konulamaz.**

### IAM Role (rol)
**Geçici olarak üstlenilen** kimlik. Kalıcı parolası veya access key'i **yoktur**; üstlenildiğinde
**AWS STS** üzerinden **geçici kimlik bilgileri** verilir (belirli süre sonra geçersiz olur).

**Roller ne zaman kullanılır (sınavın favorisi):**
| Senaryo | Çözüm |
|---|---|
| EC2 üzerindeki uygulama S3'e erişecek | **EC2'ye rol ata** (access key gömme!) |
| Lambda fonksiyonu DynamoDB'ye yazacak | **Lambda execution role** |
| Başka bir AWS hesabındaki kullanıcı senin kaynağına erişecek | **Cross-account role** |
| Şirket Active Directory kullanıcıları AWS'e girecek | **Federation + rol** (IAM Identity Center) |
| Mobil uygulama kullanıcıları AWS kaynağına erişecek | **Cognito + rol** |

> ⭐ **En sık çıkan tek IAM sorusu:** *"An application on EC2 needs to access S3. What is the MOST secure way?"*
> → **EC2 instance'a bir IAM rolü ata.** (Access key'i instance'a kopyalamak **yanlış** cevaptır.)

### IAM Policy (politika)
**JSON** belgesi; kimin neye ne yapabileceğini tanımlar. İki tür:
- **Identity-based:** kullanıcı/grup/role bağlanır ("bu kimlik neler yapabilir")
- **Resource-based:** kaynağa bağlanır (S3 bucket policy, SQS queue policy — "bu kaynağa kim erişebilir")

**Anatomi:**
```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",              // Allow veya Deny
    "Action": "s3:GetObject",       // hangi işlem
    "Resource": "arn:aws:s3:::ornek-bucket/*",   // hangi kaynak (ARN = kaynağın benzersiz adı)
    "Condition": {"IpAddress": {"aws:SourceIp": "203.0.113.0/24"}}  // opsiyonel koşul
  }]
}
```

Politika türleri:
- **AWS managed policy:** AWS'in hazırladığı (`AdministratorAccess`, `ReadOnlyAccess`, `AmazonS3ReadOnlyAccess`)
- **Customer managed policy:** senin yazdığın, tekrar kullanılabilir
- **Inline policy:** tek bir kimliğe gömülü, başkasına verilemez

## 3. ⭐ İzin değerlendirme mantığı

Bir istek geldiğinde AWS şu sırayla bakar:

1. **Explicit DENY var mı?** → Varsa **REDDEDİLİR.** (Her şeyi ezer.)
2. **Explicit ALLOW var mı?** → Varsa **İZİN VERİLİR.**
3. Hiçbiri yoksa → **implicit deny** → **REDDEDİLİR.**

> **Ezber cümlesi:** *"Varsayılan reddetmedir; açık izin açar, açık ret her şeyi kapatır."*
> **Explicit deny > Explicit allow > Implicit deny (varsayılan)**

Örnek: Kullanıcıda `AdministratorAccess` var ama bir politika `s3:DeleteBucket` için `Deny` diyorsa → **bucket silemez.**

### Least privilege (en az ayrıcalık)
Bir kimliğe **işini yapmak için gereken minimum** izni ver, fazlasını verme.
Geniş izinle başlayıp daraltmak değil, **dar başlayıp gerektikçe genişletmek** doğru yaklaşımdır.
> Yardımcı araçlar: **IAM Access Analyzer** (dışarıya açık erişimleri bulur, politika üretir),
> **Access Advisor / last accessed** (kullanılmayan izinleri gösterir), **credential report** (tüm kimlik bilgilerinin durumu).

---

## 4. MFA ve parola politikası

**MFA (Multi-Factor Authentication):** Bildiğin bir şey (parola) + sahip olduğun bir şey (kod üreten cihaz).
| Tür | Örnek |
|---|---|
| **Virtual MFA** | Google/Microsoft Authenticator, Authy (telefon uygulaması) |
| **Hardware TOTP token** | Fiziksel kod üreten anahtarlık |
| **FIDO security key** | YubiKey gibi USB güvenlik anahtarı |

**Parola politikası** (IAM → Account settings): minimum uzunluk, karakter çeşitliliği, süre dolumu,
yeniden kullanım engeli, kullanıcıların kendi parolasını değiştirebilmesi.

> Sınav refleksi: "add an extra layer of protection to sign-in" → **MFA**.

## 5. IAM'in komşuları: Identity Center, Directory Service, Cognito

Bu üçünün ayrımı sınavda düzenli çıkar:

| Servis | Kimin için | Ne yapar |
|---|---|---|
| **IAM Identity Center** (eski AWS SSO) | **Çalışanlar**, birden çok AWS hesabı | Tek oturumla **birden fazla hesaba/uygulamaya** erişim; merkezi kullanıcı yönetimi; harici IdP (Okta, Entra ID) bağlanabilir |
| **AWS Directory Service** | Şirketin **Active Directory** ortamı | AWS'te yönetilen Microsoft AD kurmak veya şirket içi AD'ye bağlanmak |
| **Amazon Cognito** | **Uygulamanın son kullanıcıları** (müşteriler) | Mobil/web uygulaman için kayıt-giriş, kullanıcı havuzu, sosyal/kurumsal federasyon |
| **AWS STS** | Her yerde | **Geçici kimlik bilgileri** üretir (rollerin arkasındaki motor) |

> ⭐ **Ayırt edici soru:** Kullanıcılar **senin şirketinin çalışanları** mı → **IAM Identity Center.**
> **Senin uygulamanın müşterileri** mi → **Cognito.**

| Soruda geçen | Doğru cevap |
|---|---|
| "application on EC2 needs S3 access, most secure" | **IAM role** (EC2'ye ata) |
| "temporary credentials" | **IAM role / AWS STS** |
| "grant the same permissions to 20 developers" | **IAM group** |
| "explicit deny in one policy, allow in another" | **Deny kazanır** |

| "give minimum permissions required" | **Least privilege** |
| "find resources shared with external accounts" | **IAM Access Analyzer** |
| "IAM is global / free" | **Doğru** |

## 🖥 Pratik — İzinleri kendi elinle kır ve tamir et (35 dk)

**Amaç:** Grup–kullanıcı–politika zincirini ve **explicit deny**'ı canlı görmek.
**💸 Maliyet:** **IAM ücretsizdir.** Bu pratikte hiç ücret çıkmaz.

### A. Grup ve kullanıcı oluştur
1. `IAM` → **User groups** → **Create group**.
   - **Name:** `sadece-okuyanlar`
   - **Attach permissions policies:** `ReadOnlyAccess` ara ve seç → **Create group**.
2. `IAM` → **Users** → **Create user**.
   - **User name:** `test-okuyucu`
   - ✅ **Provide user access to the AWS Management Console** → **I want to create an IAM user** → **Custom password** ver, "must create a new password" tikini kaldır.
   - **Next** → **Permissions options:** `Add user to group` → `sadece-okuyanlar` seç → **Create user**.
   - **Sign-in URL**'i ve parolayı kaydet.

### B. Sınırı test et (tarayıcının gizli penceresinde)
3. **Gizli/incognito pencere** aç (mevcut oturumun bozulmasın), sign-in URL'ine git, `test-okuyucu` ile gir.
4. `S3` → bucket listesini **görebiliyorsun** ✅ (ReadOnlyAccess).
5. **Create bucket** dene → **hata almalısın**: `AccessDenied` / `not authorized to perform s3:CreateBucket`.

- [ ] **Gözlem:** Okuma serbest, yazma yasak. Bu **least privilege**'ın pratiği.

6. `IAM` → **Users** ekranına git → bir kullanıcı oluşturmayı dene → yine reddedilir.

### C. Explicit deny'ı gör
7. **Ana pencerene** (`ridvan-admin`) dön. `IAM` → **Users** → `test-okuyucu` → **Permissions** sekmesi.
8. **Add permissions** → **Create inline policy** → **JSON** sekmesi → şunu yapıştır:
```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Deny",
    "Action": "s3:*",
    "Resource": "*"
  }]
}
```
9. **Next** → **Policy name:** `s3-tamamen-yasak` → **Create policy**.
10. Gizli pencereye dön, sayfayı yenile, `S3`'e git → **artık bucket listesini bile göremiyorsun.**

- [ ] **Gözlem:** `ReadOnlyAccess` (allow) hâlâ duruyor ama **explicit deny onu ezdi.**
      **Explicit deny > allow.** Sınavda bu soru birebir çıkar.

### D. Policy Simulator ile doğrula (yetki denemeden test etme aracı)
11. `IAM` → sol menü en altta **Policy simulator** (veya `https://policysim.aws.amazon.com`).
12. Soldan **Users** → `test-okuyucu` seç.
13. **Select service:** `S3` · **Select actions:** `GetObject`, `CreateBucket` seç → **Run Simulation**.
14. Sonuç sütununda **denied** ve hangi politikanın engellediğini gör.
15. Şimdi soldan `ridvan-admin` kullanıcısını seç, aynı testi yap → **allowed**.

### E. Credential report — hesabının kimlik sağlığı
16. `IAM` → sol menü → **Credential report** → **Download report** (CSV).
17. CSV'yi aç ve şu sütunlara bak:
   - `mfa_active` → root ve kullanıcıların MFA'sı var mı
   - `access_key_1_active` / `access_key_1_last_rotated` → anahtar var mı, ne zaman döndü
   - `password_last_used` → kullanılmayan kimlikler
- [ ] **Kontrol:** Root satırında `mfa_active = true` yazmalı. Yazmıyorsa **hemen** 0.1 dosyasına dön.

### F. Parola politikasını sertleştir
18. `IAM` → **Account settings** → **Password policy** → **Edit**.
19. Minimum uzunluk `14`, büyük/küçük harf, rakam ve özel karakter zorunlu, **son 3 parolayı tekrar kullanma** → **Save**.

### 💸 Temizlik
20. `IAM` → **Users** → `test-okuyucu` → **Delete** (adını yazarak onayla).
21. `IAM` → **User groups** → `sadece-okuyanlar` → **Delete**.
- [ ] **Kontrol:** IAM'de sadece `ridvan-admin` kaldı.

## Sınavda nasıl sorulur — örnek kalıplar

**Kalıp 1 — Rol (en sık)**
> *An application running on an EC2 instance needs to read objects from Amazon S3. What is the MOST secure way to provide access?*
> → **Attach an IAM role to the EC2 instance** (access key gömmek yanlış)

**Kalıp 2 — Deny önceliği**
> *A user has AdministratorAccess but another attached policy explicitly denies s3:DeleteBucket. Can the user delete the bucket?*
> → **Hayır. Explicit deny her şeyi ezer.**

**Kalıp 3 — Root**
> *Which action can ONLY be performed by the AWS account root user? (Choose TWO.)*
> → **Closing the account**, **changing the support plan**, **changing payment information**

**Kalıp 4 — Identity Center vs Cognito**
> *A company wants employees to sign in once and access multiple AWS accounts.* → **IAM Identity Center**
> *A company needs sign-up and sign-in for its mobile app users.* → **Amazon Cognito**

**Kalıp 5 — Grup**
> *How should an administrator grant identical permissions to 25 new developers with the least effort?*
> → **Create an IAM group, attach the policy to the group, add the users**

## 60 saniyelik özet

- **IAM ücretsiz ve global.**
- **Root:** MFA tak, günlük kullanma, access key yaratma. Sadece root: hesap kapatma, destek planı, ödeme bilgisi, hesap ayarları.
- **User** = kalıcı kimlik · **Group** = kullanıcı koleksiyonu (iç içe olmaz) · **Role** = geçici üstlenilen kimlik (**STS**) · **Policy** = JSON izin belgesi.
- **EC2/Lambda'dan AWS servisine erişim → ROL.** Access key gömme.
- **Explicit deny > allow > implicit deny.** Varsayılan: reddet.
- **Least privilege:** dar başla, gerekirse genişlet.
- **Identity Center** = çalışanlar/çok hesap · **Directory Service** = Active Directory · **Cognito** = uygulama kullanıcıları.
