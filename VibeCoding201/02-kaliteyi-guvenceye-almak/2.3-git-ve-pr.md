## Neden bu konu

Git, ajanla çalışırken bir kolaylık olmaktan çıkıp **altyapı** oluyor: geri alma
mekanizman, inceleme birimin ve değişikliğin kaynağını gösteren tek kayıt o.

Bir de yeni bir yüzey var: ajan artık **depoda da yaşıyor** — sorun kayıtlarına
cevap veriyor, pull request açıyor, inceleme yapıyor. Bu yüzey kolaylık kadar
risk de getiriyor.

**Büyük fikir:** Ajanın ürettiği her değişiklik **geri alınabilir ve
izlenebilir** olmalı — bunun tek garantisi git.

---

## 1. ⭐ Ajanla git alışkanlıkları

| Alışkanlık | Neden ajan çağında daha önemli |
|---|---|
| **Her iş için dal** | Ana dal her zaman çalışır kalır; deneme ucuzlar |
| **Temiz ağaçla başla** | Neyin ajandan geldiği net görülür |
| **Küçük ve sık commit** | Geri alma noktası bol; inceleme birimi küçük |
| **Diff'i sen oku** | Ajanın söylediği değil, **yaptığı** |
| **Gizli değer asla commit'e** | Ajan bir dosyayı okuyup başka yere yazabilir |

> ⚠️ **Kontrol noktası git'in yerine geçmez.** Ajanın dosya düzenleme
> araçlarıyla yaptığını geri alır; `npm install`, `sed`, betikler kapsam dışı.
> İkisi birlikte kullanılır: kontrol noktası **oturum içi**, git **kalıcı**.

---

## 2. Commit mesajını ajana yazdırmak

Ajan iyi commit mesajı yazar — çünkü değişikliği okuyabiliyor. Ama **neyi**
okuduğunu söylemen gerekir:

```text
Şu ana kadarki değişikliği incele ve tek bir commit at.
Mesaj şu biçimde olsun: ilk satır 50 karakteri geçmesin ve ne yapıldığını
söylesin; boş satır; sonra NEDEN yapıldığını iki cümleyle anlat.
Depodaki son commit mesajlarının biçimini örnek al.
```

Son satır önemli: `1.2`'deki kalıbı izletme kuralı burada da geçerli. Ajan
projenin commit geleneğini **tahmin etmez**, gösterilmesi gerekir.

> ⚠️ **Ajan neyi commit'lediğine dikkat et.** "Her şeyi ekle ve commit'le"
> demek, ortam dosyalarını ve geçici çıktıları da içine alabilir. `git status`
> okumadan commit attırma.

---

## 3. Pull request akışı

Komut satırı aracı kuruluysa (`gh`) ajan pull request'i baştan sona açabilir.
Kurulu değilse yetkisiz istek atıp hız sınırına takılır — **kur.**

```text
Bu dalı gönder ve pull request aç.
Açıklamada şunlar olsun: ne değişti, neden değişti, nasıl doğrulandı
(hangi testler), ve inceleyenin özellikle bakması gereken yer.
Kapsam dışı bıraktığın şeyleri de yaz.
```

İyi bir pull request açıklamasında olması gerekenler:

| Parça | Neden |
|---|---|
| Ne değişti | Diff'i okumadan önce çerçeve |
| **Neden** | Diff'ten okunamayan tek şey |
| Nasıl doğrulandı | İnceleyen aynı işi tekrarlamasın |
| Nereye bakılmalı | İncelemenin dikkatini yönlendirir |
| **Kapsam dışı** | "Bunu neden yapmamış?" sorusunu önler |

---

## 4. ⭐ Depoda çalışan ajan — ve güvenlik sınırı

Ajanı deponun kendisine bağlayabilirsin: bir sorun kaydında ya da pull
request yorumunda anıldığında çalışır, değişiklik yapar, commit atar.

Faydası açık. Ama **yeni bir güvenlik yüzeyi** açar:

> ⚠️ **Sorun kaydına yazılan metni ajan okur.** Bu metni **herkes** yazabilir.
> Yani dışarıdan biri, ajanın okuyacağı bir yere talimat yerleştirebilir —
> [istem enjeksiyonu ↗](../00-baslangic/02-kavram-sozlugu.md#istem-enjeksiyonu).
> **401 · *Güvenlik*** bunu ayrıntısıyla işliyor.

Bu yüzden bu tür kurulumlarda **kimin tetikleyebileceği** denetlenir:

| Denetim | Ne yapar |
|---|---|
| Yazma yetkisi şartı | Depoya yazma yetkisi olmayan tetikleyemez |
| Bot denetimi | Otomatik hesaplar tetikleyemez — sonsuz döngüyü de önler |
| Dar araç listesi | Ajan yalnızca izin verilen araçları kullanır |
| Tur sınırı | Kaçak bir çalışma sınırsız uzayamaz |

Ve iki pratik ayrıntı:

- **Gizli değerler depoya yazılmaz**, sır olarak saklanır ve iş akışına
  değişkenle geçirilir.
- **Ajanın attığı commit'ler sürekli tümleştirmeyi tetiklemeyebilir** — bu,
  iş akışlarının sonsuz döngüye girmesini önleyen bilinçli bir davranıştır.
  Testlerin ajanın commit'inde çalışmıyorsa sebebi genelde budur.

---

## 5. Kimlik ve dürüstlük

Ajanın ürettiği değişikliğin **öyle olduğu belli olmalı.** Bunun iki sebebi var:

1. **İnceleme dikkati**: inceleyen kişi `2.2`'deki beş kontrolü açmalı.
2. **Dürüstlük**: kaynağı gizlemek, sonradan güven kaybettiren bir seçim.

Nasıl yapıldığı ekibe göre değişir — commit mesajında bir satır, pull request
etiketi, ya da ajan olarak kimlik doğrulama. **Bir yolunu seç ve tutarlı ol.**

## Sık karıştırılanlar — tek tabloda

| Karıştırılan | Doğrusu | Neden diğeri değil |
|---|---|---|
| "Kontrol noktası varsa git gerekmez" | Kabuk değişikliklerini kapsamaz | İkisi farklı kapsam: oturum içi / kalıcı |
| "Ajan iyi commit mesajı yazar, bırak yazsın" | **Biçimi göster**, `git status` oku | Gelenek tahmin edilmez; fazladan dosya girebilir |
| "Sorun kaydından tetikleme güvenli" | ⚠️ Metni **herkes** yazabilir | Yetki ve araç kısıtı şart |
| "Ajanın commit'i CI'ı tetikler" | Genelde **tetiklemez** | Sonsuz döngüyü önleyen bilinçli davranış |
| "Kaynağı belirtmesek de olur" | İnceleme dikkati **değişmeli** | Ajan kodu farklı yerlerde hatalı |
| "`gh` olmasa da olur" | Yetkisiz istek hız sınırına takılır | Kur, işi kolaylaşır |

## 🖥 Pratik — dal, commit, pull request taslağı

> **Amaç:** Akışı uçtan uca ve denetimli yürütmek · **Süre:** 15 dk
> **💸 Maliyet:** Yok (uzak depoya gönderim yapılmayacak)

### Adımlar

1. Dal aç ve küçük bir değişiklik yaptır:
   ```bash
   cd ~/gorev-api && git checkout -b ozellik/gorev-sayisi
   ```
   ```text
   sunucu.js'e GET /gorevler/sayi uç noktası ekle: {"sayi": N} dönsün.
   sunucu.test.js'e testini ekle. npm test çalıştır ve çıktıyı göster.
   ```

2. **Commit'ten önce** neyin gireceğini kendin gör:
   ```bash
   git status --short && git diff --stat
   ```
   - [ ] **Kontrol:** Beklemediğin dosya var mı? ______

3. Commit mesajını yazdır — **biçimi göstererek**:
   ```text
   Şu ana kadarki değişikliği tek commit yap.
   Mesaj: ilk satır 50 karakterden kısa, ne yapıldığını söylesin;
   boş satır; sonra iki cümleyle NEDEN. Depodaki son commit
   mesajlarının biçimini örnek al. Yalnızca sunucu.js ve
   sunucu.test.js'i ekle.
   ```
   ```bash
   git log -1 --stat
   ```
   - [ ] **Kontrol:** Yalnızca iki dosya girdi mi?
   - [ ] **Kontrol:** Mesajda "neden" bölümü var mı?

4. Pull request açıklamasını **yazdır ama gönderme**:
   ```text
   Bu dal için bir pull request açıklaması yaz ve PR.md'ye kaydet.
   İçinde: ne değişti, neden, nasıl doğrulandı, inceleyenin nereye
   bakması gerektiği, ve kapsam dışı bıraktıkların.
   Henüz hiçbir şey gönderme.
   ```
   - [ ] **Kaydet:** Beş bölümün kaçı gerçekten dolu? ______

5. Kimlik satırını dene:
   ```bash
   git log -1 --format='%an <%ae>%n%n%B'
   ```
   - [ ] **Kaydet:** Bu commit'in ajan üretimi olduğu kayıttan anlaşılıyor mu?
         ______ (Anlaşılmıyorsa ekibinle bir yol kararlaştır.)

### Temizlik
6. ```bash
   rm -f PR.md
   git checkout main 2>/dev/null || git checkout master
   git branch -D ozellik/gorev-sayisi && git status --short
   ```
- [ ] **Kontrol:** Ana dalda, temiz, deneme dalı yok.

## Nasıl karşına çıkar — örnek kalıplar

**Kalıp 1 — Fazladan dosya**
> *"Commit'e `.env` ve `node_modules` da girmiş."*
> → "Her şeyi ekle" denmiş, `git status` okunmamış.

**Kalıp 2 — CI sessizliği**
> *"Ajanın commit'inde testler hiç çalışmadı."*
> → Beklenen davranış; sonsuz döngüyü önlüyor.

**Kalıp 3 — Zehirli sorun kaydı**
> *"Bir sorun kaydındaki gizli talimat ajanı yönlendirmiş."*
> → Dışarıdan yazılabilen içerik güvenilmezdir. Yetki ve araç kısıtı.

**Kalıp 4 — İzsiz değişiklik**
> *"Bu kodu kim yazdı belli değil."*
> → Kaynak belirtilmemiş; inceleme dikkati ayarlanamıyor.

## 60 saniyelik özet

- Git ajanla çalışırken **altyapıdır**: geri alma, inceleme birimi, kaynak kaydı.
- Beş alışkanlık: **dal aç · temiz başla · küçük commit · diff'i oku ·
  gizli değer commit'lemе**.
- ⚠️ Kontrol noktası **oturum içi**, git **kalıcı** — biri diğerinin yerine geçmez.
- Commit mesajı yazdırırken **biçimi göster** ve `git status` oku.
- Pull request açıklamasının beş parçası: ne · **neden** · nasıl doğrulandı ·
  nereye bakılmalı · **kapsam dışı**.
- Depoda çalışan ajan yeni bir **güvenlik yüzeyi** açar: sorun kaydını herkes yazabilir.
- Denetimler: **yazma yetkisi · bot denetimi · dar araç listesi · tur sınırı**.
- Gizli değerler depoya değil, **sır** olarak saklanır.
- Ajan commit'leri genelde **CI'ı tetiklemez** — sonsuz döngü önlemi.
- Ajan üretimi olduğu **belli olmalı**: inceleme dikkati ve dürüstlük.
